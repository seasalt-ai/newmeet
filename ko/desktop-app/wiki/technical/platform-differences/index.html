플랫폼 차이점

제 29 장: 플랫폼 차이점

소개

SeaMeet은 여러 플랫폼에서 작동합니다 — Windows, macOS, Linux — 그러나 각 운영 체제에는 자체 특이점, 기능, 제한이 있습니다. Windows에서 완벽하게 작동하는 것이 Mac에서는 다르게 동작할 수 있습니다. 일부 기능은 한 플랫폼에서는 사용 가능하지만 다른 플랫폼에서는 그렇지 않습니다. 이러한 차이점을 이해하면 사용 중인 컴퓨터에 관계없이 SeaMeet을 최대한 활용할 수 있습니다.

이 챕터에서는 SeaMeet이 각 플랫폼에 어떻게 적응하는지, 어떤 기능이 플랫폼별인지, 그리고 알아야 할 제한 사항을 설명합니다.

챕터 목표

이 챕터를 읽은 후, 당신은 다음을 할 수 있습니다:

  • Windows, macOS, Linux 버전 간의 차이 이해
  • 어떤 기능이 플랫폼별인지 알기
  • 운영 체제에 맞게 SeaMeet을 적절히 구성
  • 플랫폼별 제한 사항 우회
  • 녹음 요구 사항에 맞는 올바른 플랫폼 선택

파트 1: 플랫폼별 개요

Windows의 SeaMeet

최적 용도:

  • 최대 호환성
  • 게임 녹화
  • 비즈니스 환경
  • 가장 기능이 완전한 버전

주요 특성:

  • 가장 많은 기능 사용 가능
  • 최고의 하드웨어 가속 지원 (NVIDIA/AMD/Intel)
  • 쉬운 시스템 오디오 캡처
  • 가장 넓은 앱 호환성
  • 가장 많이 테스트되고 안정적

지원되는 Windows 버전:

  • Windows 10 (버전 1809 이상)
  • Windows 11
  • Windows Server 2019/2022 (제한된 지원)

지원되는 Windows 아키텍처:

  • x64 (Intel/AMD 64비트): 전체 지원, 모든 기능 사용 가능
  • ARM64 (Windows on ARM): 지원됨, 일부 오디오 기능 사용 불가
    • Surface Pro X 및 유사 장치
    • 화면 녹화, 비디오 녹화, 마이크 녹음 완전 지원
    • 시스템 오디오 캡처 및 오디오 장치 열거 사용 불가 (우아한 저하)
    • 자세한 내용은 아래 Windows ARM64 섹션 참조

지원되지 않음:

  • Windows 7, 8, 8.1 (수명 종료)
  • Windows XP/Vista (고대)
  • 32비트 Windows (x86)

macOS의 SeaMeet

최적 용도:

  • 크리에이티브 전문가
  • Apple 생태계 사용자
  • 깨끗하고 일관된 인터페이스
  • Mac 워크플로우와의 통합

주요 특성:

  • 세련된 네이티브 Mac 인터페이스
  • Apple Silicon (M1/M2/M3)에서 우수한 성능
  • Intel Mac에서 우수한 성능
  • 긴밀한 시스템 통합
  • 다른 권한 모델
  • 앱별 마이크 모니터링
  • 브라우저 미팅 감지 및 자동 시작 방지

지원되는 macOS 버전:

  • macOS 14.2 Sonoma (최소 - native-audio-node 기능에 필요)
  • macOS 15 Sequoia
  • 미래 버전

지원되는 macOS 아키텍처:

  • Apple Silicon (arm64): 전체 지원, 앱별 오디오 감지를 포함한 모든 기능
  • Intel (x64): 별도 설치 프로그램으로 전체 지원

Apple Silicon 및 Intel 지원:

  • 두 개의 별도 DMG 설치 프로그램: 하나는 Intel용, 하나는 Apple Silicon용
  • Mac의 프로세서와 일치하는 버전 다운로드
  • M1/M2/M3 Mac → arm64 버전 다운로드
  • Intel Mac → x64 버전 다운로드
  • 두 버전 모두 동일한 기능
  • VideoToolbox (Apple Silicon) 또는 Quick Sync (Intel)를 통한 하드웨어 가속
  • 앱별 마이크 감지 (native-audio-node)
  • 미팅 애플리케이션에 대한 스마트 창 사전 선택

Intel Mac 호환성

SeaMeet은 macOS 14.2 Sonoma 이상이 필요합니다. 모든 Intel Mac이 이 버전을 지원하지는 않습니다:

Linux의 SeaMeet

최적 용도:

  • 소스에서 SeaMeet을 실행하는 기술 사용자
  • 프로젝트에 기여하는 개발자
  • 개인정보 보호를 의식하는 사용자
  • 오픈 소스 옹호자

주요 특성:

  • 커뮤니티 지원, 소스 전용 (공식 사전 빌드 설치 프로그램 없음)
  • 배포판별 변동하는 기능 세트
  • 더 많은 수동 구성 필요
  • 명령줄 친화적
  • 적은 "그냥 작동" 기능

지원되는 배포판:

  • Ubuntu 20.04+ (최고의 지원)
  • Fedora 34+
  • Debian 11+
  • 기타 Debian/Ubuntu 기반 배포판

Linux 설치 참고 사항 (v2.1.4+):

✅ npm install이 이제 Linux에서 깨끗하게 성공합니다

v2.1.4까지, `npm install`은 native-audio-node — macOS/Windows
전용 네이티브 모듈 — 가 `dependencies`에 나열되어 있어 Linux에서
EBADPLATFORM으로 실패했습니다. v2.1.4부터는 다른 플랫폼별 오디오
패키지 (macos-audio-devices, native-sound-mixer, win-audio)와 함께
`optionalDependencies`에 살므로, npm은 Linux에서 그것들을 중단
대신 건너뜁니다.

이전에 `npm ERR! EBADPLATFORM`이 발생했다면:
1. v2.1.4 이상 풀
2. node_modules와 package-lock.json 삭제
3. npm install을 다시 실행 — 오류 없이 완료되어야 합니다

제한 사항:

  • 공식 사전 빌드 설치 프로그램 없음 — npm start를 통해 소스에서 실행
  • 앱별 마이크 모니터링 및 미팅 자동 감지 사용 불가 (Linux 바이너리가 없는 native-audio-node 필요)
  • 시스템 트레이 가용성은 데스크톱 환경에 따라 다름 (아래 트레이 섹션 참조)
  • 하드웨어 가속은 GPU/드라이버 조합에 따라 다름
  • 시스템 오디오 캡처에 더 많은 설정 필요 (PulseAudio / PipeWire 루프백)

플랫폼별 시스템 트레이 및 Lite 모드

SeaMeet은 메인 창을 닫은 후에도 백그라운드에서 계속 실행됩니다 — 시스템 트레이 (macOS에서는 메뉴 바라고 함)는 그것으로 돌아가고, 녹음 상태를 변경하고, 깨끗하게 종료하는 방법입니다. Electron의 Tray API는 플랫폼별이므로 동작이 다양합니다:

기능WindowsmacOSLinux
트레이 아이콘✅ 알림 영역의 tray.ico✅ 메뉴 바의 템플릿 icon.png (다크/라이트에 적응)⚠️ 데스크톱 환경에 따라 다름

Linux 트레이 참고 사항:

Electron 트레이는 GNOME (AppIndicator 확장 포함), KDE Plasma, XFCE, Cinnamon, 그리고 대부분의 Ubuntu/Fedora 기본 데스크톱에서 안정적으로 작동합니다. Wayland 전용 세션과 일부 최소 창 관리자에서는 트레이 아이콘이 전혀 나타나지 않을 수 있습니다 — 앱은 여전히 실행되지만, 터미널에서 다시 실행하거나 창을 다시 가져오려면 전역 단축키를 사용해야 합니다. Linux 전용 트레이 아이콘 자산은 없습니다; Windows와 동일한 .ico가 로드됩니다.

Lite 모드:

Lite 모드 (v2.x에서 도입됨)는 렌더러 측 컴팩트 레이아웃입니다 — 전체 앱 창 대신 녹음 컨트롤, 파형, 빠른 액션이 있는 560×80 플로터 바. ui.appMode 설정 ('full' 또는 'lite')으로 제어되며 설정을 통해 런타임에 전환됩니다. Lite 모드는 플랫폼별 코드 경로가 없으므로 세 플랫폼 모두에서 동일하게 작동합니다.

파트 3: Windows 전용 기능 및 설정

Windows 장점

1. 시스템 오디오가 쉬움

Windows에서는 시스템 오디오 캡처가 간단합니다:

방법: Stereo Mix (가장 안정적)

설정:
1. 스피커 아이콘 우클릭 → Open Sound settings
2. Sound Control Panel → Recording
3. 빈 영역에서 우클릭 → Show Disabled Devices
4. "Stereo Mix" 우클릭 → Enable
5. 기본값으로 설정

SeaMeet은 이제 시스템 오디오를 직접 캡처할 수 있습니다

대안 방법:

  • WASAPI 루프백 (현대적 방법)
  • DirectSound 캡처
  • 가상 오디오 케이블

2. 하드웨어 가속 풍성함

Windows는 최고의 GPU 인코더 지원을 가지고 있습니다:

NVIDIA GPU:

GTX 600 시리즈 이상:
• NVENC 전용 인코더 칩
• 우수한 품질
• 매우 효율적
• SeaMeet이 자동으로 지원

AMD GPU:

Radeon HD 7000 시리즈 이상:
• VCE (Video Coding Engine)
• 좋은 품질
• 효율적인 인코딩
• 자동 지원

Intel 통합:

4세대 Core 이상:
• Quick Sync Video
• 놀랍게도 좋은 품질
• 매우 전력 효율적
• 노트북에 좋음

3. 게임 기능

Windows 전용 게임 통합:

게임 모드 지원:
• Windows 게임 모드 API
• 게임 중일 때 자동 감지
• 리소스 최적화
• Windows에서만 사용 가능

게임 바 통합:

Windows ARM64 전용 정보

Windows ARM64란?

ARM64는 다른 프로세서 아키텍처입니다:
• Windows on ARM 장치 (Surface Pro X 등)에서 사용
• ARM 기반 프로세서의 네이티브 지원
• x64 앱 에뮬레이션 가능 (더 느림)
• 네이티브 ARM64 앱에 대한 성장하는 지원

ARM64의 SeaMeet

SeaMeet은 v1.0.2+부터 네이티브 ARM64 지원을 제공합니다:

✅ ARM64에서 완전히 지원됨:
• 화면 녹화 (고성능)
• 비디오 녹화 (고성능)
• 마이크 녹음 (직접 Windows API)
• 창 감지 및 관리
• Floater 위젯 및 키보드 단축키
• 설정 및 녹음 라이브러리
• 모든 UI 기능

❌ ARM64에서 사용 불가:
• 시스템 오디오 캡처 (앱/스피커의 오디오)
• 오디오 장치 열거 (마이크/스피커 감지)
• 오디오 믹서 컨트롤
• 이것들은 ARM64용으로 컴파일되지 않은 네이티브 모듈이 필요합니다

ARM64를 사용해야 할 때

최적:

  • 네이티브 성능을 원하는 Surface Pro X 사용자
  • 시스템 오디오 없이 비디오/화면 녹화
  • 마이크 녹음 (직접 녹음 작동)
  • 에뮬레이션 속도 저하 없는 전체 성능

이상적이지 않음:

  • 시스템 오디오 캡처 (사용 불가)
  • 복잡한 오디오 워크플로우
  • 오디오 장치 선택 (사용 불가)

어느 버전을 가지고 있는지 알기

2. "시스템 종류" 찾기
3. 다음 중 하나 표시:
   • "x64 기반 프로세서" (64비트 Intel/AMD)
   • "ARM 기반 프로세서" (Windows on ARM)

명령줄:

PowerShell: wmic os get osarchitecture
출력: 64-bit 또는 ARM 64-bit

설치

SeaMeet은 아키텍처를 자동 감지합니다:

• 일반 설치 프로그램 다운로드
• 올바른 버전을 자동으로 설치합니다
• x64 사용자: SeaMeet-...-x64-Setup.exe
• ARM64 사용자: SeaMeet-...-arm64-Setup.exe

또는 릴리스에서 올바른 것을 수동으로 다운로드:
• 시스템 종류 확인 (위)
• 일치하는 아키텍처 다운로드

ARM64의 자동 업데이트

원활한 업데이트:
• 앱이 자동으로 업데이트를 확인
• ARM64는 ARM64로 업데이트 (x64가 아님)
• 이전 버전과 역호환
• 수동 개입 필요 없음

ARM64 문제 해결

문제: "시스템 오디오" 옵션이 회색으로 표시됨

ARM64의 예상 동작:
✓ 이는 정상입니다
✓ 네이티브 모듈을 사용할 수 없음
✓ 여전히 마이크 녹음 가능
✓ 오류 없음 - 우아한 저하

문제: 마이크/스피커를 선택할 수 없음

해결책:
1. 기본 시스템 장치 사용
2. Windows Sound 설정으로 가서 장치 선택
3. SeaMeet은 Windows가 선택한 것을 사용합니다
4. ARM64에서는 수동 장치 선택 사용 불가

문제: 마이크 녹음이 작동하지 않음

해결책:
1. Windows Sound 설정 확인
2. 마이크가 기본 입력 장치여야 함
3. SeaMeet에 마이크 권한 부여
4. Windows에 녹음 수준이 표시되어야 함
5. 먼저 Windows 녹음 앱에서 테스트

  • Quick Sync가 있는 Intel Mac은 괜찮습니다

   - Stereo Mix 활성화

2. WASAPI 방법 사용:
   - SeaMeet 설정 → 오디오 → 방법
   - WASAPI 루프백 선택

3. Realtek에 Stereo Mix 없음:
   - Realtek 드라이버 업데이트
   - 또는 대신 WASAPI 방법 사용

4. Windows 11 전용:
   - 개인정보 설정 확인
   - 설정 → 개인정보 → 마이크
   - 앱이 오디오에 액세스할 수 있는지 확인

문제: 게임 녹화 검은 화면

해결책:

1. 전체 화면 최적화 비활성화:
   - 게임 exe 우클릭 → 속성
   - 호환성 → 전체 화면 최적화 비활성화

2. 창 또는 테두리 없는 모드 사용

3. Windows 게임 바 비활성화:
   - SeaMeet과 충돌할 수 있음

4. SeaMeet을 관리자로 실행

5. 사용 가능한 경우 게임 캡처 모드 사용

macOS 전용 문제

문제: 시스템 오디오 없음

해결책:

1. 화면 녹화 권한 부여:
   시스템 환경설정 → 보안 및 개인정보 보호 → 개인정보 → 화면 녹화
   SeaMeet 체크
   SeaMeet 다시 시작

2. BlackHole (가상 오디오) 설치:
   brew install blackhole-2ch
   또는 GitHub에서 다운로드

3. 멀티 출력 장치 설정:
   Audio MIDI Setup → Create Multi-Output
   스피커 + BlackHole 추가
   시스템 출력으로 설정

4. 새 macOS (12+):
   내장 루프백이 있을 수 있음
   SeaMeet 설정 확인

문제: SeaMeet이 시작되지 않음

해결책:

1. 권한 확인:
   - 화면 녹화
   - 마이크
   - 접근성
   - 시스템 이벤트

2. 우클릭 → Open:
   - 처음에 필요할 수 있음
   - Gatekeeper 우회

3. 격리 속성 확인:
   xattr -d com.apple.quarantine /Applications/SeaMeet.app

4. macOS 버전 확인:
   • macOS 14.2 Sonoma 이상 필요
   • Apple 아이콘 → 이 Mac에 대하여로 확인
   • 필요한 경우 업데이트

5. 완전히 다시 시작:
   - 강제 종료: Cmd+Q
   - 앱 완전히 종료
   - 다시 실행

6. SeaMeet 재설치
   - 응용 프로그램에서 제거
   - 새 DMG 다운로드
   - 재설치

문제: 미팅 감지가 작동하지 않음

해결책:

1. macOS 버전 확인:
   • 미팅 감지에는 macOS 14.2+ 필요
   • 이 Mac에 대하여 확인
   • 이전 버전이면 업데이트

2. 필요한 권한 부여:
   시스템 환경설정 → 보안 및 개인정보 보호 → 개인정보
   ✓ 화면 녹화
   ✓ 마이크
   SeaMeet 다시 시작

3. 미팅 플랫폼 확인:
   • 미팅 앱에 마이크 액세스 권한이 있는지 확인
   • 시스템 환경설정 → 보안 및 개인정보 보호 → 마이크
   • 필요한 경우 미팅 앱 추가 (Zoom, Teams 등)

4. 창 감지 테스트:
   • 지원되는 앱에서 미팅 시작
   • 창이 SeaMeet에 나타나는지 확인
   • 먼저 창을 수동으로 선택해 보기

5. 브라우저 미팅:
   • 미팅 브라우저 탭이 활성인지 확인
   • 브라우저에 화면 녹화 권한이 있어야 함
   • 일부 브라우저는 추가 설정이 필요할 수 있음

Linux 전용 문제

문제: 오디오 장치가 표시되지 않음

해결책:

1. 오디오 시스템 확인:
   - PulseAudio가 실행 중입니까?
   - 또는 PipeWire?
   pactl info

2. 권한:
   - 사용자를 오디오 그룹에 추가
   sudo usermod -a -G audio $USER

3. pavucontrol 설치:
   - PulseAudio 볼륨 컨트롤
   - 입력/출력 장치 확인

4. SeaMeet에 특정 설정이 필요할 수 있음:
   - 앱 내 오디오 구성 따르기
   - 가상 장치가 필요할 수 있음

문제: 높은 CPU 사용량

해결책:

1. 하드웨어 가속 활성화:
   - VA-API 드라이버 설치
   - NVIDIA: NVENC 지원 확인
   - AMD: 제한적일 수 있음

2. 더 낮은 품질 설정 사용:
   - 1080p 대신 720p
   - 더 낮은 프레임 속도

3. 느린 디스크에 녹화하는지 확인:
   - 가능하면 SSD 사용
   - 디스크 성능 확인

4. 데스크톱 환경:
   - 일부 DE는 더 많은 리소스 사용
   - 필요한 경우 가벼운 WM 시도

파트 7: 크로스 플랫폼 워크플로우 팁

플랫폼 간 이동

설정 전송:

SeaMeet 설정은 로컬에 저장됨
자동으로 클라우드 동기화되지 않음

수동 전송:
1. 설정 내보내기 (기능이 사용 가능한 경우)
2. 또는 주요 설정 기록
3. 다른 플랫폼에서 재구성
4. 일부 차이 예상

파일 호환성:

녹음 파일은 범용적:
• MP4가 모든 플랫폼에서 작동
• WebM이 모든 플랫폼에서 작동
• MOV가 모든 플랫폼에서 작동 (코덱 포함)

컴퓨터를 전환할 때 변환 필요 없음

키보드 단축키:

Windows/Linux: Ctrl + Alt + [키]
Mac: Cmd + Shift + [키]

근육 기억이 조정 필요
각 플랫폼의 설정에서 단축키 확인

특정 사용에 대한 최적 플랫폼

게임용:

  • Windows (최고의 하드웨어 지원, 가장 많은 게임)

크리에이티브 작업용:

  • macOS (크리에이티브 앱과의 통합)

프로그래밍/개발용:

  • 모두 (개인 선호도)
  • 오픈 소스를 선호하면 Linux

비즈니스/엔터프라이즈용:

  • Windows (가장 일반적, 가장 쉬운 IT 지원)
  • macOS (비즈니스에서 성장)

개인정보용:

  • Linux (가장 많은 제어)

요약

SeaMeet은 모든 주요 플랫폼에서 작동하지만 각각 강점이 있습니다:

✅ Windows: 가장 많은 기능, 가장 쉬운 설정, 최고의 게임, 포괄적인 오디오 제어

✅ macOS: 세련됨, 스마트 미팅 감지, 별도 최적화된 DMG를 통해 Intel과 Apple Silicon 모두 작동 (범용 바이너리가 아님 — 칩과 일치하는 것을 선택), 우수한 성능

✅ Linux: 유연함, 개인정보 중심, 커뮤니티 지원, 소스 전용 설치 (사전 빌드 설치 프로그램 없음 — v2.1.4부터 깨끗한 npm install)

플랫폼 권장 사항:

다음의 경우 Windows를 선택:

  • 최대 호환성을 원함
  • 게임을 녹화함
  • 쉬운 시스템 오디오 캡처가 필요함
  • NVIDIA/AMD GPU 사용
  • 최대 기능 제어가 필요함

다음의 경우 macOS를 선택:

  • Apple 생태계에 있음
  • Intel 또는 Apple Silicon Mac이 있음 (둘 다 지원됨)
  • 세련된 네이티브 경험을 원함
  • 크리에이티브 작업을 함
  • 자동 미팅 감지 및 스마트 창 선택을 원함
  • 통합된 앱별 오디오 모니터링을 중요시함

다음의 경우 Linux를 선택:

  • 기술적으로 능숙함
  • 오픈 소스를 중요시함
  • 최대 제어를 원함
  • 구성을 신경 쓰지 않음
  • 커뮤니티 지원 옵션을 선호함

v1.0.5+의 macOS 장점:

✨ 새 기능 (macOS 14.2+):
• 앱별 마이크 모니터링 (native-audio-node)
• 자동 미팅 감지
• 스마트 창 사전 선택
• 브라우저 미팅 감지
• 자동 시작 방지
• 별도 최적화된 설치 프로그램 (Intel + Apple Silicon)
• 더 작은 다운로드 크기 (아키텍처당 ~100 MB)
