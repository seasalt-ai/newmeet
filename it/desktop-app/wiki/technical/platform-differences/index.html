Differenze di piattaforma

Capitolo 29: Differenze di piattaforma

Introduzione

SeaMeet funziona su più piattaforme—Windows, macOS e Linux—ma ogni sistema operativo ha le sue stranezze, capacità e limitazioni. Ciò che funziona perfettamente su Windows potrebbe comportarsi diversamente su Mac. Alcune funzionalità sono disponibili su una piattaforma ma non su un'altra. Comprendere queste differenze vi aiuta a ottenere il massimo da SeaMeet indipendentemente da quale computer state usando.

Questo capitolo spiega come SeaMeet si adatta a ciascuna piattaforma, quali funzionalità sono specifiche per piattaforma e quali limitazioni dovreste conoscere.

Obiettivi del capitolo

Dopo aver letto questo capitolo, sarete in grado di:

  • Comprendere le differenze tra le versioni Windows, macOS e Linux
  • Sapere quali funzionalità sono specifiche per piattaforma
  • Configurare SeaMeet correttamente per il vostro sistema operativo
  • Aggirare le limitazioni specifiche della piattaforma
  • Scegliere la piattaforma giusta per le vostre esigenze di registrazione

Parte 1: Panoramica per piattaforma

SeaMeet su Windows

Ideale per:

  • Massima compatibilità
  • Registrazione di giochi
  • Ambienti aziendali
  • Versione più completa di funzionalità

Caratteristiche chiave:

  • La maggior parte delle funzionalità disponibili
  • Migliore supporto per l'accelerazione hardware (NVIDIA/AMD/Intel)
  • Cattura facile dell'audio di sistema
  • Compatibilità app più ampia
  • La più testata e stabile

Versioni di Windows supportate:

  • Windows 10 (versione 1809 e successive)
  • Windows 11
  • Windows Server 2019/2022 (supporto limitato)

Architetture Windows supportate:

  • x64 (Intel/AMD 64-bit): Supporto completo, tutte le funzionalità disponibili
  • ARM64 (Windows on ARM): Supportato, alcune funzionalità audio non disponibili
    • Surface Pro X e dispositivi simili
    • Registrazione dello schermo, registrazione video, registrazione microfono completamente supportate
    • Cattura audio di sistema ed enumerazione dei dispositivi audio non disponibili (degradazione graduale)
    • Vedi la sezione Windows ARM64 sotto per i dettagli

Non supportati:

  • Windows 7, 8, 8.1 (fine vita)
  • Windows XP/Vista (antichi)
  • Windows 32-bit (x86)

SeaMeet su macOS

Ideale per:

  • Professionisti creativi
  • Utenti dell'ecosistema Apple
  • Interfaccia pulita e coerente
  • Integrazione con flussi di lavoro Mac

Caratteristiche chiave:

  • Interfaccia Mac nativa raffinata
  • Prestazioni eccellenti su Apple Silicon (M1/M2/M3)
  • Prestazioni eccellenti su Mac Intel
  • Stretta integrazione di sistema
  • Modello di permessi diverso
  • Monitoraggio microfono per app
  • Rilevamento riunioni del browser e prevenzione dell'avvio automatico

Versioni di macOS supportate:

  • macOS 14.2 Sonoma (minimo - richiesto per le funzionalità native-audio-node)
  • macOS 15 Sequoia
  • Versioni future

Architetture macOS supportate:

  • Apple Silicon (arm64): Supporto completo, tutte le funzionalità incluso il rilevamento audio per app
  • Intel (x64): Supporto completo con installer separato

Supporto Apple Silicon e Intel:

  • Due installer DMG separati: uno per Intel, uno per Apple Silicon
  • Scaricate la versione corrispondente al processore del vostro Mac
  • Mac M1/M2/M3 → Scaricate versione arm64
  • Mac Intel → Scaricate versione x64
  • Entrambe le versioni hanno funzionalità identiche
  • Accelerazione hardware tramite VideoToolbox (Apple Silicon) o Quick Sync (Intel)
  • Rilevamento microfono per app (native-audio-node)
  • Pre-selezione intelligente della finestra per applicazioni di riunione

SeaMeet su Linux

Ideale per:

  • Utenti tecnici che eseguono SeaMeet dal sorgente
  • Sviluppatori che contribuiscono al progetto
  • Utenti attenti alla privacy
  • Sostenitori dell'open source

Caratteristiche chiave:

  • Supportato dalla comunità, solo sorgente (nessun installer ufficiale precostruito)
  • Set di funzionalità variabile per distribuzione
  • Richiesta più configurazione manuale
  • Compatibile con la riga di comando
  • Meno funzionalità "funziona e basta"

Distribuzioni supportate:

  • Ubuntu 20.04+ (miglior supporto)
  • Fedora 34+
  • Debian 11+
  • Altre distro basate su Debian/Ubuntu

Note di installazione Linux (v2.1.4+):

✅ npm install ora funziona pulito su Linux

Fino a v2.1.4, `npm install` falliva su Linux con EBADPLATFORM
perché native-audio-node — un modulo nativo solo per macOS/Windows —
era elencato in `dependencies`. A partire da v2.1.4 vive in
`optionalDependencies` insieme agli altri pacchetti audio specifici
per piattaforma (macos-audio-devices, native-sound-mixer, win-audio),
quindi npm li salta su Linux invece di abortire.

Se in precedenza avete incontrato `npm ERR! EBADPLATFORM`:
1. Pull v2.1.4 o successivo
2. Eliminate node_modules e package-lock.json
3. Eseguite npm install di nuovo — dovrebbe completarsi senza errori

Limitazioni:

  • Nessun installer ufficiale precostruito — eseguite dal sorgente tramite npm start
  • Monitoraggio del microfono per app e rilevamento automatico delle riunioni non disponibili (richiedono native-audio-node, che non ha binario Linux)
  • La disponibilità del System Tray dipende dall'ambiente desktop (vedi sezione Tray sotto)
  • L'accelerazione hardware varia in base alla combinazione GPU/driver
  • Più configurazione richiesta per la cattura audio di sistema (loopback PulseAudio / PipeWire)

System Tray e modalità Lite per piattaforma

SeaMeet continua a funzionare in background dopo che chiudete la finestra principale — il system tray (chiamato barra dei menu su macOS) è il modo in cui tornate ad esso, cambiate lo stato di registrazione ed uscite puliti. L'API Tray di Electron è specifica per piattaforma, quindi il comportamento varia:

CapacitàWindowsmacOSLinux
Icona tray✅ tray.ico nell'area notifiche✅ Template icon.png nella barra dei menu (si adatta a scuro/chiaro)⚠️ Dipende dall'ambiente desktop
Icona stato registrazione✅ Scambio tray-recording.ico rosso✅ Scambio non-template icon-recording.png rosso⚠️ Stesso scambio, ma rendering dipende dal DE
Posizione tray persistente✅ Sì (legata a GUID, solo build pacchettizzate)✅ N/A (l'ordine della barra dei menu è controllato dall'utente)❌ Non garantito
Menu contestuale tasto destro✅ Completo✅ Completo⚠️ Solo alcuni DE
"Avvia nascosto nel tray"✅ Supportato✅ Supportato⚠️ Migliore sforzo
Modalità Lite (UI floater compatta)✅ Completo✅ Completo✅ Completo

Note Tray Linux:

Il tray Electron funziona in modo affidabile su GNOME (con l'estensione AppIndicator), KDE Plasma, XFCE, Cinnamon e la maggior parte dei desktop Ubuntu/Fedora predefiniti. Su sessioni solo Wayland e alcuni window manager minimi, l'icona del tray potrebbe non apparire affatto — l'app funziona ancora, ma dovrete rilanciarla dal terminale o usare un tasto rapido globale per riportare la finestra. Non c'è un asset di icona tray specifico per Linux; lo stesso .ico viene caricato come per Windows.

Modalità Lite:

La modalità Lite (introdotta in v2.x) è un layout compatto lato renderer — una barra floater 560×80 con i controlli di registrazione, forma d'onda e azioni rapide invece dell'intera finestra dell'app. È controllata dall'impostazione ui.appMode ('full' o 'lite') e cambia in fase di runtime tramite Impostazioni. La modalità Lite funziona in modo identico su tutte e tre le piattaforme perché non ha alcun percorso di codice specifico per piattaforma.

Parte 3: Funzionalità e configurazione specifiche di Windows

Vantaggi di Windows

1. L'audio di sistema è facile

Su Windows, catturare l'audio di sistema è semplice:

Metodo: Stereo Mix (più affidabile)

Configurazione:
1. Tasto destro sull'icona altoparlante → Apri impostazioni audio
2. Pannello di controllo audio → Registrazione
3. Tasto destro nell'area vuota → Mostra dispositivi disabilitati
4. Tasto destro su "Stereo Mix" → Abilita
5. Imposta come predefinito

SeaMeet può ora catturare l'audio di sistema direttamente

Metodi alternativi:

  • Loopback WASAPI (metodo moderno)
  • Cattura DirectSound
  • Cavi audio virtuali

2. Abbondanza di accelerazione hardware

Windows ha il miglior supporto per encoder GPU:

GPU NVIDIA:

GTX 600 series e più recenti:
• Chip dedicato encoder NVENC
• Qualità eccellente
• Molto efficiente
• SeaMeet supporta automaticamente

GPU AMD:

Radeon HD 7000 series e più recenti:
• VCE (Video Coding Engine)
• Buona qualità
• Codifica efficiente
• Supporto automatico

Intel integrato:

4a generazione Core e più recente:
• Quick Sync Video
• Sorprendentemente buona qualità
• Molto efficiente dal punto di vista energetico
• Ottimo per laptop

3. Funzionalità di gioco

Integrazione di gioco specifica per Windows:

Supporto modalità Gioco:
• API Windows Game Mode
• Auto-rileva quando in giochi
• Ottimizza risorse
• Disponibile solo su Windows

Integrazione Game Bar:
• Può funzionare insieme a Xbox Game Bar
• Nessun conflitto
• Scorciatoie separate

Guida alla configurazione Windows

Configurazione ottimale:

1. Abilita Stereo Mix per audio di sistema
2. Aggiorna i driver GPU:
   - NVIDIA: GeForce Experience
   - AMD: Radeon Software
   - Intel: Intel Driver Assistant

3. Abilita accelerazione hardware in SeaMeet:
   Impostazioni → Video → Usa accelerazione hardware

4. Imposta il piano energetico su "Alte prestazioni" per la registrazione

5. Disabilita Windows Game Mode se causa problemi:
   Impostazioni → Giochi → Modalità Gioco → Off

Scorciatoie specifiche di Windows

Scorciatoie globali (funzionano ovunque):
• Ctrl + Alt + R — Avvia/Ferma registrazione
• Ctrl + Alt + F — Salva Flashback
• Ctrl + Alt + S — Schermata

Gestione finestre:
• Win + G — Game bar (se abilitato)
• Win + Alt + R — Registrazione Xbox Game Bar
   (funziona insieme a SeaMeet)

Informazioni specifiche di Windows ARM64

Cos'è Windows ARM64?

ARM64 è un'architettura di processore diversa:
• Usata in dispositivi Windows on ARM (Surface Pro X, ecc.)
• Supporto nativo per processori basati su ARM
• Può emulare app x64 (più lento)
• Crescente supporto per app ARM64 native

SeaMeet su ARM64

SeaMeet ha supporto ARM64 nativo a partire da v1.0.2+:

✅ Completamente supportato su ARM64:
• Registrazione schermo (alte prestazioni)
• Registrazione video (alte prestazioni)
• Registrazione microfono (API Windows diretta)
• Rilevamento e gestione finestre
• Widget Floater e scorciatoie da tastiera
• Impostazioni e libreria di registrazioni
• Tutte le funzionalità UI

❌ Non disponibile su ARM64:
• Cattura audio di sistema (audio da app/altoparlanti)
• Enumerazione dispositivi audio (rilevamento mic/altoparlanti)
• Controllo mixer audio
• Questi richiedono moduli nativi non compilati per ARM64

Confronto funzionalità: x64 vs ARM64

Quando dovreste usare ARM64

Ideale per:

  • Utenti Surface Pro X che vogliono prestazioni native
  • Registrazione video/schermo senza audio di sistema
  • Registrazione microfono (la registrazione diretta funziona)
  • Prestazioni complete senza rallentamenti dell'emulazione

Non ideale per:

  • Cattura audio di sistema (non sarà disponibile)
  • Flussi di lavoro audio complessi
  • Selezione dispositivo audio (non disponibile)

Come sapere quale versione avete

Impostazioni Windows:
1. Impostazioni → Sistema → Informazioni
2. Cercate "Tipo di sistema"
3. Mostra:
   • "Processore basato su x64" (Intel/AMD 64-bit)
   • "Processore basato su ARM" (Windows on ARM)

Riga di comando:

PowerShell: wmic os get osarchitecture
Output: 64-bit o ARM 64-bit

Installazione

SeaMeet rileva automaticamente la vostra architettura:

• Scaricate l'installer generico
• Installerà automaticamente la versione corretta
• Utenti x64 ottengono: SeaMeet-...-x64-Setup.exe
• Utenti ARM64 ottengono: SeaMeet-...-arm64-Setup.exe

O scaricate manualmente quello giusto dai rilasci:
• Controllate il vostro tipo di sistema (sopra)
• Scaricate l'architettura corrispondente

Auto-updater su ARM64

Aggiornamenti senza interruzioni:
• L'app controlla automaticamente gli aggiornamenti
• ARM64 si aggiorna ad ARM64 (non x64)
• Retrocompatibile con versioni precedenti
• Nessun intervento manuale necessario

Risoluzione dei problemi ARM64

Problema: Opzione "Audio di sistema" disattivata

Comportamento atteso su ARM64:
✓ Questo è normale
✓ Modulo nativo non disponibile
✓ Può ancora registrare microfono
✓ Nessun errore - degradazione graduale

Problema: Non riesco a selezionare microfono/altoparlante

Soluzioni:
1. Usate i dispositivi di sistema predefiniti
2. Andate nelle impostazioni audio di Windows per scegliere il dispositivo
3. SeaMeet userà qualunque cosa Windows abbia selezionato
4. Selezione manuale del dispositivo non disponibile su ARM64

Problema: La registrazione del microfono non funziona

Soluzioni:
1. Controllate le impostazioni audio di Windows
2. Il microfono dovrebbe essere il dispositivo di input predefinito
3. Concedete i permessi del microfono a SeaMeet
4. Windows dovrebbe mostrare il livello di registrazione
5. Testate prima nell'app di registrazione di Windows

Parte 4: Funzionalità e configurazione specifiche di macOS

Vantaggi di macOS

1. Interfaccia raffinata

SeaMeet su Mac sembra nativo:

• Segue le linee guida di design macOS
• Usa controlli nativi
• Rispetta il tema di sistema
• Supporto Touch Bar (su Mac compatibili)
• Integrazione corretta della barra dei menu

2. Eccellente supporto Apple Silicon

I chip M1/M2/M3 funzionano alla grande:

Funzionalità Apple Silicon:
• Accelerazione hardware tramite VideoToolbox
• Prestazioni eccellenti per watt
• Codifica veloce
• Funzionamento fresco
• Lunga durata della batteria durante la registrazione

3. Integrazione di sistema

Integrazione macOS:
• Supporto iCloud Drive
• Compatibile Time Machine
• Pronto per Handoff/Continuity
• Sandboxing appropriato
• Segnalibri con ambito di sicurezza

Limitazioni macOS

1. L'audio di sistema richiede permesso

A differenza di Windows, macOS necessita di un permesso esplicito:

Passaggi di configurazione:

1. Prima volta che si registra l'audio di sistema:
   Preferenze di Sistema → Sicurezza e Privacy → Privacy
   
2. Cliccate "Registrazione schermo" a sinistra

3. Spuntate "SeaMeet" nell'elenco
   (Potrebbe essere necessario sbloccare con la password)

4. Riavviate completamente SeaMeet

5. L'audio di sistema funzionerà ora

Perché è richiesto:

  • Modello di sicurezza macOS
  • La registrazione dello schermo cattura tutto
  • L'utente deve consentire esplicitamente
  • Protegge contro lo spyware

2. Nessuna accelerazione hardware NVIDIA/AMD

Accelerazione hardware Mac:
• Mac Intel: Intel Quick Sync (se disponibile)
• Apple Silicon: VideoToolbox (eccellente)
• GPU esterne: Non supportate per la codifica
• Nessun NVENC o AMD VCE (chip non presenti)

Prestazioni:

  • Apple Silicon è così efficiente che non importa
  • I Mac Intel con Quick Sync vanno bene
  • I Mac Intel più vecchi senza Quick Sync usano la codifica CPU

3. Restrizioni di sandboxing

Sicurezza macOS:
• Le app sono in sandbox
• Devono richiedere il permesso per:
  - Microfono
  - Fotocamera (se usata)
  - Registrazione schermo
  - Posizioni del file system
  - Cartella Download
  - Desktop

SeaMeet vi chiederà questi quando necessario

Installer specifici per architettura macOS

SeaMeet su macOS fornisce installer separati per Mac Intel e Apple Silicon:

Quale versione dovrei scaricare?

Controllate il tipo del vostro Mac:
Menu Apple (🍎) → Informazioni su questo Mac → Chip

Se vedete:
• "Apple M1", "Apple M2" o "Apple M3"
  → Scaricate: SeaMeet-macOS-arm64-[versione].dmg

• "Intel Core i5", "Intel Core i7", ecc.
  → Scaricate: SeaMeet-macOS-x64-[versione].dmg

Perché installer separati?

✅ Dimensione di download più piccola (~100 MB ciascuno vs ~180 MB universale)
✅ Ottimizzato per il vostro processore specifico
✅ Nessun problema di compatibilità con moduli nativi
✅ Processo di build e aggiornamento più semplice

Prestazioni:

Apple Silicon (arm64):
• Chip M1, M2, M3
• Prestazioni eccellenti
• Migliore durata della batteria
• Esecuzione arm64 nativa

Intel (x64):
• Mac 2013-2021
• Parità completa di funzionalità
• Accelerazione Quick Sync
• Esecuzione x64 nativa

Installazione:

1. Scaricate il DMG corretto per il vostro Mac
2. Aprite il file DMG
3. Trascinate SeaMeet in Applicazioni
4. Lanciate e concedete i permessi

Funzionalità di rilevamento riunioni macOS

SeaMeet su macOS include rilevamento avanzato delle riunioni con monitoraggio audio per app:

Monitoraggio del microfono per app:

Come funziona:
• Monitora quale app sta usando il vostro microfono
• Rileva quando iniziano/finiscono le riunioni
• Usa native-audio-node per il rilevamento per app
• Disponibile su macOS 14.2+ (Sonoma)

Piattaforme supportate:
• Zoom
• Google Meet
• Microsoft Teams
• Apple FaceTime
• Webex
• E altre piattaforme di riunione

Rilevamento riunioni nel browser:

Auto-rileva riunioni attive in:
• Google Meet (Chrome/Firefox/Safari)
• Client web Zoom
• Client web Webex
• Teams web
• Altre piattaforme di riunione web

Pre-selezione finestra:
• Seleziona automaticamente la finestra della riunione
• Previene la registrazione accidentale di altre app
• Nessun avvio automatico a meno che non sia abilitato esplicitamente
• Controllo dell'utente mantenuto

Requisiti:

macOS 14.2 Sonoma o successivo
• Richiesto per le API native-audio-node
• Copre tutti gli utenti Mac moderni
• Abilita il rilevamento audio per app

Guida alla configurazione macOS

Configurazione iniziale:

1. Installate SeaMeet
   - Scaricate il DMG corretto (arm64 per Apple Silicon, x64 per Intel)
   - Aprite il file DMG
   - Trascinate SeaMeet in Applicazioni
   - Doppio clic per avviare

2. Concedete i permessi (Critico!):
   Preferenze di Sistema → Sicurezza e Privacy → Privacy

   Abilitate per:
   ☑ Registrazione schermo
   ☑ Microfono
   ☑ Accessibilità (per alcune scorciatoie)
   ☑ System Events (per interazione con barra dei menu)

3. Riavviate completamente SeaMeet
   - Force quit (Cmd+Q)
   - Rilanciate

4. Testate la registrazione
   - Test semplice prima
   - Poi provate il rilevamento riunioni

5. Per l'audio di sistema:
   - SeaMeet rileva l'audio di sistema automaticamente
   - O usate BlackHole (driver audio virtuale) per configurazioni avanzate
   - O usate il loopback integrato su macOS più recente
   - Seguite le istruzioni in-app se necessario

• Touch Bar: Pulsante registra (se disponibile)

Parte 5: Informazioni specifiche di Linux

Caratteristiche di Linux

1. Esperienza variabile

Le versioni Linux variano per distribuzione:

Ubuntu (consigliato):
• Meglio supportato
• Configurazione più facile
• La maggior parte delle funzionalità funzionano
• Test regolari

Fedora:
• Buon supporto
• Pacchetti più nuovi
• Potrebbero servire repo extra

Altre distro:
• Il vostro chilometraggio può variare
• Supporto della comunità
• Potrebbe servire correzioni manuali

2. Complessità della cattura audio

L'audio Linux è più complesso:

Sistemi audio:
• PulseAudio (più comune)
• PipeWire (più nuovo, moderno)
• ALSA (basso livello)
• JACK (audio professionale)

Configurazione richiesta:
Potrebbe essere necessario creare dispositivi audio virtuali
O usare moduli loopback
Non "plug and play" come Windows

Configurazione PulseAudio:

# Crea sink virtuale per audio di sistema
pactl load-module module-null-sink sink_name=SeaMeet sink_properties=device.description=SeaMeetRecording

# Monitoralo
pactl load-module module-loopback source=SeaMeet.monitor

3. L'accelerazione hardware varia

NVIDIA su Linux:
• NVENC disponibile tramite driver proprietari
• Deve essere installato separatamente
• Qualità buona quando funziona

AMD su Linux:
• Supporto VCE varia per driver
• Driver open-source vs proprietari
• Potrebbe servire configurazione

Intel su Linux:
• VA-API per la codifica
• Solitamente funziona bene
• Parte dei driver Mesa

Guida alla configurazione Linux

Installazione Ubuntu:

# Scarica pacchetto .deb
# O installa tramite repository se disponibile

sudo dpkg -i seameet-linux.deb
sudo apt-get install -f  # Risolvi dipendenze

# Concedi permessi
# Aggiungi utente al gruppo video
sudo usermod -a -G video $USER

# Disconnettiti e riconnettiti

Installazione Fedora:

# Scarica pacchetto .rpm
sudo rpm -i seameet-linux.rpm

# O tramite dnf se nei repo
sudo dnf install seameet

Configurazione post-installazione:

# 1. Configurazione audio (complessa)
# Segui la guida di configurazione audio in-app di SeaMeet

# 2. Accelerazione hardware
# Installa i driver appropriati:
# NVIDIA: nvidia-utils o proprietari
# AMD: mesa-va-drivers
# Intel: intel-media-driver

# 3. Permessi
# Potrebbe essere necessario configurare regole udev
# Per accesso al dispositivo

Scorciatoie specifiche di Linux

Scorciatoie globali:
• Ctrl + Alt + R — Avvia/Ferma registrazione
• Ctrl + Alt + F — Salva Flashback
• Ctrl + Alt + S — Schermata

Nota: Possono entrare in conflitto con le scorciatoie del desktop

Parte 6: Risoluzione dei problemi specifica per piattaforma

Problemi specifici di Windows

Problema: Non posso catturare l'audio di sistema

Soluzioni:

1. Abilita Stereo Mix:
   - Pannello di controllo audio → Registrazione
   - Mostra dispositivi disabilitati
   - Abilita Stereo Mix

2. Usa metodo WASAPI:
   - Impostazioni SeaMeet → Audio → Metodo
   - Seleziona loopback WASAPI

3. No Stereo Mix su Realtek:
   - Aggiorna driver Realtek
   - O usa invece metodo WASAPI

4. Specifico Windows 11:
   - Controlla impostazioni privacy
   - Impostazioni → Privacy → Microfono
   - Assicurati che le app possano accedere all'audio

Problema: Schermo nero durante la registrazione del gioco

Soluzioni:

1. Disabilita ottimizzazione schermo intero:
   - Tasto destro su exe del gioco → Proprietà
   - Compatibilità → Disabilita ottimizzazioni a schermo intero

2. Usa modalità a finestra o senza bordi

3. Disabilita Windows Game Bar:
   - Potrebbe entrare in conflitto con SeaMeet

4. Esegui SeaMeet come amministratore

5. Usa modalità Cattura gioco se disponibile

Problemi specifici di macOS

Problema: Nessun audio di sistema

Soluzioni:

1. Concedi il permesso Registrazione schermo:
   Preferenze di Sistema → Sicurezza e Privacy → Privacy → Registrazione schermo
   Spunta SeaMeet
   Riavvia SeaMeet

2. Installa BlackHole (audio virtuale):
   brew install blackhole-2ch
   O scarica da GitHub

3. Configura dispositivo multi-output:
   Audio MIDI Setup → Crea Multi-Output
   Aggiungi altoparlanti + BlackHole
   Imposta come output di sistema

4. macOS più recente (12+):
   Potrebbe avere loopback integrato
   Controlla le impostazioni di SeaMeet

Problema: SeaMeet non si avvia

Soluzioni:

1. Controlla i permessi:
   - Registrazione schermo
   - Microfono
   - Accessibilità
   - System Events

2. Tasto destro → Apri:
   - La prima volta potrebbe essere necessario
   - Bypass Gatekeeper

3. Controlla l'attributo quarantine:
   xattr -d com.apple.quarantine /Applications/SeaMeet.app

4. Verifica versione macOS:
   • Richiede macOS 14.2 Sonoma o successivo
   • Controlla con icona Apple → Informazioni su questo Mac
   • Aggiorna se necessario

5. Riavvia completamente:
   - Force quit: Cmd+Q
   - Termina completamente l'app
   - Rilancia

6. Reinstalla SeaMeet
   - Rimuovi da Applicazioni
   - Scarica DMG fresco
   - Reinstalla

Problema: Il rilevamento riunioni non funziona

Soluzioni:

1. Verifica versione macOS:
   • Il rilevamento riunioni richiede macOS 14.2+
   • Controlla Informazioni su questo Mac
   • Aggiorna se su versione precedente

2. Concedi i permessi necessari:
   Preferenze di Sistema → Sicurezza e Privacy → Privacy
   ✓ Registrazione schermo
   ✓ Microfono
   Riavvia SeaMeet

3. Controlla la piattaforma di riunione:
   • Assicurati che l'app di riunione abbia accesso al microfono
   • Preferenze di Sistema → Sicurezza e Privacy → Microfono
   • Aggiungi app di riunione se necessario (Zoom, Teams, ecc.)

4. Testa il rilevamento finestra:
   • Avvia una riunione nell'app supportata
   • Controlla se la finestra appare in SeaMeet
   • Prova prima a selezionare la finestra manualmente

5. Riunioni del browser:
   • Assicurati che la scheda del browser della riunione sia attiva
   • Il browser deve avere il permesso di registrazione dello schermo
   • Alcuni browser potrebbero necessitare di configurazione aggiuntiva

Problemi specifici di Linux

Problema: Nessun dispositivo audio mostrato

Soluzioni:

1. Controlla il sistema audio:
   - PulseAudio è in esecuzione?
   - O PipeWire?
   pactl info

2. Permessi:
   - Aggiungi utente al gruppo audio
   sudo usermod -a -G audio $USER

3. Installa pavucontrol:
   - PulseAudio Volume Control
   - Controlla dispositivi input/output

4. SeaMeet potrebbe necessitare di configurazione specifica:
   - Segui la configurazione audio in-app
   - Potrebbero servire dispositivi virtuali

Problema: Alto utilizzo CPU

Soluzioni:

1. Abilita accelerazione hardware:
   - Installa driver VA-API
   - NVIDIA: Controlla supporto NVENC
   - AMD: Potrebbe essere limitato

2. Usa impostazioni di qualità inferiori:
   - 720p invece di 1080p
   - Frame rate inferiore

3. Controlla se la registrazione è su disco lento:
   - Usa SSD se possibile
   - Controlla le prestazioni del disco

4. Ambiente desktop:
   - Alcuni DE usano più risorse
   - Prova WM più leggero se necessario

Parte 7: Suggerimenti per flussi di lavoro multipiattaforma

Spostarsi tra piattaforme

Trasferimento delle impostazioni:

Le impostazioni di SeaMeet sono memorizzate localmente
Non sincronizzate automaticamente nel cloud

Trasferimento manuale:
1. Esporta impostazioni (se funzionalità disponibile)
2. O annota le impostazioni chiave
3. Riconfigura sull'altra piattaforma
4. Aspettati alcune differenze

Compatibilità dei file:

I file di registrazione sono universali:
• MP4 funziona su tutte le piattaforme
• WebM funziona su tutte le piattaforme
• MOV funziona su tutte le piattaforme (con codec)

Nessuna conversione necessaria quando si cambia computer

Scorciatoie da tastiera:

Windows/Linux: Ctrl + Alt + [tasto]
Mac: Cmd + Shift + [tasto]

La memoria muscolare avrà bisogno di adattamento
Controlla le scorciatoie nelle impostazioni su ciascuna piattaforma

Migliore piattaforma per usi specifici

Per giochi:

  • Windows (miglior supporto hardware, più giochi)

Per lavoro creativo:

  • macOS (integrazione con app creative)

Per programmazione/sviluppo:

  • Qualsiasi (preferenza personale)
  • Linux se preferite open source

Per business/aziende:

  • Windows (più comune, più facile supporto IT)
  • macOS (in crescita nel business)

Per privacy:

  • Linux (più controllo)

Riepilogo

SeaMeet funziona su tutte le principali piattaforme ma ognuna ha punti di forza:

✅ Windows: Più funzionalità, configurazione più facile, miglior gaming, controllo audio completo

✅ macOS: Raffinato, rilevamento intelligente delle riunioni, funziona sia su Intel che Apple Silicon tramite DMG separati ottimizzati (non un binario universale — scegliete quello che corrisponde al vostro chip), prestazioni eccellenti

✅ Linux: Flessibile, focalizzato sulla privacy, supportato dalla comunità, installazione solo sorgente (nessun installer precostruito — npm install pulito da v2.1.4 in poi)

Raccomandazioni di piattaforma:

Scegliete Windows se:

  • Volete massima compatibilità
  • Registrate giochi
  • Avete bisogno di cattura facile dell'audio di sistema
  • Usate GPU NVIDIA/AMD
  • Avete bisogno di massimo controllo delle funzionalità

Scegliete macOS se:

  • Siete nell'ecosistema Apple
  • Avete Mac Intel o Apple Silicon (entrambi supportati)
  • Volete un'esperienza nativa raffinata
  • Fate lavoro creativo
  • Volete rilevamento automatico delle riunioni e selezione intelligente della finestra
  • Apprezzate il monitoraggio audio per app integrato

Scegliete Linux se:

  • Siete tecnicamente inclini
  • Apprezzate l'open source
  • Volete massimo controllo
  • Non vi importa la configurazione
  • Preferite opzioni supportate dalla comunità

Vantaggi macOS in v1.0.5+:

✨ Nuove funzionalità (macOS 14.2+):
• Monitoraggio microfono per app (native-audio-node)
• Rilevamento automatico delle riunioni
• Pre-selezione intelligente della finestra
• Rilevamento riunioni del browser
• Prevenzione dell'avvio automatico
• Installer separati ottimizzati (Intel + Apple Silicon)
• Dimensioni di download più piccole (~100 MB per architettura)
