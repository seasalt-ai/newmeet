Różnice między platformami

Rozdział 29: Różnice między platformami

Wprowadzenie

SeaMeet działa na wielu platformach — Windows, macOS i Linux — ale każdy system operacyjny ma swoje dziwactwa, możliwości i ograniczenia. To, co działa idealnie w systemie Windows, może zachowywać się inaczej na komputerze Mac. Niektóre funkcje są dostępne na jednej platformie, ale nie na innej. Zrozumienie tych różnic pomaga w pełni wykorzystać SeaMeet bez względu na używany komputer.

Ten rozdział wyjaśnia, jak SeaMeet dostosowuje się do każdej platformy, jakie funkcje są specyficzne dla platformy i o jakich ograniczeniach powinieneś wiedzieć.

Cele rozdziału

Po przeczytaniu tego rozdziału będziesz w stanie:

  • Zrozumieć różnice między wersjami Windows, macOS i Linux
  • Wiedzieć, które funkcje są specyficzne dla platformy
  • Prawidłowo skonfigurować SeaMeet dla swojego systemu operacyjnego
  • Obejść ograniczenia specyficzne dla platformy
  • Wybrać odpowiednią platformę do swoich potrzeb nagrywania

Część 1: Przegląd według platformy

SeaMeet w systemie Windows

Najlepsze dla:

  • Maksymalnej kompatybilności
  • Nagrywania gier
  • Środowisk biznesowych
  • Najbardziej kompletnej funkcjonalnie wersji

Kluczowe cechy:

  • Najwięcej dostępnych funkcji
  • Najlepsze wsparcie akceleracji sprzętowej (NVIDIA/AMD/Intel)
  • Łatwe przechwytywanie dźwięku systemowego
  • Najszersza kompatybilność aplikacji
  • Najlepiej przetestowana i stabilna

Obsługiwane wersje Windows:

  • Windows 10 (wersja 1809 i nowsze)
  • Windows 11
  • Windows Server 2019/2022 (ograniczone wsparcie)

Obsługiwane architektury Windows:

  • x64 (Intel/AMD 64-bit): Pełne wsparcie, wszystkie funkcje dostępne
  • ARM64 (Windows on ARM): Obsługiwane, niektóre funkcje audio niedostępne
    • Surface Pro X i podobne urządzenia
    • Nagrywanie ekranu, nagrywanie wideo, nagrywanie mikrofonu w pełni obsługiwane
    • Przechwytywanie dźwięku systemowego i wyliczanie urządzeń audio niedostępne (płynna degradacja)
    • Szczegóły w sekcji Windows ARM64 poniżej

Nieobsługiwane:

  • Windows 7, 8, 8.1 (koniec wsparcia)
  • Windows XP/Vista (archaiczne)
  • 32-bitowy Windows (x86)

SeaMeet w systemie macOS

Najlepsze dla:

  • Profesjonalistów kreatywnych
  • Użytkowników ekosystemu Apple
  • Czystego, spójnego interfejsu
  • Integracji z workflow Mac

Kluczowe cechy:

  • Dopracowany, natywny interfejs Mac
  • Doskonała wydajność na Apple Silicon (M1/M2/M3)
  • Doskonała wydajność na Intel Mac
  • Ścisła integracja systemowa
  • Inny model uprawnień
  • Monitorowanie mikrofonu per aplikacja
  • Wykrywanie spotkań w przeglądarce i zapobieganie automatycznemu uruchamianiu

Obsługiwane wersje macOS:

  • macOS 14.2 Sonoma (minimum - wymagane dla funkcji native-audio-node)
  • macOS 15 Sequoia
  • Przyszłe wersje

Obsługiwane architektury macOS:

  • Apple Silicon (arm64): Pełne wsparcie, wszystkie funkcje, w tym wykrywanie dźwięku per aplikacja
  • Intel (x64): Pełne wsparcie z osobnym instalatorem

Wsparcie Apple Silicon i Intel:

  • Dwa osobne instalatory DMG: jeden dla Intel, jeden dla Apple Silicon
  • Pobierz wersję pasującą do procesora swojego Maca
  • Maci M1/M2/M3 → Pobierz wersję arm64
  • Maci Intel → Pobierz wersję x64
  • Obie wersje mają identyczne funkcje
  • Akceleracja sprzętowa poprzez VideoToolbox (Apple Silicon) lub Quick Sync (Intel)
  • Wykrywanie mikrofonu per aplikacja (native-audio-node)
  • Inteligentne pre-zaznaczanie okien aplikacji do spotkań

Kompatybilność z Intel Mac

SeaMeet w systemie Linux

Najlepsze dla:

  • Użytkowników technicznych uruchamiających SeaMeet ze źródeł
  • Programistów współtworzących projekt
  • Użytkowników dbających o prywatność
  • Zwolenników open-source

Kluczowe cechy:

  • Wspierany przez społeczność, tylko ze źródeł (brak oficjalnego prekompilowanego instalatora)
  • Zmienny zestaw funkcji w zależności od dystrybucji
  • Wymaga więcej ręcznej konfiguracji
  • Przyjazny dla wiersza poleceń
  • Mniej funkcji "działa od razu"

Obsługiwane dystrybucje:

  • Ubuntu 20.04+ (najlepsze wsparcie)
  • Fedora 34+
  • Debian 11+
  • Inne dystrybucje oparte na Debian/Ubuntu

Uwagi instalacyjne Linux (v2.1.4+):

✅ npm install teraz przechodzi czysto na Linux

Do wersji v2.1.4 `npm install` zawodził na Linux z błędem EBADPLATFORM,
ponieważ native-audio-node — natywny moduł tylko dla macOS/Windows —
był wymieniony w `dependencies`. Od wersji v2.1.4 znajduje się w
`optionalDependencies` obok innych pakietów audio specyficznych
dla platformy (macos-audio-devices, native-sound-mixer, win-audio),
więc npm pomija je na Linux zamiast przerywać.

Jeśli wcześniej napotkałeś `npm ERR! EBADPLATFORM`:
1. Pobierz v2.1.4 lub nowszą
2. Usuń node_modules i package-lock.json
3. Uruchom ponownie npm install — powinno zakończyć się bez błędów

Ograniczenia:

  • Brak oficjalnego prekompilowanego instalatora — uruchamiaj ze źródeł poprzez npm start
  • Monitorowanie mikrofonu per aplikacja i automatyczne wykrywanie spotkań są niedostępne (wymagają native-audio-node, który nie ma binarki Linux)
  • Dostępność System Tray zależy od środowiska graficznego (patrz sekcja Tray poniżej)
  • Akceleracja sprzętowa różni się w zależności od kombinacji GPU/sterownik
  • Wymaga więcej konfiguracji do przechwytywania dźwięku systemowego (PulseAudio / PipeWire loopback)

System Tray i tryb Lite według platformy

SeaMeet działa w tle po zamknięciu głównego okna — system tray (zwany paskiem menu na macOS) jest sposobem na powrót do niego, zmianę stanu nagrywania i czyste zamknięcie. Electronowe API Tray jest specyficzne dla platformy, więc zachowanie jest zróżnicowane:

Uwagi o Linux Tray:

Tray Electrona działa niezawodnie w GNOME (z rozszerzeniem AppIndicator), KDE Plasma, XFCE, Cinnamon i większości domyślnych pulpitów Ubuntu/Fedora. W sesjach tylko-Wayland i niektórych minimalnych menedżerach okien ikona tray może w ogóle się nie pojawić — aplikacja nadal działa, ale trzeba ją ponownie uruchomić z terminala lub użyć globalnego skrótu, aby przywrócić okno. Nie ma zasobu ikony tray specyficznego dla Linux; ładowany jest ten sam plik .ico co dla Windows.

Tryb Lite:

Tryb Lite (wprowadzony w v2.x) to kompaktowy układ po stronie renderera — pasek floatera 560×80 z kontrolkami nagrywania, wykresem fali i szybkimi akcjami zamiast pełnego okna aplikacji. Jest kontrolowany przez ustawienie ui.appMode ('full' lub 'lite') i przełącza się w czasie wykonania za pomocą Ustawienia. Tryb Lite działa identycznie na wszystkich trzech platformach, ponieważ nie ma ścieżki kodu specyficznej dla platformy.

Część 3: Funkcje i konfiguracja specyficzne dla Windows

Zalety Windows

1. Dźwięk systemowy jest łatwy

W systemie Windows przechwytywanie dźwięku systemowego jest proste:

Metoda: Stereo Mix (najbardziej niezawodna)

Konfiguracja:
1. Kliknij prawym na ikonę głośnika → Open Sound settings
2. Sound Control Panel → Recording
3. Kliknij prawym w pustym obszarze → Show Disabled Devices
4. Kliknij prawym na "Stereo Mix" → Enable
5. Ustaw jako Default

SeaMeet może teraz przechwytywać dźwięk systemowy bezpośrednio

Alternatywne metody:

  • WASAPI loopback (nowoczesna metoda)
  • DirectSound capture
  • Wirtualne kable audio

2. Mnóstwo akceleracji sprzętowej

Windows ma najlepsze wsparcie enkoderów GPU:

GPU NVIDIA:

Seria GTX 600 i nowsze:
• Dedykowany chip enkodera NVENC
• Doskonała jakość
• Bardzo wydajny
• SeaMeet wspiera automatycznie

GPU AMD:

Seria Radeon HD 7000 i nowsze:
• VCE (Video Coding Engine)
• Dobra jakość
• Wydajne kodowanie
• Automatyczne wsparcie

Intel zintegrowany:

4. generacja Core i nowsze:
• Quick Sync Video
• Zaskakująco dobra jakość
• Bardzo wydajny energetycznie
• Świetny dla laptopów

3. Funkcje gamingowe

Specyficzna dla Windows integracja gamingowa:

Wsparcie trybu gry:
• Windows Game Mode API
• Auto-wykrywanie gier
• Optymalizacja zasobów
• Dostępne tylko w Windows

Integracja Game Bar:
• Może działać obok Xbox Game Bar
• Brak konfliktów
• Osobne skróty

Przewodnik konfiguracji Windows

Optymalna konfiguracja:

1. Włącz Stereo Mix dla dźwięku systemowego
2. Zaktualizuj sterowniki GPU:
   - NVIDIA: GeForce Experience
   - AMD: Radeon Software
   - Intel: Intel Driver Assistant

3. Włącz akcelerację sprzętową w SeaMeet:
   Ustawienia → Wideo → Użyj akceleracji sprzętowej

4. Ustaw plan zasilania na "High Performance" dla nagrywania

5. Wyłącz Windows Game Mode, jeśli powoduje problemy:
   Ustawienia → Gaming → Game Mode → Off

Skróty specyficzne dla Windows

Skróty globalne (działają wszędzie):
• Ctrl + Alt + R — Start/Stop nagrywania
• Ctrl + Alt + F — Zapisz Flashback
• Ctrl + Alt + S — Zrzut ekranu

Zarządzanie oknami:
• Win + G — Game bar (jeśli włączony)
• Win + Alt + R — Xbox Game Bar record
   (działa obok SeaMeet)

Informacje specyficzne dla Windows ARM64

Czym jest Windows ARM64?

ARM64 to inna architektura procesora:
• Używana w urządzeniach Windows on ARM (Surface Pro X, itp.)
• Natywne wsparcie dla procesorów opartych na ARM
• Może emulować aplikacje x64 (wolniej)
• Rosnące wsparcie dla natywnych aplikacji ARM64

SeaMeet na ARM64

SeaMeet ma natywne wsparcie ARM64 od wersji v1.0.2+:

✅ W pełni obsługiwane na ARM64:
• Nagrywanie ekranu (wysoka wydajność)
• Nagrywanie wideo (wysoka wydajność)
• Nagrywanie mikrofonu (bezpośrednie API Windows)
• Wykrywanie i zarządzanie oknami
• Widget Floater i skróty klawiszowe
• Ustawienia i biblioteka nagrań
• Wszystkie funkcje UI

❌ Niedostępne na ARM64:
• Przechwytywanie dźwięku systemowego (dźwięk z aplikacji/głośników)
• Wyliczanie urządzeń audio (wykrywanie mikrofonu/głośnika)
• Kontrola miksera audio
• Wymagają natywnych modułów niekompilowanych dla ARM64

Kiedy używać ARM64

Najlepsze dla:

  • Użytkowników Surface Pro X chcących natywnej wydajności
  • Nagrywania wideo/ekranu bez dźwięku systemowego
  • Nagrywania mikrofonu (bezpośrednie nagrywanie działa)
  • Pełnej wydajności bez spowolnienia emulacji

Nieidealne dla:

  • Przechwytywania dźwięku systemowego (będzie niedostępne)
  • Złożonych workflow audio
  • Wyboru urządzeń audio (niedostępne)

Jak sprawdzić, którą wersję masz

Ustawienia Windows:
1. Ustawienia → System → About
2. Szukaj "System type"
3. Pokaże:
   • "x64-based processor" (64-bitowy Intel/AMD)
   • "ARM-based processor" (Windows on ARM)

Wiersz poleceń:

PowerShell: wmic os get osarchitecture
Wyjście: 64-bit lub ARM 64-bit

Instalacja

SeaMeet automatycznie wykrywa Twoją architekturę:

• Pobierz ogólny instalator
• Automatycznie zainstaluje poprawną wersję
• Użytkownicy x64 dostają: SeaMeet-...-x64-Setup.exe
• Użytkownicy ARM64 dostają: SeaMeet-...-arm64-Setup.exe

Lub pobierz ręcznie odpowiednią wersję z wydań:
• Sprawdź swój System type (powyżej)
• Pobierz pasującą architekturę

Auto-aktualizator na ARM64

Bezproblemowe aktualizacje:
• Aplikacja sprawdza aktualizacje automatycznie
• ARM64 aktualizuje do ARM64 (nie x64)
• Wstecznie kompatybilne z poprzednimi wersjami
• Brak potrzeby ręcznej interwencji

Rozwiązywanie problemów ARM64

Problem: Opcja "System Audio" wyszarzona

Oczekiwane zachowanie na ARM64:
✓ To jest normalne
✓ Natywny moduł niedostępny
✓ Nadal można nagrywać mikrofon
✓ Brak błędu - płynna degradacja

Problem: Nie można wybrać mikrofonu/głośnika

Rozwiązania:
1. Użyj domyślnych urządzeń systemowych
2. Przejdź do Windows Sound settings, aby wybrać urządzenie
3. SeaMeet użyje tego, co Windows ma wybrane
4. Ręczny wybór urządzenia niedostępny na ARM64

Problem: Nagrywanie mikrofonu nie działa

Rozwiązania:
1. Sprawdź Windows Sound settings
2. Mikrofon powinien być domyślnym urządzeniem wejściowym
3. Przyznaj uprawnienia mikrofonu SeaMeet
4. Windows powinien pokazywać poziom nagrywania
5. Najpierw przetestuj w aplikacji nagrywania Windows

Część 4: Funkcje i konfiguracja specyficzne dla macOS

Zalety macOS

1. Dopracowany interfejs

SeaMeet na Mac wygląda natywnie:

• Przestrzega wytycznych projektowania macOS
• Używa natywnych kontrolek
• Respektuje motyw systemowy
• Wsparcie Touch Bar (na kompatybilnych Mac)
• Prawidłowa integracja paska menu

2. Doskonałe wsparcie Apple Silicon

Chipy M1/M2/M3 działają świetnie:

Funkcje Apple Silicon:
• Akceleracja sprzętowa poprzez VideoToolbox
• Doskonała wydajność na wat
• Szybkie kodowanie
• Chłodne działanie
• Długa żywotność baterii podczas nagrywania

3. Integracja systemowa

Integracja macOS:
• Wsparcie iCloud Drive
• Kompatybilność z Time Machine
• Gotowe na Handoff/Continuity
• Prawidłowe sandboxing
• Zakładki o zakresie bezpieczeństwa

Ograniczenia macOS

1. Dźwięk systemowy wymaga uprawnień

W przeciwieństwie do Windows, macOS wymaga jawnego pozwolenia:

Kroki konfiguracji:

1. Pierwsze nagrywanie dźwięku systemowego:
   System Preferences → Security & Privacy → Privacy
   
2. Kliknij "Screen Recording" po lewej

3. Zaznacz "SeaMeet" na liście
   (Może wymagać odblokowania hasłem)

4. Całkowicie zrestartuj SeaMeet

5. Dźwięk systemowy będzie teraz działał

Dlaczego jest to wymagane:

  • Model bezpieczeństwa macOS
  • Nagrywanie ekranu przechwytuje wszystko
  • Użytkownik musi jawnie zezwolić
  • Chroni przed spyware

2. Brak akceleracji sprzętowej NVIDIA/AMD

Akceleracja sprzętowa Mac:
• Maci Intel: Intel Quick Sync (jeśli dostępne)
• Apple Silicon: VideoToolbox (doskonałe)
• Zewnętrzne GPU: Nieobsługiwane do kodowania
• Brak NVENC ani AMD VCE (chipy nieobecne)

Wydajność:

  • Apple Silicon jest tak wydajny, że to nie ma znaczenia
  • Maci Intel z Quick Sync są w porządku
  • Starsze Maci Intel bez Quick Sync używają kodowania CPU

3. Ograniczenia sandboxing

Bezpieczeństwo macOS:
• Aplikacje są w sandboxie
• Muszą żądać uprawnień do:
  - Mikrofonu
  - Kamery (jeśli używana)
  - Nagrywania ekranu
  - Lokalizacji systemu plików
  - Folderu Downloads
  - Desktop

SeaMeet poprosi o nie w razie potrzeby

Instalatory specyficzne dla architektury macOS

SeaMeet na macOS dostarcza osobne instalatory dla Maców Intel i Apple Silicon:

Którą wersję pobrać?

Sprawdź typ swojego Maca:
Menu Apple (🍎) → About This Mac → Chip

Jeśli widzisz:
• "Apple M1", "Apple M2" lub "Apple M3"
  → Pobierz: SeaMeet-macOS-arm64-[version].dmg

• "Intel Core i5", "Intel Core i7" itp.
  → Pobierz: SeaMeet-macOS-x64-[version].dmg

Dlaczego osobne instalatory?

✅ Mniejszy rozmiar pobierania (~100 MB każdy vs ~180 MB uniwersalny)
✅ Zoptymalizowany dla konkretnego procesora
✅ Brak problemów z kompatybilnością modułów natywnych
✅ Prostszy proces budowy i aktualizacji

Wydajność:

Apple Silicon (arm64):
• Chipy M1, M2, M3
• Doskonała wydajność
• Lepsza żywotność baterii
• Natywne wykonanie arm64

Intel (x64):
• Maci 2013-2021
• Pełna parzystość funkcji
• Akceleracja Quick Sync
• Natywne wykonanie x64

Instalacja:

1. Pobierz prawidłowy DMG dla swojego Maca
2. Otwórz plik DMG
3. Przeciągnij SeaMeet do Applications
4. Uruchom i przyznaj uprawnienia

Funkcje wykrywania spotkań w macOS

SeaMeet na macOS zawiera zaawansowane wykrywanie spotkań z monitorowaniem audio per aplikacja:

Monitorowanie mikrofonu per aplikacja:

Jak to działa:
• Monitoruje, która aplikacja używa Twojego mikrofonu
• Wykrywa, kiedy spotkania się rozpoczynają/kończą
• Używa native-audio-node do wykrywania per aplikacja
• Dostępne na macOS 14.2+ (Sonoma)

Obsługiwane platformy:
• Zoom
• Google Meet
• Microsoft Teams
• Apple FaceTime
• Webex
• I inne platformy do spotkań

Wykrywanie spotkań w przeglądarce:

Auto-wykrywa aktywne spotkania w:
• Google Meet (Chrome/Firefox/Safari)
• Klient web Zoom
• Klient web Webex
• Teams web
• Inne platformy spotkań oparte na web

Pre-zaznaczanie okien:
• Automatycznie zaznacza okno spotkania
• Zapobiega przypadkowemu nagrywaniu innych aplikacji
• Brak auto-startu, chyba że jawnie włączony
• Kontrola użytkownika utrzymana

Wymagania:

macOS 14.2 Sonoma lub nowsza
• Wymagana dla API native-audio-node
• Obejmuje wszystkich nowoczesnych użytkowników Mac
• Włącza wykrywanie audio per aplikacja

Przewodnik konfiguracji macOS

Pierwsza konfiguracja:

1. Zainstaluj SeaMeet
   - Pobierz prawidłowy DMG (arm64 dla Apple Silicon, x64 dla Intel)
   - Otwórz plik DMG
   - Przeciągnij SeaMeet do Applications
   - Kliknij dwukrotnie, aby uruchomić

2. Przyznaj uprawnienia (Krytyczne!):
   System Preferences → Security & Privacy → Privacy

   Włącz dla:
   ☑ Screen Recording
   ☑ Microphone
   ☑ Accessibility (dla niektórych skrótów)
   ☑ System Events (dla interakcji z paskiem menu)

3. Całkowicie zrestartuj SeaMeet
   - Wymuś zamknięcie (Cmd+Q)
   - Uruchom ponownie

4. Przetestuj nagrywanie
   - Najpierw prosty test
   - Następnie spróbuj wykrywania spotkań

5. Dla dźwięku systemowego:
   - SeaMeet wykrywa dźwięk systemowy automatycznie
   - Lub użyj BlackHole (wirtualny sterownik audio) dla zaawansowanych konfiguracji
   - Lub użyj wbudowanego loopback na nowszym macOS
   - W razie potrzeby postępuj zgodnie z instrukcjami w aplikacji

Skróty specyficzne dla macOS

Skróty globalne:
• Cmd + Shift + R — Start/Stop nagrywania
• Cmd + Shift + F — Zapisz Flashback
• Cmd + Shift + S — Zrzut ekranu

Integracja macOS:
• Touch Bar: Przycisk Record (jeśli dostępny)
• Pasek menu: Szybkie kontrolki
• Notification Center: Status nagrywania

Część 5: Informacje specyficzne dla Linux

Charakterystyka Linux

1. Zmienne doświadczenie

Wersje Linux różnią się w zależności od dystrybucji:

Ubuntu (Zalecane):
• Najlepsze wsparcie
• Najłatwiejsza konfiguracja
• Większość funkcji działa
• Regularne testowanie

Fedora:
• Dobre wsparcie
• Nowsze pakiety
• Może wymagać dodatkowych repo

Inne dystrybucje:
• Twoje doświadczenie może się różnić
• Wsparcie społeczności
• Mogą wymagać ręcznych poprawek

2. Złożoność przechwytywania audio

Audio w Linux jest bardziej złożone:

Systemy audio:
• PulseAudio (najczęstszy)
• PipeWire (nowszy, nowoczesny)
• ALSA (niskopoziomowy)
• JACK (profesjonalny audio)

Wymagana konfiguracja:
Może być konieczne utworzenie wirtualnych urządzeń audio
Lub użycie modułów loopback
Nie "plug and play" jak Windows

Konfiguracja PulseAudio:

# Utwórz wirtualny sink dla dźwięku systemowego
pactl load-module module-null-sink sink_name=SeaMeet sink_properties=device.description=SeaMeetRecording

# Monitoruj go
pactl load-module module-loopback source=SeaMeet.monitor

3. Akceleracja sprzętowa różni się

NVIDIA na Linux:
• NVENC dostępne przez sterowniki własnościowe
• Trzeba instalować osobno
• Jakość dobra, gdy działa

AMD na Linux:
• Wsparcie VCE różni się w zależności od sterownika
• Sterowniki open-source vs własnościowe
• Może wymagać konfiguracji

Intel na Linux:
• VA-API do kodowania
• Zwykle działa dobrze
• Część sterowników Mesa

Przewodnik konfiguracji Linux

Instalacja Ubuntu:

# Pobierz pakiet .deb
# Lub zainstaluj przez repozytorium, jeśli dostępne

sudo dpkg -i seameet-linux.deb
sudo apt-get install -f  # Napraw zależności

# Przyznaj uprawnienia
# Dodaj użytkownika do grupy video
sudo usermod -a -G video $USER

# Wyloguj się i zaloguj ponownie

Instalacja Fedora:

# Pobierz pakiet .rpm
sudo rpm -i seameet-linux.rpm

# Lub przez dnf, jeśli w repo
sudo dnf install seameet

Konfiguracja po instalacji:

# 1. Konfiguracja audio (złożona)
# Postępuj zgodnie z przewodnikiem konfiguracji audio w SeaMeet

# 2. Akceleracja sprzętowa
# Zainstaluj odpowiednie sterowniki:
# NVIDIA: nvidia-utils lub własnościowe
# AMD: mesa-va-drivers
# Intel: intel-media-driver

# 3. Uprawnienia
# Może wymagać konfiguracji reguł udev
# Dla dostępu do urządzeń

Skróty specyficzne dla Linux

Skróty globalne:
• Ctrl + Alt + R — Start/Stop nagrywania
• Ctrl + Alt + F — Zapisz Flashback
• Ctrl + Alt + S — Zrzut ekranu

Uwaga: Mogą kolidować ze skrótami pulpitu
W razie potrzeby skonfiguruj w ustawieniach SeaMeet

Część 6: Rozwiązywanie problemów specyficzne dla platformy

Problemy specyficzne dla Windows

Problem: Nie można przechwycić dźwięku systemowego

Rozwiązania:

1. Włącz Stereo Mix:
   - Sound Control Panel → Recording
   - Pokaż wyłączone urządzenia
   - Włącz Stereo Mix

2. Użyj metody WASAPI:
   - Ustawienia SeaMeet → Audio → Method
   - Wybierz WASAPI loopback

3. Brak Stereo Mix na Realtek:
   - Zaktualizuj sterowniki Realtek
   - Lub użyj metody WASAPI

4. Specyficzne dla Windows 11:
   - Sprawdź ustawienia prywatności
   - Ustawienia → Privacy → Microphone
   - Upewnij się, że aplikacje mają dostęp do audio

Problem: Czarny ekran nagrywania gry

Rozwiązania:

1. Wyłącz optymalizację pełnoekranową:
   - Kliknij prawym na exe gry → Properties
   - Compatibility → Disable fullscreen optimizations

2. Użyj trybu okienkowego lub bez ramki

3. Wyłącz Windows Game Bar:
   - Może kolidować z SeaMeet

4. Uruchom SeaMeet jako administrator

5. Użyj trybu Game Capture, jeśli dostępny

Problemy specyficzne dla macOS

Problem: Brak dźwięku systemowego

Rozwiązania:

1. Przyznaj uprawnienia Screen Recording:
   System Preferences → Security & Privacy → Privacy → Screen Recording
   Zaznacz SeaMeet
   Zrestartuj SeaMeet

2. Zainstaluj BlackHole (wirtualne audio):
   brew install blackhole-2ch
   Lub pobierz z GitHub

3. Skonfiguruj urządzenie wielowyjściowe:
   Audio MIDI Setup → Create Multi-Output
   Dodaj głośniki + BlackHole
   Ustaw jako wyjście systemowe

4. Nowszy macOS (12+):
   Może mieć wbudowany loopback
   Sprawdź ustawienia SeaMeet

Problem: SeaMeet nie uruchamia się

Rozwiązania:

1. Sprawdź uprawnienia:
   - Screen Recording
   - Microphone
   - Accessibility
   - System Events

2. Kliknij prawym → Open:
   - Pierwszy raz może wymagać tego
   - Obejdź Gatekeeper

3. Sprawdź atrybut kwarantanny:
   xattr -d com.apple.quarantine /Applications/SeaMeet.app

4. Zweryfikuj wersję macOS:
   • Wymaga macOS 14.2 Sonoma lub nowszej
   • Sprawdź ikoną Apple → About This Mac
   • W razie potrzeby zaktualizuj

5. Całkowicie zrestartuj:
   - Wymuś zamknięcie: Cmd+Q
   - Całkowicie zabij aplikację
   - Uruchom ponownie

6. Zainstaluj SeaMeet ponownie
   - Usuń z Applications
   - Pobierz świeży DMG
   - Zainstaluj ponownie

Problem: Wykrywanie spotkań nie działa

Rozwiązania:

1. Zweryfikuj wersję macOS:
   • Wykrywanie spotkań wymaga macOS 14.2+
   • Sprawdź About This Mac
   • Zaktualizuj, jeśli na starszej wersji

2. Przyznaj niezbędne uprawnienia:
   System Preferences → Security & Privacy → Privacy
   ✓ Screen Recording
   ✓ Microphone
   Zrestartuj SeaMeet

3. Sprawdź platformę spotkań:
   • Upewnij się, że aplikacja spotkań ma dostęp do mikrofonu
   • System Preferences → Security & Privacy → Microphone
   • Dodaj aplikację spotkań, jeśli potrzeba (Zoom, Teams itp.)

4. Przetestuj wykrywanie okien:
   • Rozpocznij spotkanie w obsługiwanej aplikacji
   • Sprawdź, czy okno pojawia się w SeaMeet
   • Spróbuj najpierw wybrać okno ręcznie

5. Spotkania w przeglądarce:
   • Upewnij się, że karta przeglądarki ze spotkaniem jest aktywna
   • Przeglądarka musi mieć uprawnienia do nagrywania ekranu
   • Niektóre przeglądarki mogą wymagać dodatkowej konfiguracji

Problemy specyficzne dla Linux

Problem: Brak urządzeń audio

Rozwiązania:

1. Sprawdź system audio:
   - Czy PulseAudio działa?
   - Czy PipeWire?
   pactl info

2. Uprawnienia:
   - Dodaj użytkownika do grupy audio
   sudo usermod -a -G audio $USER

3. Zainstaluj pavucontrol:
   - PulseAudio Volume Control
   - Sprawdź urządzenia wejścia/wyjścia

4. SeaMeet może wymagać specyficznej konfiguracji:
   - Postępuj zgodnie z konfiguracją audio w aplikacji
   - Może wymagać urządzeń wirtualnych

Problem: Wysokie zużycie CPU

Rozwiązania:

1. Włącz akcelerację sprzętową:
   - Zainstaluj sterowniki VA-API
   - NVIDIA: Sprawdź wsparcie NVENC
   - AMD: Może być ograniczone

2. Użyj niższych ustawień jakości:
   - 720p zamiast 1080p
   - Niższa częstotliwość klatek

3. Sprawdź, czy nagrywasz na wolny dysk:
   - Użyj SSD, jeśli to możliwe
   - Sprawdź wydajność dysku

4. Środowisko graficzne:
   - Niektóre DE używają więcej zasobów
   - Wypróbuj lżejszy WM, jeśli potrzeba

Część 7: Wskazówki dla workflow międzyplatformowego

Przenoszenie się między platformami

Transfer ustawień:

Ustawienia SeaMeet są przechowywane lokalnie
Brak automatycznej synchronizacji w chmurze

Ręczny transfer:
1. Eksportuj ustawienia (jeśli funkcja dostępna)
2. Lub zapisz kluczowe ustawienia
3. Skonfiguruj ponownie na innej platformie
4. Spodziewaj się pewnych różnic

Kompatybilność plików:

Pliki nagrań są uniwersalne:
• MP4 działa na wszystkich platformach
• WebM działa na wszystkich platformach
• MOV działa na wszystkich platformach (z kodekami)

Brak konwersji potrzebnej przy zmianie komputerów

Skróty klawiszowe:

Windows/Linux: Ctrl + Alt + [klawisz]
Mac: Cmd + Shift + [klawisz]

Pamięć mięśniowa będzie wymagała dostosowania
Sprawdź skróty w ustawieniach na każdej platformie

Najlepsza platforma do konkretnych zastosowań

Do gier:

  • Windows (najlepsze wsparcie sprzętowe, najwięcej gier)

Do pracy kreatywnej:

  • macOS (integracja z aplikacjami kreatywnymi)

Do programowania/rozwoju:

  • Dowolna (osobiste preferencje)
  • Linux, jeśli wolisz open source

Do biznesu/przedsiębiorstwa:

  • Windows (najczęstszy, najłatwiejsze wsparcie IT)
  • macOS (rośnie w biznesie)

Do prywatności:

  • Linux (największa kontrola)

Podsumowanie

SeaMeet działa na wszystkich głównych platformach, ale każda ma swoje mocne strony:

✅ Windows: Najwięcej funkcji, najłatwiejsza konfiguracja, najlepszy gaming, kompleksowa kontrola audio

✅ macOS: Dopracowany, inteligentne wykrywanie spotkań, działa na Intel i Apple Silicon poprzez osobne zoptymalizowane DMG (nie uniwersalny binarny — wybierz pasujący do swojego chipa), doskonała wydajność

✅ Linux: Elastyczny, skupiony na prywatności, wspierany przez społeczność, instalacja tylko ze źródeł (brak prekompilowanego instalatora — czyste npm install od v2.1.4)

Rekomendacje platform:

Wybierz Windows, jeśli:

  • Chcesz maksymalną kompatybilność
  • Nagrywasz gry
  • Potrzebujesz łatwego przechwytywania dźwięku systemowego
  • Używasz GPU NVIDIA/AMD
  • Potrzebujesz maksymalnej kontroli funkcji

Wybierz macOS, jeśli:

  • Jesteś w ekosystemie Apple
  • Masz Mac Intel lub Apple Silicon (oba obsługiwane)
  • Chcesz dopracowanego natywnego doświadczenia
  • Wykonujesz pracę kreatywną
  • Chcesz automatycznego wykrywania spotkań i inteligentnego wyboru okien
  • Cenisz zintegrowane monitorowanie audio per aplikacja

Wybierz Linux, jeśli:

  • Jesteś techniczny
  • Cenisz open source
  • Chcesz maksymalnej kontroli
  • Nie przeszkadza Ci konfiguracja
  • Wolisz opcje wspierane przez społeczność

Zalety macOS w v1.0.5+:

✨ Nowe funkcje (macOS 14.2+):
• Monitorowanie mikrofonu per aplikacja (native-audio-node)
• Automatyczne wykrywanie spotkań
• Inteligentne pre-zaznaczanie okien
• Wykrywanie spotkań w przeglądarce
• Zapobieganie auto-startowi
• Osobne zoptymalizowane instalatory (Intel + Apple Silicon)
• Mniejsze rozmiary pobierania (~100 MB na architekturę)
