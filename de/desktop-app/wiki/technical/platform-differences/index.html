Plattform-Unterschiede

Kapitel 29: Plattform-Unterschiede

Einführung

SeaMeet funktioniert auf mehreren Plattformen – Windows, macOS und Linux –, aber jedes Betriebssystem hat seine eigenen Eigenheiten, Fähigkeiten und Einschränkungen. Was auf Windows perfekt funktioniert, kann sich auf Mac anders verhalten. Einige Funktionen sind auf einer Plattform verfügbar, aber nicht auf einer anderen. Das Verständnis dieser Unterschiede hilft Ihnen, das Beste aus SeaMeet herauszuholen, unabhängig davon, welchen Computer Sie verwenden.

Dieses Kapitel erklärt, wie sich SeaMeet an jede Plattform anpasst, welche Funktionen plattformspezifisch sind und welche Einschränkungen Sie kennen sollten.

Kapitelziele

Nach dem Lesen dieses Kapitels werden Sie in der Lage sein:

  • Unterschiede zwischen Windows-, macOS- und Linux-Versionen zu verstehen
  • Zu wissen, welche Funktionen plattformspezifisch sind
  • SeaMeet ordnungsgemäß für Ihr Betriebssystem zu konfigurieren
  • Plattformspezifische Einschränkungen zu umgehen
  • Die richtige Plattform für Ihre Aufnahmebedürfnisse zu wählen

Teil 1: Übersicht nach Plattform

SeaMeet auf Windows

Am besten für:

  • Maximale Kompatibilität
  • Spielaufnahmen
  • Geschäftsumgebungen
  • Funktionsreichste Version

Schlüsseleigenschaften:

  • Die meisten Funktionen verfügbar
  • Beste Hardware-Beschleunigungs-Unterstützung (NVIDIA/AMD/Intel)
  • Einfache Systemaudio-Erfassung
  • Breiteste App-Kompatibilität
  • Am meisten getestet und stabil

Unterstützte Windows-Versionen:

  • Windows 10 (Version 1809 und später)
  • Windows 11
  • Windows Server 2019/2022 (begrenzte Unterstützung)

Unterstützte Windows-Architekturen:

  • x64 (Intel/AMD 64-Bit): Volle Unterstützung, alle Funktionen verfügbar
  • ARM64 (Windows on ARM): Unterstützt, einige Audiofunktionen nicht verfügbar
    • Surface Pro X und ähnliche Geräte
    • Bildschirmaufnahme, Videoaufnahme, Mikrofonaufnahme vollständig unterstützt
    • Systemaudio-Erfassung und Audio-Geräteaufzählung nicht verfügbar (anmutige Degradation)
    • Siehe Windows ARM64-Abschnitt unten für Details

Nicht unterstützt:

  • Windows 7, 8, 8.1 (End of Life)
  • Windows XP/Vista (uralt)
  • 32-Bit-Windows (x86)

SeaMeet auf macOS

Am besten für:

  • Kreative Profis
  • Apple-Ökosystem-Benutzer
  • Saubere, konsistente Oberfläche
  • Integration mit Mac-Workflows

Schlüsseleigenschaften:

  • Polierte, native Mac-Oberfläche
  • Hervorragende Leistung auf Apple Silicon (M1/M2/M3)
  • Hervorragende Leistung auf Intel-Macs
  • Enge Systemintegration
  • Anderes Berechtigungsmodell
  • Pro-App-Mikrofonüberwachung
  • Browser-Meeting-Erkennung und Auto-Start-Verhinderung

Unterstützte macOS-Versionen:

  • macOS 14.2 Sonoma (Minimum - erforderlich für native-audio-node-Funktionen)
  • macOS 15 Sequoia
  • Zukünftige Versionen

Unterstützte macOS-Architekturen:

  • Apple Silicon (arm64): Volle Unterstützung, alle Funktionen einschließlich Pro-App-Audio-Erkennung
  • Intel (x64): Volle Unterstützung mit separatem Installer

Apple Silicon & Intel-Unterstützung:

  • Zwei separate DMG-Installer: einer für Intel, einer für Apple Silicon
  • Laden Sie die Version herunter, die zu Ihrem Mac-Prozessor passt
  • M1/M2/M3-Macs → Laden Sie die arm64-Version herunter
  • Intel-Macs → Laden Sie die x64-Version herunter
  • Beide Versionen haben identische Funktionen
  • Hardware-Beschleunigung über VideoToolbox (Apple Silicon) oder Quick Sync (Intel)
  • Pro-App-Mikrofonerkennung (native-audio-node)
  • Intelligente Fenster-Vorauswahl für Meeting-Anwendungen

SeaMeet auf Linux

Am besten für:

  • Technische Benutzer, die SeaMeet aus dem Quellcode ausführen
  • Entwickler, die zum Projekt beitragen
  • Datenschutzbewusste Benutzer
  • Open-Source-Befürworter

Schlüsseleigenschaften:

  • Von der Community unterstützt, nur aus dem Quellcode (kein offizieller vorgebauter Installer)
  • Variabler Funktionsumfang je nach Distribution
  • Mehr manuelle Konfiguration erforderlich
  • Kommandozeilenfreundlich
  • Weniger „funktioniert einfach"-Funktionen

Unterstützte Distributionen:

  • Ubuntu 20.04+ (beste Unterstützung)
  • Fedora 34+
  • Debian 11+
  • Andere Debian/Ubuntu-basierte Distros

Linux-Installationshinweise (v2.1.4+):

✅ npm install ist jetzt sauber auf Linux erfolgreich

Bis v2.1.4 schlug `npm install` auf Linux mit EBADPLATFORM fehl,
weil native-audio-node — ein nur für macOS/Windows verfügbares
natives Modul — in `dependencies` aufgeführt war. Ab v2.1.4 lebt es
in `optionalDependencies` zusammen mit den anderen plattformspezifischen
Audiopaketen (macos-audio-devices, native-sound-mixer, win-audio),
sodass npm sie auf Linux überspringt, anstatt abzubrechen.

Wenn Sie zuvor `npm ERR! EBADPLATFORM` getroffen haben:
1. Ziehen Sie v2.1.4 oder später
2. Löschen Sie node_modules und package-lock.json
3. Führen Sie npm install erneut aus — es sollte ohne Fehler abschließen

Einschränkungen:

  • Kein offizieller vorgebauter Installer – aus dem Quellcode über npm start ausführen
  • Pro-App-Mikrofonüberwachung und automatische Meeting-Erkennung sind nicht verfügbar (benötigen native-audio-node, das keine Linux-Binärdatei hat)
  • System-Tray-Verfügbarkeit hängt von der Desktop-Umgebung ab (siehe Tray-Abschnitt unten)
  • Hardware-Beschleunigung variiert je nach GPU/Treiber-Kombination
  • Mehr Einrichtung erforderlich für Systemaudio-Erfassung (PulseAudio / PipeWire-Loopback)

System-Tray und Lite-Modus nach Plattform

SeaMeet läuft im Hintergrund weiter, nachdem Sie das Hauptfenster geschlossen haben – der System-Tray (auf macOS Menüleiste genannt) ist die Art und Weise, wie Sie zurückkommen, den Aufnahmestatus ändern und sauber beenden. Electrons Tray-API ist plattformspezifisch, sodass das Verhalten variiert:

FähigkeitWindowsmacOSLinux
Tray-Symbol✅ tray.ico im Benachrichtigungsbereich✅ Vorlage icon.png in der Menüleiste (passt sich an Dunkel-/Hellmodus an)⚠️ Hängt von der Desktop-Umgebung ab
Aufnahmestatus-Symbol✅ Roter tray-recording.ico-Wechsel✅ Nicht-Vorlage roter icon-recording.png-Wechsel⚠️ Gleicher Wechsel, aber Rendering hängt von der DE ab
Persistente Tray-Position✅ Ja (GUID-gebunden, nur in paketierten Builds)✅ N/A (Menüleisten-Reihenfolge wird vom Benutzer gesteuert)❌ Nicht garantiert
Rechtsklick-Kontextmenü✅ Voll✅ Voll⚠️ Nur einige DEs
„Versteckt im Tray starten"✅ Unterstützt✅ Unterstützt⚠️ Best-Effort
Lite-Modus (kompakte Floater-UI)✅ Voll✅ Voll✅ Voll

Linux-Tray-Hinweise:

Der Electron-Tray funktioniert zuverlässig auf GNOME (mit der AppIndicator-Erweiterung), KDE Plasma, XFCE, Cinnamon und den meisten Ubuntu/Fedora-Standard-Desktops. Auf reinen Wayland-Sitzungen und einigen minimalen Window-Managern erscheint das Tray-Symbol möglicherweise gar nicht – die App läuft weiter, aber Sie müssen sie aus dem Terminal neu starten oder einen globalen Hotkey verwenden, um das Fenster zurückzubringen. Es gibt kein Linux-spezifisches Tray-Symbol-Asset; dasselbe .ico wird wie für Windows geladen.

Lite-Modus:

Lite-Modus (eingeführt in v2.x) ist ein renderer-seitiges kompaktes Layout – eine 560×80-Floater-Leiste mit den Aufnahmesteuerelementen, Wellenform und Schnellaktionen anstelle des vollständigen App-Fensters. Er wird durch die ui.appMode-Einstellung gesteuert ('full' oder 'lite') und wechselt zur Laufzeit über die Einstellungen. Der Lite-Modus funktioniert auf allen drei Plattformen identisch, da er keinen plattformspezifischen Code-Pfad hat.

Teil 3: Windows-spezifische Funktionen und Einrichtung

Windows-Vorteile

1. Systemaudio ist einfach

Unter Windows ist das Erfassen von Systemaudio unkompliziert:

Methode: Stereo-Mix (am zuverlässigsten)

Einrichtung:
1. Rechtsklick auf Lautsprechersymbol → Soundeinstellungen öffnen
2. Sound-Systemsteuerung → Aufnahme
3. Rechtsklick in leerem Bereich → Deaktivierte Geräte anzeigen
4. Rechtsklick auf „Stereo-Mix" → Aktivieren
5. Als Standard festlegen

SeaMeet kann jetzt Systemaudio direkt erfassen

Alternative Methoden:

  • WASAPI-Loopback (moderne Methode)
  • DirectSound-Erfassung
  • Virtuelle Audiokabel

2. Hardware-Beschleunigung in Hülle und Fülle

Windows hat die beste GPU-Encoder-Unterstützung:

NVIDIA-GPUs:

GTX 600-Serie und neuer:
• NVENC-Encoder dedizierter Chip
• Hervorragende Qualität
• Sehr effizient
• SeaMeet unterstützt automatisch

AMD-GPUs:

Radeon HD 7000-Serie und neuer:
• VCE (Video Coding Engine)
• Gute Qualität
• Effiziente Codierung
• Automatische Unterstützung

Intel integriert:

4. Generation Core und neuer:
• Quick Sync Video
• Überraschend gute Qualität
• Sehr energieeffizient
• Großartig für Laptops

3. Spielfunktionen

Windows-spezifische Spielintegration:

Spielmodus-Unterstützung:
• Windows-Spielmodus-API
• Auto-Erkennung bei Spielen
• Ressourcen optimieren
• Nur unter Windows verfügbar

Game Bar-Integration:
• Kann neben Xbox Game Bar funktionieren
• Keine Konflikte
• Separate Tastenkürzel

Windows-Einrichtungsanleitung

Optimale Konfiguration:

1. Stereo-Mix für Systemaudio aktivieren
2. GPU-Treiber aktualisieren:
   - NVIDIA: GeForce Experience
   - AMD: Radeon Software
   - Intel: Intel Driver Assistant

3. Hardware-Beschleunigung in SeaMeet aktivieren:
   Einstellungen → Video → Hardware-Beschleunigung verwenden

4. Energieplan für Aufnahme auf „Höchstleistung" einstellen

5. Windows-Spielmodus deaktivieren, falls Probleme:
   Einstellungen → Spielen → Spielmodus → Aus

Windows-spezifische Tastenkürzel

Globale Tastenkürzel (funktionieren überall):
• Strg + Alt + R — Aufnahme starten/stoppen
• Strg + Alt + F — Flashback speichern
• Strg + Alt + S — Screenshot

Fensterverwaltung:
• Win + G — Game bar (falls aktiviert)
• Win + Alt + R — Xbox Game Bar aufnehmen
   (funktioniert neben SeaMeet)

Windows ARM64-spezifische Informationen

Was ist Windows ARM64?

ARM64 ist eine andere Prozessorarchitektur:
• Verwendet in Windows on ARM-Geräten (Surface Pro X usw.)
• Native Unterstützung für ARM-basierte Prozessoren
• Kann x64-Apps emulieren (langsamer)
• Wachsende Unterstützung für native ARM64-Apps

SeaMeet auf ARM64

SeaMeet hat ab v1.0.2+ native ARM64-Unterstützung:

✅ Vollständig unterstützt auf ARM64:
• Bildschirmaufnahme (hohe Leistung)
• Videoaufnahme (hohe Leistung)
• Mikrofonaufnahme (direkte Windows-API)
• Fenstererkennung und -verwaltung
• Floater-Widget und Tastenkürzel
• Einstellungen und Aufnahmebibliothek
• Alle UI-Funktionen

❌ Nicht verfügbar auf ARM64:
• Systemaudio-Erfassung (Audio von Apps/Lautsprechern)
• Audio-Geräteaufzählung (Mikrofon-/Lautsprecher-Erkennung)
• Audio-Mixer-Steuerung
• Diese erfordern native Module, die nicht für ARM64 kompiliert sind

Funktionsvergleich: x64 vs. ARM64

Funktionx64ARM64Hinweise

Mikrofonaufnahme✅ Voll✅ VollWindows-API-basiert

Wann Sie ARM64 verwenden sollten

Am besten für:

  • Surface Pro X-Benutzer, die native Leistung wünschen
  • Aufnehmen von Video/Bildschirm ohne Systemaudio
  • Mikrofonaufnahme (direkte Aufnahme funktioniert)
  • Volle Leistung ohne Emulations-Verlangsamung

Nicht ideal für:

  • Systemaudio-Erfassung (wird nicht verfügbar sein)
  • Komplexe Audio-Workflows
  • Audio-Geräteauswahl (nicht verfügbar)

So wissen Sie, welche Version Sie haben

Windows-Einstellungen:
1. Einstellungen → System → Info
2. Suchen Sie nach „Systemtyp"
3. Zeigt entweder:
   • „x64-basierter Prozessor" (64-Bit Intel/AMD)
   • „ARM-basierter Prozessor" (Windows on ARM)

Kommandozeile:

PowerShell: wmic os get osarchitecture
Ausgabe: 64-Bit oder ARM 64-Bit

Installation

SeaMeet erkennt Ihre Architektur automatisch:

• Generischen Installer herunterladen
• Er installiert automatisch die richtige Version
• x64-Benutzer erhalten: SeaMeet-...-x64-Setup.exe
• ARM64-Benutzer erhalten: SeaMeet-...-arm64-Setup.exe

Oder manuell die richtige aus den Releases herunterladen:
• Prüfen Sie Ihren Systemtyp (oben)
• Übereinstimmende Architektur herunterladen

Auto-Updater auf ARM64

Nahtlose Updates:
• App prüft automatisch auf Updates
• ARM64 aktualisiert auf ARM64 (nicht x64)
• Abwärtskompatibel mit früheren Versionen
• Keine manuelle Intervention erforderlich

ARM64-Probleme beheben

Problem: „Systemaudio"-Option ausgegraut

Erwartetes Verhalten auf ARM64:
✓ Dies ist normal
✓ Natives Modul nicht verfügbar
✓ Kann immer noch Mikrofon aufnehmen
✓ Kein Fehler - anmutige Degradation

Problem: Kann kein Mikrofon/Lautsprecher auswählen

Lösungen:
1. Standard-Systemgeräte verwenden
2. Zu Windows-Soundeinstellungen gehen, um Gerät auszuwählen
3. SeaMeet verwendet, was Windows ausgewählt hat
4. Manuelle Geräteauswahl auf ARM64 nicht verfügbar

Problem: Aufnahme des Mikrofons funktioniert nicht

Lösungen:
1. Windows-Soundeinstellungen prüfen
2. Mikrofon sollte das Standardeingabegerät sein
3. SeaMeet Mikrofonberechtigungen erteilen
4. Windows sollte Aufnahmepegel anzeigen
5. Zuerst in Windows-Aufnahme-App testen

Teil 4: macOS-spezifische Funktionen und Einrichtung

macOS-Vorteile

1. Polierte Oberfläche

SeaMeet auf Mac fühlt sich nativ an:

• Folgt macOS-Designrichtlinien
• Verwendet native Steuerelemente
• Respektiert System-Theme
• Touch Bar-Unterstützung (auf kompatiblen Macs)
• Ordnungsgemäße Menüleisten-Integration

2. Hervorragende Apple Silicon-Unterstützung

M1/M2/M3-Chips funktionieren großartig:

Apple Silicon-Funktionen:
• Hardware-Beschleunigung über VideoToolbox
• Hervorragende Leistung pro Watt
• Schnelle Codierung
• Kühler Betrieb
• Lange Akkulaufzeit beim Aufnehmen

3. Systemintegration

macOS-Integration:
• iCloud Drive-Unterstützung
• Time Machine-kompatibel
• Handoff/Continuity-bereit
• Ordnungsgemäßes Sandboxing
• Sicherheitsbezogene Lesezeichen

macOS-Einschränkungen

1. Systemaudio erfordert Berechtigung

Im Gegensatz zu Windows benötigt macOS explizite Berechtigung:

Einrichtungsschritte:

1. Beim ersten Aufnehmen von Systemaudio:
   Systemeinstellungen → Sicherheit & Datenschutz → Datenschutz
   
2. Klicken Sie auf „Bildschirmaufnahme" links

3. Aktivieren Sie „SeaMeet" in der Liste
   (Möglicherweise müssen Sie mit Ihrem Passwort entsperren)

4. SeaMeet vollständig neu starten

5. Systemaudio funktioniert jetzt

Warum dies erforderlich ist:

  • macOS-Sicherheitsmodell
  • Bildschirmaufnahme erfasst alles
  • Benutzer muss explizit erlauben
  • Schützt vor Spyware

2. Keine NVIDIA/AMD-Hardware-Beschleunigung

Mac-Hardware-Beschleunigung:
• Intel-Macs: Intel Quick Sync (falls verfügbar)
• Apple Silicon: VideoToolbox (hervorragend)
• Externe GPUs: Nicht für Codierung unterstützt
• Kein NVENC oder AMD VCE (Chips nicht vorhanden)

Leistung:

  • Apple Silicon ist so effizient, dass es keine Rolle spielt
  • Intel-Macs mit Quick Sync sind in Ordnung
  • Ältere Intel-Macs ohne Quick Sync verwenden CPU-Codierung

3. Sandboxing-Einschränkungen

macOS-Sicherheit:
• Apps sind sandboxed
• Müssen Berechtigung anfordern für:
  - Mikrofon
  - Kamera (falls verwendet)
  - Bildschirmaufnahme
  - Dateisystem-Standorte
  - Downloads-Ordner
  - Desktop

SeaMeet fordert diese bei Bedarf an

macOS-architekturspezifische Installer

SeaMeet auf macOS bietet separate Installer für Intel- und Apple Silicon-Macs:

Welche Version sollte ich herunterladen?

Mac-Typ prüfen:
Apple-Menü (🍎) → Über diesen Mac → Chip

Wenn Sie sehen:
• „Apple M1", „Apple M2" oder „Apple M3"
  → Herunterladen: SeaMeet-macOS-arm64-[version].dmg

• „Intel Core i5", „Intel Core i7" usw.
  → Herunterladen: SeaMeet-macOS-x64-[version].dmg

Warum separate Installer?

✅ Kleinere Downloadgröße (~100 MB jeweils vs. ~180 MB universal)
✅ Optimiert für Ihren spezifischen Prozessor
✅ Keine Kompatibilitätsprobleme mit nativen Modulen
✅ Einfacherer Build- und Update-Prozess

Leistung:

Apple Silicon (arm64):
• M1, M2, M3-Chips
• Hervorragende Leistung
• Bessere Akkulaufzeit
• Native arm64-Ausführung

Intel (x64):
• 2013-2021 Macs
• Volle Funktionsparität
• Quick Sync-Beschleunigung
• Native x64-Ausführung

Installation:

1. Korrekten DMG für Ihren Mac herunterladen
2. DMG-Datei öffnen

SeaMeet auf macOS enthält erweiterte Meeting-Erkennung mit Pro-App-Audio-Überwachung:

Pro-App-Mikrofonüberwachung:

Wie es funktioniert:
• Überwacht, welche App Ihr Mikrofon verwendet
• Erkennt, wann Meetings beginnen/enden
• Verwendet native-audio-node für Pro-App-Erkennung
• Verfügbar auf macOS 14.2+ (Sonoma)

Unterstützte Plattformen:
• Zoom
• Google Meet
• Microsoft Teams
• Apple FaceTime
• Webex

• Teams Web

Fenster-Vorauswahl:
• Wählt automatisch das Meeting-Fenster aus
• Verhindert versehentliche Aufnahmen anderer Apps
• Kein Auto-Start, es sei denn explizit aktiviert
• Benutzerkontrolle beibehalten

Anforderungen:

macOS 14.2 Sonoma oder später
• Erforderlich für native-audio-node-APIs
• Deckt alle modernen Mac-Benutzer ab
• Aktiviert Pro-App-Audio-Erkennung

Teil 5: Linux-spezifische Informationen

Linux-Eigenschaften

1. Variable Erfahrung

Linux-Versionen variieren je nach Distribution:

Ubuntu (Empfohlen):
• Beste Unterstützung
• Einfachste Einrichtung
• Die meisten Funktionen funktionieren
• Regelmäßige Tests

Fedora:
• Gute Unterstützung
• Neuere Pakete
• Kann zusätzliche Repos benötigen

Andere Distros:
• Ihre Erfahrungen können variieren
• Community-Support
• Kann manuelle Korrekturen benötigen

2. Komplexität der Audio-Erfassung

Linux-Audio ist komplexer:

Audio-Systeme:
• PulseAudio (am häufigsten)
• PipeWire (neuer, modern)
• ALSA (niedrige Ebene)
• JACK (professionelles Audio)

Einrichtung erforderlich:
Möglicherweise virtuelle Audiogeräte erstellen
Oder Loopback-Module verwenden
Nicht „Plug and Play" wie Windows

PulseAudio-Einrichtung:

# Virtuelle Senke für Systemaudio erstellen
pactl load-module module-null-sink sink_name=SeaMeet sink_properties=device.description=SeaMeetRecording

# Überwachen
pactl load-module module-loopback source=SeaMeet.monitor

3. Hardware-Beschleunigung variiert

NVIDIA auf Linux:
• NVENC verfügbar über proprietäre Treiber
• Muss separat installiert werden
• Qualität gut, wenn funktioniert

AMD auf Linux:
• VCE-Unterstützung variiert je nach Treiber
• Open-Source vs. proprietäre Treiber
• Kann Konfiguration benötigen

Intel auf Linux:
• VA-API für Codierung
• Funktioniert normalerweise gut
• Teil der Mesa-Treiber

Linux-Einrichtungsanleitung

Ubuntu-Installation:

# .deb-Paket herunterladen
# Oder über Repository installieren, falls verfügbar

sudo dpkg -i seameet-linux.deb
sudo apt-get install -f  # Abhängigkeiten beheben

sudo usermod -a -G video $USER

# Aus- und wieder anmelden

Fedora-Installation:

# .rpm-Paket herunterladen
sudo rpm -i seameet-linux.rpm

# Oder über dnf, falls in Repos

# NVIDIA: nvidia-utils oder proprietär
# AMD: mesa-va-drivers
# Intel: intel-media-driver

# 3. Berechtigungen
# Möglicherweise udev-Regeln konfigurieren
# Für Gerätezugriff

Teil 6: Plattformspezifische Fehlerbehebung

Windows-spezifische Probleme

Problem: Systemaudio kann nicht erfasst werden

Lösungen:

1. Stereo-Mix aktivieren:
   - Sound-Systemsteuerung → Aufnahme
   - Deaktivierte Geräte anzeigen
   - Stereo-Mix aktivieren

2. WASAPI-Methode verwenden:
   - SeaMeet-Einstellungen → Audio → Methode
   - WASAPI-Loopback auswählen

3. Kein Stereo-Mix auf Realtek:
   - Realtek-Treiber aktualisieren
   - Oder stattdessen WASAPI-Methode verwenden

4. Windows 11-spezifisch:
   - Datenschutzeinstellungen prüfen
   - Einstellungen → Datenschutz → Mikrofon
   - Sicherstellen, dass Apps auf Audio zugreifen können

Problem: Schwarzer Bildschirm bei Spielaufnahme

Lösungen:

1. Vollbildoptimierung deaktivieren:
   - Rechtsklick auf Spiel-exe → Eigenschaften
   - Kompatibilität → Vollbildoptimierung deaktivieren

2. Fenster- oder randlosen Modus verwenden

3. Windows Game Bar deaktivieren:
   - Kann mit SeaMeet kollidieren

4. SeaMeet als Administrator ausführen

5. Spielaufnahmemodus verwenden, falls verfügbar

macOS-spezifische Probleme

Problem: Kein Systemaudio

Lösungen:

1. Bildschirmaufnahme-Berechtigung erteilen:
   Systemeinstellungen → Sicherheit & Datenschutz → Datenschutz → Bildschirmaufnahme
   SeaMeet aktivieren
   SeaMeet neu starten

2. BlackHole (virtuelles Audio) installieren:
   brew install blackhole-2ch
   Oder von GitHub herunterladen

3. Multi-Output-Gerät einrichten:
   Audio-MIDI-Setup → Multi-Output erstellen
   Lautsprecher + BlackHole hinzufügen
   Als Systemausgabe einstellen

4. Neueres macOS (12+):
   Kann eingebauten Loopback haben
   SeaMeet-Einstellungen prüfen

Problem: SeaMeet startet nicht

Lösungen:

1. Berechtigungen prüfen:
   - Bildschirmaufnahme
   - Mikrofon
   - Bedienungshilfen
   - Systemereignisse

2. Rechtsklick → Öffnen:
   - Beim ersten Mal könnte dies nötig sein
   - Gatekeeper umgehen

3. Auf Quarantäne-Attribut prüfen:
   xattr -d com.apple.quarantine /Applications/SeaMeet.app

4. macOS-Version überprüfen:
   • Erfordert macOS 14.2 Sonoma oder später
   • Mit Apple-Symbol → Über diesen Mac prüfen
   • Bei Bedarf aktualisieren

5. Vollständig neu starten:
   - Beenden erzwingen: Cmd+Q
   - App vollständig beenden
   - Neu starten

6. SeaMeet neu installieren
   - Aus Anwendungen entfernen
   - Frischen DMG herunterladen
   - Neu installieren

Problem: Meeting-Erkennung funktioniert nicht

Lösungen:

1. macOS-Version überprüfen:
   • Meeting-Erkennung erfordert macOS 14.2+
   • Über diesen Mac prüfen
   • Aktualisieren, wenn auf älterer Version

2. Erforderliche Berechtigungen erteilen:
   Systemeinstellungen → Sicherheit & Datenschutz → Datenschutz
   ✓ Bildschirmaufnahme
   ✓ Mikrofon
   SeaMeet neu starten

3. Meeting-Plattform prüfen:
   • Stellen Sie sicher, dass die Meeting-App Mikrofonzugriff hat
   • Systemeinstellungen → Sicherheit & Datenschutz → Mikrofon
   • Meeting-App bei Bedarf hinzufügen (Zoom, Teams usw.)

4. Fenstererkennung testen:
   • Meeting in unterstützter App starten
   • Prüfen, ob Fenster in SeaMeet erscheint
   • Fenster zuerst manuell auswählen versuchen

5. Browser-Meetings:
   • Sicherstellen, dass Meeting-Browser-Tab aktiv ist
   • Browser muss Bildschirmaufnahme-Berechtigung haben
   • Einige Browser können zusätzliche Einrichtung benötigen

Linux-spezifische Probleme

Problem: Keine Audiogeräte angezeigt

Lösungen:

1. Audio-System prüfen:
   - Läuft PulseAudio?
   - Oder PipeWire?
   pactl info

2. Berechtigungen:
   - Benutzer zur Audio-Gruppe hinzufügen
   sudo usermod -a -G audio $USER

3. pavucontrol installieren:
   - PulseAudio Volume Control
   - Eingangs-/Ausgangsgeräte prüfen

4. SeaMeet braucht möglicherweise spezifische Einrichtung:
   - In-App-Audio-Konfiguration befolgen
   - Möglicherweise virtuelle Geräte benötigt

Problem: Hohe CPU-Auslastung

Lösungen:

1. Hardware-Beschleunigung aktivieren:
   - VA-API-Treiber installieren
   - NVIDIA: NVENC-Unterstützung prüfen
   - AMD: Kann begrenzt sein

2. Niedrigere Qualitätseinstellungen verwenden:
   - 720p statt 1080p
   - Niedrigere Bildrate

3. Prüfen, ob Aufnahme auf langsame Festplatte:
   - SSD verwenden, wenn möglich
   - Festplattenleistung prüfen

4. Desktop-Umgebung:
   - Einige DEs verwenden mehr Ressourcen
   - Bei Bedarf leichteren WM versuchen

Teil 7: Plattformübergreifende Workflow-Tipps

Zwischen Plattformen wechseln

Einstellungen-Übertragung:

SeaMeet-Einstellungen werden lokal gespeichert
Nicht automatisch in der Cloud synchronisiert

Manuelle Übertragung:
1. Einstellungen exportieren (falls Funktion verfügbar)
2. Oder Schlüsseleinstellungen notieren
3. Auf anderer Plattform neu konfigurieren
4. Einige Unterschiede erwarten

Dateikompatibilität:

Aufnahmedateien sind universal:
• MP4 funktioniert auf allen Plattformen
• WebM funktioniert auf allen Plattformen
• MOV funktioniert auf allen Plattformen (mit Codecs)

Keine Konvertierung beim Wechseln von Computern erforderlich

Tastenkürzel:

Windows/Linux: Strg + Alt + [Taste]
Mac: Cmd + Shift + [Taste]

Muskelgedächtnis braucht Anpassung
Tastenkürzel in den Einstellungen auf jeder Plattform prüfen

Beste Plattform für bestimmte Nutzungen

Für Spiele:

  • Windows (beste Hardware-Unterstützung, die meisten Spiele)

Für kreative Arbeit:

  • macOS (Integration mit kreativen Apps)

Für Programmierung/Entwicklung:

  • Beliebig (persönliche Präferenz)
  • Linux, wenn Sie Open Source bevorzugen

Für Geschäft/Unternehmen:

  • Windows (am häufigsten, einfachster IT-Support)
  • macOS (wächst im Geschäftsleben)

Für Datenschutz:

  • Linux (die meiste Kontrolle)

Zusammenfassung

SeaMeet funktioniert auf allen wichtigen Plattformen, aber jede hat Stärken:

✅ Windows: Die meisten Funktionen, einfachste Einrichtung, beste Spiele, umfassende Audiosteuerung

✅ macOS: Poliert, intelligente Meeting-Erkennung, funktioniert auf Intel & Apple Silicon über separate optimierte DMGs (kein universelles Binary – wählen Sie den, der zu Ihrem Chip passt), hervorragende Leistung

✅ Linux: Flexibel, datenschutzorientiert, von der Community unterstützt, nur Quellcode-Installation (kein vorgebauter Installer – sauberes npm install ab v2.1.4)

Plattform-Empfehlungen:

Wählen Sie Windows, wenn:

  • Sie maximale Kompatibilität möchten
  • Sie Spiele aufnehmen
  • Sie einfache Systemaudio-Erfassung benötigen
  • Sie NVIDIA/AMD-GPUs verwenden
  • Sie maximale Funktionssteuerung benötigen

Wählen Sie macOS, wenn:

  • Sie im Apple-Ökosystem sind
  • Sie einen Intel- oder Apple Silicon-Mac haben (beide unterstützt)
  • Sie eine polierte native Erfahrung möchten
  • Sie kreative Arbeit machen
  • Sie automatische Meeting-Erkennung und intelligente Fensterauswahl möchten
  • Sie integrierte Pro-App-Audioüberwachung schätzen

Wählen Sie Linux, wenn:

  • Sie technisch versiert sind
  • Sie Open Source schätzen
  • Sie maximale Kontrolle möchten
  • Sie sich nicht an Konfiguration stören
  • Sie von der Community unterstützte Optionen bevorzugen

macOS-Vorteile in v1.0.5+:

✨ Neue Funktionen (macOS 14.2+):
• Pro-App-Mikrofonüberwachung (native-audio-node)
• Automatische Meeting-Erkennung
• Intelligente Fenster-Vorauswahl
• Browser-Meeting-Erkennung
• Auto-Start-Verhinderung
• Separate optimierte Installer (Intel + Apple Silicon)
• Kleinere Downloadgrößen (~100 MB pro Architektur)
