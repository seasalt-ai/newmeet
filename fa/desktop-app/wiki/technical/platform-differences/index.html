تفاوت‌های پلتفرم

فصل 29: تفاوت‌های پلتفرم

مقدمه

SeaMeet روی چندین پلتفرم کار می‌کند — Windows، macOS و Linux — اما هر سیستم‌عامل ویژگی‌ها، قابلیت‌ها و محدودیت‌های خاص خود را دارد. آنچه در Windows کاملاً کار می‌کند ممکن است در Mac متفاوت رفتار کند. برخی ویژگی‌ها در یک پلتفرم در دسترس هستند اما در دیگری نه. درک این تفاوت‌ها به شما کمک می‌کند بدون توجه به کامپیوتری که استفاده می‌کنید، بیشترین استفاده را از SeaMeet ببرید.

این فصل توضیح می‌دهد چگونه SeaMeet با هر پلتفرم سازگار می‌شود، چه ویژگی‌هایی مخصوص پلتفرم هستند و چه محدودیت‌هایی باید بدانید.

اهداف فصل

پس از خواندن این فصل، قادر خواهید بود:

  • تفاوت‌های بین نسخه‌های Windows، macOS و Linux را درک کنید
  • بدانید کدام ویژگی‌ها مخصوص پلتفرم هستند
  • SeaMeet را به درستی برای سیستم‌عامل خود پیکربندی کنید
  • محدودیت‌های خاص پلتفرم را دور بزنید
  • پلتفرم مناسب را برای نیازهای ضبط خود انتخاب کنید

بخش 1: نمای کلی بر اساس پلتفرم

SeaMeet در Windows

بهترین برای:

  • حداکثر سازگاری
  • ضبط بازی
  • محیط‌های تجاری
  • نسخه با کامل‌ترین ویژگی‌ها

ویژگی‌های کلیدی:

  • بیشترین ویژگی‌ها در دسترس
  • بهترین پشتیبانی از شتاب سخت‌افزاری (NVIDIA/AMD/Intel)
  • ضبط صدای سیستم آسان
  • وسیع‌ترین سازگاری برنامه
  • بیشترین آزمایش‌شده و پایدار

نسخه‌های Windows پشتیبانی‌شده:

  • Windows 10 (نسخه 1809 و بالاتر)
  • Windows 11
  • Windows Server 2019/2022 (پشتیبانی محدود)

معماری‌های Windows پشتیبانی‌شده:

  • x64 (Intel/AMD 64-bit): پشتیبانی کامل، تمام ویژگی‌ها در دسترس
  • ARM64 (Windows on ARM): پشتیبانی می‌شود، برخی ویژگی‌های صوتی در دسترس نیست
    • Surface Pro X و دستگاه‌های مشابه
    • ضبط صفحه، ضبط ویدیو، ضبط میکروفون به طور کامل پشتیبانی می‌شود
    • ضبط صدای سیستم و شمارش دستگاه صوتی در دسترس نیست (تخریب تدریجی)
    • برای جزئیات به بخش Windows ARM64 در زیر مراجعه کنید

پشتیبانی نمی‌شود:

  • Windows 7، 8، 8.1 (پایان عمر)
  • Windows XP/Vista (باستانی)
  • Windows 32-bit (x86)

SeaMeet در macOS

بهترین برای:

  • حرفه‌ای‌های خلاق
  • کاربران اکوسیستم Apple
  • رابط تمیز و سازگار
  • ادغام با گردش‌کار Mac

ویژگی‌های کلیدی:

  • رابط Mac بومی پرداخت‌شده
  • عملکرد عالی روی Apple Silicon (M1/M2/M3)
  • عملکرد عالی روی Intel Macs
  • ادغام سیستم محکم
  • مدل مجوز متفاوت
  • نظارت میکروفون به ازای هر برنامه
  • تشخیص جلسه مرورگر و جلوگیری از شروع خودکار

نسخه‌های macOS پشتیبانی‌شده:

  • macOS 14.2 Sonoma (حداقل - برای ویژگی‌های native-audio-node لازم است)
  • macOS 15 Sequoia
  • نسخه‌های آینده

معماری‌های macOS پشتیبانی‌شده:

  • Apple Silicon (arm64): پشتیبانی کامل، تمام ویژگی‌ها شامل تشخیص صدای به ازای هر برنامه
  • Intel (x64): پشتیبانی کامل با نصب‌کننده جداگانه

پشتیبانی Apple Silicon و Intel:

  • دو نصب‌کننده DMG جداگانه: یکی برای Intel، یکی برای Apple Silicon
  • نسخه‌ای را دانلود کنید که با پردازنده Mac شما مطابقت دارد
  • Macهای M1/M2/M3 → نسخه arm64 را دانلود کنید
  • Macهای Intel → نسخه x64 را دانلود کنید
  • هر دو نسخه ویژگی‌های یکسان دارند
  • شتاب سخت‌افزاری از طریق VideoToolbox (Apple Silicon) یا Quick Sync (Intel)
  • تشخیص میکروفون به ازای هر برنامه (native-audio-node)
  • پیش‌انتخاب هوشمند پنجره برای برنامه‌های جلسه

SeaMeet در Linux

بهترین برای:

  • کاربران فنی که SeaMeet را از منبع اجرا می‌کنند
  • توسعه‌دهندگان مشارکت‌کننده در پروژه
  • کاربران آگاه به حریم خصوصی
  • حامیان منبع باز

ویژگی‌های کلیدی:

  • پشتیبانی‌شده توسط جامعه، فقط منبع (بدون نصب‌کننده رسمی از پیش ساخته)
  • مجموعه ویژگی‌های متغیر بر اساس توزیع
  • نیاز به پیکربندی دستی بیشتر
  • دوستدار خط فرمان
  • ویژگی‌های کمتر "فقط کار می‌کند"

توزیع‌های پشتیبانی‌شده:

  • Ubuntu 20.04+ (بهترین پشتیبانی)
  • Fedora 34+
  • Debian 11+
  • سایر توزیع‌های مبتنی بر Debian/Ubuntu

یادداشت‌های نصب Linux (v2.1.4+):

✅ npm install اکنون به طور تمیز در Linux موفق می‌شود

تا v2.1.4، `npm install` در Linux با EBADPLATFORM شکست می‌خورد
زیرا native-audio-node — یک ماژول بومی فقط برای macOS/Windows —
در `dependencies` فهرست شده بود. از v2.1.4 در
`optionalDependencies` در کنار سایر بسته‌های صوتی خاص پلتفرم
(macos-audio-devices، native-sound-mixer، win-audio) قرار دارد، بنابراین
npm به جای متوقف شدن، آنها را در Linux رد می‌کند.

اگر قبلاً به `npm ERR! EBADPLATFORM` برخورد کرده‌اید:
1. v2.1.4 یا بعد از آن را بکشید
2. node_modules و package-lock.json را حذف کنید
3. npm install را دوباره اجرا کنید — باید بدون خطا کامل شود

محدودیت‌ها:

  • بدون نصب‌کننده رسمی از پیش ساخته — از منبع از طریق npm start اجرا کنید
  • نظارت میکروفون به ازای هر برنامه و تشخیص خودکار جلسه در دسترس نیستند (به native-audio-node نیاز دارند که برای Linux باینری ندارد)
  • در دسترس بودن System Tray به محیط دسکتاپ بستگی دارد (به بخش Tray در زیر مراجعه کنید)
  • شتاب سخت‌افزاری بر اساس ترکیب GPU/درایور متفاوت است
  • راه‌اندازی بیشتر برای ضبط صدای سیستم لازم است (PulseAudio / PipeWire loopback)

System Tray و حالت Lite بر اساس پلتفرم

SeaMeet پس از بستن پنجره اصلی در پس‌زمینه اجرا می‌شود — system tray (که در macOS نوار منو نامیده می‌شود) نحوه بازگشت به آن، تغییر وضعیت ضبط و خروج تمیز است. API Tray Electron مخصوص پلتفرم است، بنابراین رفتار متفاوت است:

یادداشت‌های Tray در Linux:

tray در Electron به طور قابل اعتماد در GNOME (با افزونه AppIndicator)، KDE Plasma، XFCE، Cinnamon و بیشتر دسکتاپ‌های پیش‌فرض Ubuntu/Fedora کار می‌کند. در جلسات فقط Wayland و برخی پنجره‌مدیران حداقلی، آیکون tray ممکن است اصلاً ظاهر نشود — برنامه همچنان اجرا می‌شود، اما باید آن را از ترمینال راه‌اندازی مجدد کنید یا از یک hotkey سراسری برای برگرداندن پنجره استفاده کنید. هیچ دارایی آیکون tray مخصوص Linux وجود ندارد؛ همان .ico که برای Windows بارگذاری می‌شود.

حالت Lite:

حالت Lite (معرفی شده در v2.x) یک چیدمان فشرده سمت renderer است — یک نوار floater 560×80 با کنترل‌های ضبط، شکل موج و اقدامات سریع به جای پنجره کامل برنامه. توسط تنظیم ui.appMode ('full' یا 'lite') کنترل می‌شود و در زمان اجرا از طریق تنظیمات سوئیچ می‌کند. حالت Lite در تمام سه پلتفرم به طور یکسان کار می‌کند زیرا هیچ مسیر کد خاص پلتفرم ندارد.

بخش 3: ویژگی‌ها و راه‌اندازی خاص Windows

مزایای Windows

1. صدای سیستم آسان است

در Windows، ضبط صدای سیستم مستقیم است:

روش: Stereo Mix (قابل اعتمادترین)

راه‌اندازی:
1. روی آیکون بلندگو کلیک راست کنید → باز کردن تنظیمات صدا
2. کنترل پنل صدا → ضبط
3. در یک ناحیه خالی کلیک راست کنید → نمایش دستگاه‌های غیرفعال
4. روی "Stereo Mix" کلیک راست کنید → فعال کنید
5. به عنوان پیش‌فرض تنظیم کنید

SeaMeet اکنون می‌تواند صدای سیستم را مستقیماً ضبط کند

روش‌های جایگزین:

  • WASAPI loopback (روش مدرن)
  • ضبط DirectSound
  • کابل‌های صدای مجازی

2. شتاب سخت‌افزاری فراوان

Windows بهترین پشتیبانی encoder GPU را دارد:

NVIDIA GPUها:

سری GTX 600 و جدیدتر:
• تراشه اختصاصی encoder NVENC
• کیفیت عالی
• بسیار کارآمد
• SeaMeet به طور خودکار پشتیبانی می‌کند

AMD GPUها:

سری Radeon HD 7000 و جدیدتر:
• VCE (Video Coding Engine)
• کیفیت خوب
• کدگذاری کارآمد
• پشتیبانی خودکار

Intel Integrated:

نسل 4 Core و جدیدتر:
• Quick Sync Video
• کیفیت خوب به طور شگفت‌انگیز
• بسیار صرفه‌جوی انرژی
• عالی برای لپ‌تاپ‌ها

3. ویژگی‌های بازی

ادغام بازی خاص Windows:

پشتیبانی Game Mode:
• Windows Game Mode API
• تشخیص خودکار هنگام بازی
• بهینه‌سازی منابع
• فقط در Windows در دسترس

ادغام Game Bar:
• می‌تواند در کنار Xbox Game Bar کار کند
• بدون تعارض
• میانبرهای جداگانه

راهنمای راه‌اندازی Windows

پیکربندی بهینه:

1. Stereo Mix را برای صدای سیستم فعال کنید
2. درایورهای GPU را به‌روز کنید:
   - NVIDIA: GeForce Experience
   - AMD: Radeon Software
   - Intel: Intel Driver Assistant

3. شتاب سخت‌افزاری را در SeaMeet فعال کنید:
   تنظیمات → ویدیو → استفاده از شتاب سخت‌افزاری

4. طرح برق را روی "High Performance" برای ضبط تنظیم کنید

5. Windows Game Mode را در صورت ایجاد مشکل غیرفعال کنید:
   تنظیمات → بازی → Game Mode → خاموش

میانبرهای خاص Windows

میانبرهای سراسری (همه جا کار می‌کنند):
• Ctrl + Alt + R — شروع/توقف ضبط
• Ctrl + Alt + F — ذخیره Flashback

اطلاعات خاص Windows ARM64

Windows ARM64 چیست؟

ARM64 یک معماری پردازنده متفاوت است:
• در دستگاه‌های Windows on ARM (Surface Pro X و غیره) استفاده می‌شود
• پشتیبانی بومی برای پردازنده‌های مبتنی بر ARM
• می‌تواند برنامه‌های x64 را شبیه‌سازی کند (کندتر)
• پشتیبانی روزافزون برای برنامه‌های ARM64 بومی

SeaMeet در ARM64

SeaMeet از v1.0.2+ پشتیبانی ARM64 بومی دارد:

✅ به طور کامل در ARM64 پشتیبانی می‌شود:
• ضبط صفحه (عملکرد بالا)
• ضبط ویدیو (عملکرد بالا)
• ضبط میکروفون (API مستقیم Windows)
• تشخیص و مدیریت پنجره
• Floater widget و میانبرهای صفحه‌کلید
• تنظیمات و کتابخانه ضبط
• تمام ویژگی‌های UI

❌ در ARM64 در دسترس نیست:
• ضبط صدای سیستم (صدا از برنامه‌ها/بلندگوها)
• شمارش دستگاه صوتی (تشخیص میکروفون/بلندگو)
• کنترل میکسر صدا
• این‌ها به ماژول‌های بومی نیاز دارند که برای ARM64 کامپایل نشده‌اند

مقایسه ویژگی‌ها: x64 در مقابل ARM64

محدودیت‌های macOS

1. صدای سیستم به مجوز نیاز دارد

برخلاف Windows، macOS به مجوز صریح نیاز دارد:

مراحل راه‌اندازی:

1. اولین بار ضبط صدای سیستم:
   تنظیمات سیستم → امنیت و حریم خصوصی → حریم خصوصی
   
2. روی "Screen Recording" در سمت چپ کلیک کنید

3. "SeaMeet" را در لیست تیک بزنید
   (ممکن است نیاز داشته باشید با رمز عبور خود قفل را باز کنید)

4. SeaMeet را به طور کامل راه‌اندازی مجدد کنید

5. صدای سیستم اکنون کار خواهد کرد

چرا این لازم است:

  • مدل امنیتی macOS
  • ضبط صفحه همه چیز را می‌گیرد
  • کاربر باید به طور صریح اجازه دهد
  • در برابر نرم‌افزارهای جاسوسی محافظت می‌کند

2. شتاب سخت‌افزاری NVIDIA/AMD نیست

شتاب سخت‌افزاری Mac:
• Intel Macs: Intel Quick Sync (در صورت موجود بودن)
• Apple Silicon: VideoToolbox (عالی)
• GPUهای خارجی: برای کدگذاری پشتیبانی نمی‌شود
• NVENC یا AMD VCE نیست (تراشه‌ها موجود نیستند)

عملکرد:

  • Apple Silicon آنقدر کارآمد است که مهم نیست
  • Intel Macs با Quick Sync خوب هستند
  • Intel Macs قدیمی‌تر بدون Quick Sync از کدگذاری CPU استفاده می‌کنند

3. محدودیت‌های Sandbox

امنیت macOS:
• برنامه‌ها sandbox شده‌اند
• باید مجوز درخواست کنند برای:
  - میکروفون
  - دوربین (در صورت استفاده)
  - ضبط صفحه
  - مکان‌های فایل سیستم
  - پوشه دانلودها
  - دسکتاپ

SeaMeet در صورت نیاز این‌ها را درخواست می‌کند

• ممکن است به پیکربندی نیاز داشته باشد

Intel در Linux:
• VA-API برای کدگذاری
• معمولاً به خوبی کار می‌کند
• بخشی از درایورهای Mesa

مشکل: صدای سیستم نیست

راه‌حل‌ها:

1. مجوز ضبط صفحه را اعطا کنید:
   تنظیمات سیستم → امنیت و حریم خصوصی → حریم خصوصی → ضبط صفحه
   SeaMeet را تیک بزنید
   SeaMeet را راه‌اندازی مجدد کنید

2. BlackHole را نصب کنید (صدای مجازی):
   brew install blackhole-2ch
   یا از GitHub دانلود کنید

3. دستگاه چند خروجی تنظیم کنید:
   Audio MIDI Setup → ایجاد Multi-Output
   بلندگوها + BlackHole را اضافه کنید
   به عنوان خروجی سیستم تنظیم کنید

4. macOS جدیدتر (12+):
   ممکن است loopback داخلی داشته باشد
   تنظیمات SeaMeet را بررسی کنید

مشکل: SeaMeet شروع نمی‌شود

راه‌حل‌ها:

1. مجوزها را بررسی کنید:
   - ضبط صفحه
   - میکروفون
   - دسترسی‌پذیری
   - رویدادهای سیستم

2. کلیک راست → باز کردن:
   - اولین بار ممکن است به این نیاز داشته باشد
   - دور زدن Gatekeeper

3. صفت قرنطینه را بررسی کنید:
   xattr -d com.apple.quarantine /Applications/SeaMeet.app

4. نسخه macOS را تأیید کنید:
   • به macOS 14.2 Sonoma یا بالاتر نیاز دارد
   • با آیکون Apple → درباره این Mac بررسی کنید
   • در صورت نیاز به‌روزرسانی کنید

5. به طور کامل راه‌اندازی مجدد کنید:
   - خروج اجباری: Cmd+Q
   - برنامه را به طور کامل بکُشید
   - راه‌اندازی مجدد

6. SeaMeet را دوباره نصب کنید
   - از Applications حذف کنید
   - DMG جدید را دانلود کنید
   - دوباره نصب کنید

مشکل: تشخیص جلسه کار نمی‌کند

راه‌حل‌ها:

1. نسخه macOS را تأیید کنید:
   • تشخیص جلسه به macOS 14.2+ نیاز دارد
   • درباره این Mac را بررسی کنید
   • در صورت داشتن نسخه قدیمی‌تر به‌روزرسانی کنید

2. مجوزهای لازم را اعطا کنید:
   تنظیمات سیستم → امنیت و حریم خصوصی → حریم خصوصی
   ✓ ضبط صفحه
   ✓ میکروفون
   SeaMeet را راه‌اندازی مجدد کنید

3. پلتفرم جلسه را بررسی کنید:
   • مطمئن شوید برنامه جلسه به میکروفون دسترسی دارد
   • تنظیمات سیستم → امنیت و حریم خصوصی → میکروفون
   • در صورت نیاز برنامه جلسه را اضافه کنید (Zoom، Teams و غیره)

4. تشخیص پنجره را تست کنید:
   • یک جلسه در برنامه پشتیبانی‌شده شروع کنید
   • بررسی کنید پنجره در SeaMeet ظاهر می‌شود
   • ابتدا انتخاب پنجره را به صورت دستی امتحان کنید

5. جلسات مرورگر:
   • مطمئن شوید تب مرورگر جلسه فعال است
   • مرورگر باید مجوز ضبط صفحه داشته باشد
   • برخی مرورگرها ممکن است به راه‌اندازی اضافی نیاز داشته باشند

مسائل خاص Linux

مشکل: هیچ دستگاه صوتی نشان داده نمی‌شود

راه‌حل‌ها:

1. سیستم صوتی را بررسی کنید:
   - آیا PulseAudio در حال اجرا است؟
   - یا PipeWire؟
   pactl info

2. مجوزها:
   - کاربر را به گروه audio اضافه کنید
   sudo usermod -a -G audio $USER

3. pavucontrol را نصب کنید:
   - PulseAudio Volume Control
   - دستگاه‌های ورودی/خروجی را بررسی کنید

4. SeaMeet ممکن است به راه‌اندازی خاص نیاز داشته باشد:
   - پیکربندی صدای داخل برنامه را دنبال کنید
   - ممکن است به دستگاه‌های مجازی نیاز داشته باشد

مشکل: استفاده بالای CPU

راه‌حل‌ها:

1. شتاب سخت‌افزاری را فعال کنید:
   - درایورهای VA-API را نصب کنید
   - NVIDIA: پشتیبانی NVENC را بررسی کنید
   - AMD: ممکن است محدود باشد

2. از تنظیمات کیفیت پایین‌تر استفاده کنید:
   - 720p به جای 1080p
   - نرخ فریم پایین‌تر

3. بررسی کنید آیا روی دیسک کند ضبط می‌کنید:
   - در صورت امکان از SSD استفاده کنید
   - عملکرد دیسک را بررسی کنید

4. محیط دسکتاپ:
   - برخی DEها از منابع بیشتری استفاده می‌کنند
   - در صورت نیاز WM سبک‌تری را امتحان کنید

بخش 7: نکات گردش‌کار میان‌پلتفرمی

حرکت بین پلتفرم‌ها

انتقال تنظیمات:

تنظیمات SeaMeet به صورت محلی ذخیره می‌شوند
به طور خودکار با ابر همگام‌سازی نمی‌شوند

انتقال دستی:
1. صادر کردن تنظیمات (در صورت موجود بودن ویژگی)
2. یا یادداشت برداری از تنظیمات کلیدی
3. در پلتفرم دیگر پیکربندی مجدد کنید
4. انتظار برخی تفاوت‌ها را داشته باشید

سازگاری فایل:

فایل‌های ضبط جهانی هستند:
• MP4 در تمام پلتفرم‌ها کار می‌کند
• WebM در تمام پلتفرم‌ها کار می‌کند
• MOV در تمام پلتفرم‌ها کار می‌کند (با کدک‌ها)

هنگام تغییر کامپیوتر نیازی به تبدیل نیست

میانبرهای صفحه‌کلید:

Windows/Linux: Ctrl + Alt + [کلید]
Mac: Cmd + Shift + [کلید]

حافظه عضلانی نیاز به تنظیم دارد
میانبرها را در تنظیمات هر پلتفرم بررسی کنید

بهترین پلتفرم برای استفاده‌های خاص

برای بازی:

  • Windows (بهترین پشتیبانی سخت‌افزار، بیشترین بازی‌ها)

برای کار خلاقانه:

  • macOS (ادغام با برنامه‌های خلاقانه)

برای برنامه‌نویسی/توسعه:

  • هر کدام (ترجیح شخصی)
  • Linux اگر منبع باز را ترجیح می‌دهید

برای تجارت/سازمانی:

  • Windows (رایج‌ترین، آسان‌ترین پشتیبانی IT)
  • macOS (در حال رشد در تجارت)

برای حریم خصوصی:

  • Linux (بیشترین کنترل)

خلاصه

SeaMeet در تمام پلتفرم‌های اصلی کار می‌کند اما هر کدام نقاط قوت دارند:

✅ Windows: بیشترین ویژگی‌ها، راه‌اندازی آسان‌تر، بهترین بازی، کنترل جامع صدا

✅ macOS: پرداخت‌شده، تشخیص جلسه هوشمند، در هر دو Intel و Apple Silicon از طریق DMGهای بهینه جداگانه (نه یک باینری جهانی — مطابق با تراشه خود را انتخاب کنید) کار می‌کند، عملکرد عالی

✅ Linux: انعطاف‌پذیر، متمرکز بر حریم خصوصی، پشتیبانی‌شده توسط جامعه، نصب فقط منبع (بدون نصب‌کننده از پیش ساخته — npm install تمیز از v2.1.4 به بعد)

توصیه‌های پلتفرم:

اگر این موارد هستید Windows را انتخاب کنید:

  • می‌خواهید حداکثر سازگاری
  • بازی ضبط می‌کنید
  • به ضبط صدای سیستم آسان نیاز دارید
  • از GPUهای NVIDIA/AMD استفاده می‌کنید
  • به حداکثر کنترل ویژگی نیاز دارید

اگر این موارد هستید macOS را انتخاب کنید:

  • در اکوسیستم Apple هستید
  • Intel یا Apple Silicon Mac دارید (هر دو پشتیبانی می‌شوند)
  • می‌خواهید تجربه بومی پرداخت‌شده
  • کار خلاقانه انجام می‌دهید
  • می‌خواهید تشخیص خودکار جلسه و انتخاب هوشمند پنجره
  • نظارت صدای به ازای هر برنامه یکپارچه را ارزش می‌دهید

اگر این موارد هستید Linux را انتخاب کنید:

  • از نظر فنی متمایل هستید
  • منبع باز را ارزش می‌دهید
  • می‌خواهید حداکثر کنترل
  • از پیکربندی ناراحت نیستید
  • گزینه‌های پشتیبانی‌شده توسط جامعه را ترجیح می‌دهید

مزایای macOS در v1.0.5+:

✨ ویژگی‌های جدید (macOS 14.2+):
• نظارت میکروفون به ازای هر برنامه (native-audio-node)
• تشخیص خودکار جلسه
• پیش‌انتخاب هوشمند پنجره
• تشخیص جلسه مرورگر
• جلوگیری از شروع خودکار
• نصب‌کننده‌های بهینه جداگانه (Intel + Apple Silicon)
• اندازه‌های دانلود کوچک‌تر (~100 MB به ازای هر معماری)
