平台差异

第 29 章：平台差异

介绍

SeaMeet 在多个平台上工作——Windows、macOS 和 Linux——但每个操作系统都有自己的怪癖、能力和限制。在 Windows 上完美工作的可能在 Mac 上行为不同。一些功能在一个平台上可用，另一个平台上不可用。理解这些差异有助于你无论用哪台电脑都能充分发挥 SeaMeet。

本章解释 SeaMeet 如何适配每个平台、哪些功能是平台特定的，以及你应该知道的限制。

本章目标

读完本章后，你将能够：

  • 理解 Windows、macOS 和 Linux 版本之间的差异
  • 知道哪些功能是平台特定的
  • 为你的操作系统正确配置 SeaMeet
  • 绕过平台特定限制
  • 为录音需求选择合适的平台

第 1 部分：按平台概览

Windows 上的 SeaMeet

最适合：

  • 最大兼容性
  • 游戏录制
  • 商业环境
  • 功能最完整的版本

关键特征：

  • 大多数功能可用
  • 最佳硬件加速支持（NVIDIA/AMD/Intel）
  • 简易的系统音频捕获
  • 最广的应用兼容性
  • 经过最多测试且稳定

支持的 Windows 版本：

  • Windows 10（版本 1809 及更新）
  • Windows 11
  • Windows Server 2019/2022（有限支持）

支持的 Windows 架构：

  • x64 (Intel/AMD 64-bit)： 完整支持，所有功能可用
  • ARM64 (Windows on ARM)： 支持，部分音频功能不可用
    • Surface Pro X 及类似设备
    • 屏幕录制、视频录制、麦克风录制完全支持
    • 系统音频捕获和音频设备枚举不可用（优雅降级）
    • 详见下方 Windows ARM64 部分

不支持：

  • Windows 7、8、8.1（生命周期结束）
  • Windows XP/Vista（古董）
  • 32 位 Windows (x86)

macOS 上的 SeaMeet

最适合：

  • 创意专业人士
  • Apple 生态系统用户
  • 清晰、一致的界面
  • 与 Mac 工作流集成

关键特征：

  • 精致、原生 Mac 界面
  • 在 Apple Silicon (M1/M2/M3) 上表现卓越
  • 在 Intel Mac 上表现卓越
  • 紧密的系统集成
  • 不同的权限模型
  • 每应用麦克风监控
  • 浏览器会议检测和自动开始预防

支持的 macOS 版本：

  • macOS 14.2 Sonoma（最低 - native-audio-node 功能所需）
  • macOS 15 Sequoia
  • 未来版本

支持的 macOS 架构：

  • Apple Silicon (arm64)： 完整支持，包含每应用音频检测的所有功能
  • Intel (x64)： 完整支持，使用单独的安装包

Apple Silicon 与 Intel 支持：

  • 两个独立的 DMG 安装包：一个用于 Intel，一个用于 Apple Silicon
  • 下载与你 Mac 处理器匹配的版本
  • M1/M2/M3 Mac → 下载 arm64 版本
  • Intel Mac → 下载 x64 版本
  • 两个版本功能相同
  • 通过 VideoToolbox（Apple Silicon）或 Quick Sync（Intel）实现硬件加速
  • 每应用麦克风检测 (native-audio-node)
  • 会议应用的智能窗口预选

Linux 上的 SeaMeet

最适合：

  • 从源码运行 SeaMeet 的技术用户
  • 为项目做贡献的开发者
  • 注重隐私的用户
  • 开源倡导者

关键特征：

  • 社区支持、仅源码（无官方预构建安装包）
  • 各发行版功能差异较大
  • 需要更多手动配置
  • 命令行友好
  • 较少"它就这样工作"的功能

支持的发行版：

  • Ubuntu 20.04+（最佳支持）
  • Fedora 34+
  • Debian 11+
  • 其他基于 Debian/Ubuntu 的发行版

Linux 安装说明 (v2.1.4+)：

✅ npm install 现在在 Linux 上能干净地成功

直到 v2.1.4，由于 native-audio-node ——一个仅 macOS/Windows
的原生模块——被列在 `dependencies` 中，`npm install` 在 Linux 上
会因 EBADPLATFORM 而失败。从 v2.1.4 起，它与其他平台特定的音频
包（macos-audio-devices、native-sound-mixer、win-audio）一起
位于 `optionalDependencies` 中，因此 npm 在 Linux 上跳过它们
而不是中止。

如果你之前遇到 `npm ERR! EBADPLATFORM`：
1. 拉取 v2.1.4 或更新
2. 删除 node_modules 和 package-lock.json
3. 再次运行 npm install — 应该无错误完成

限制：

  • 无官方预构建安装包——通过 npm start 从源码运行
  • 每应用麦克风监控和会议自动检测不可用（需要 native-audio-node，没有 Linux 二进制）
  • 系统托盘可用性取决于桌面环境（见下方托盘部分）
  • 硬件加速因 GPU/驱动组合而异
  • 系统音频捕获需要更多设置（PulseAudio / PipeWire 回环）

Linux 托盘说明：

Electron 托盘在 GNOME（带 AppIndicator 扩展）、KDE Plasma、XFCE、Cinnamon 以及大多数 Ubuntu/Fedora 默认桌面上可靠工作。在仅 Wayland 会话和一些最小窗口管理器上，托盘图标可能根本不出现——应用仍在运行，但你需要从终端重新启动它或使用全局热键召回窗口。没有 Linux 特定的托盘图标资源；加载与 Windows 相同的 .ico。

Lite 模式：

Lite 模式（在 v2.x 引入）是一种渲染器侧的紧凑布局——一个 560×80 的悬浮栏，包含录音控件、波形和快速操作，而不是完整应用窗口。它由 ui.appMode 设置（'full' 或 'lite'）控制，并通过 Settings 在运行时切换。Lite 模式在所有三个平台上行为相同，因为它没有平台特定的代码路径。

Windows ARM64 特定信息

什么是 Windows ARM64？

ARM64 是不同的处理器架构：
• 用于 Windows on ARM 设备（Surface Pro X 等）
• 对 ARM 基础处理器的原生支持
• 可以模拟 x64 应用（较慢）
• 对原生 ARM64 应用的支持不断增长

ARM64 上的 SeaMeet

SeaMeet 从 v1.0.2+ 开始有原生 ARM64 支持：

✅ ARM64 完全支持：
• 屏幕录制（高性能）
• 视频录制（高性能）
• 麦克风录制（直接 Windows API）
• 窗口检测和管理
• Floater 组件和键盘快捷键
• 设置和录音库
• 所有 UI 功能

❌ ARM64 上不可用：
• 系统音频捕获（来自应用/喇叭的音频）
• 音频设备枚举（麦克风/喇叭检测）
• 音频混合器控制
• 这些需要未为 ARM64 编译的原生模块

何时应使用 ARM64

最适合：

  • Surface Pro X 用户想要原生性能
  • 录制视频/屏幕不需要系统音频
  • 麦克风录制（直接录制可用）
  • 完整性能无模拟减速

不理想：

  • 系统音频捕获（将不可用）
  • 复杂音频工作流
  • 音频设备选择（不可用）

如何知道你有哪个版本

Windows 设置：
1. Settings → System → About
2. 寻找 "系统类型"
3. 显示以下之一：
   • "基于 x64 的处理器"（64 位 Intel/AMD）
   • "基于 ARM 的处理器"（Windows on ARM）

命令行：

PowerShell：wmic os get osarchitecture
输出：64-bit 或 ARM 64-bit

• 下载通用安装包
• 它会自动安装正确版本
• x64 用户得到：SeaMeet-...-x64-Setup.exe
• ARM64 用户得到：SeaMeet-...-arm64-Setup.exe

或从 releases 手动下载正确的：
• 检查你的系统类型（上方）
• 下载匹配的架构

ARM64 上的自动更新器

无缝更新：
• 应用自动检查更新
• ARM64 更新为 ARM64（不是 x64）
• 与之前版本向后兼容
• 无需手动干预

ARM64 问题排查

问题：系统音频选项变灰

ARM64 上的预期行为：
✓ 这是正常的
✓ 原生模块不可用
✓ 仍可录制麦克风
✓ 没有错误 - 优雅降级

问题：无法选择麦克风/喇叭

解决方案：
1. 使用默认系统设备
2. 进入 Windows Sound 设置选择设备
3. SeaMeet 会使用 Windows 选定的设备
4. 手动设备选择在 ARM64 上不可用

问题：录制麦克风不工作

解决方案：
1. 检查 Windows Sound 设置
2. 麦克风应该是默认输入设备
3. 给 SeaMeet 授予麦克风权限
4. Windows 应该显示录音电平
5. 先在 Windows 录音应用中测试

1. 精致界面

Mac 上的 SeaMeet 感觉原生：

• 遵循 macOS 设计指南
• 使用原生控件
• 尊重系统主题
• Touch Bar 支持（在兼容的 Mac 上）
• 适当的菜单栏集成

2. 卓越的 Apple Silicon 支持

M1/M2/M3 芯片工作出色：

Apple Silicon 功能：
• 通过 VideoToolbox 的硬件加速
• 卓越的每瓦特性能
• 快速编码
• 低温操作
• 录制时长电池续航

3. 系统集成

macOS 集成：
• iCloud Drive 支持
• Time Machine 兼容
• Handoff/Continuity 就绪
• 适当的沙盒
• 安全范围书签

macOS 限制

1. 系统音频需要权限

不像 Windows，macOS 需要明确权限：

设置步骤：

1. 首次录制系统音频：
   System Preferences → Security & Privacy → Privacy
   
2. 点击左侧 "Screen Recording"

3. 在列表中勾选 "SeaMeet"
   （可能需要用密码解锁）

4. 完全重启 SeaMeet

5. 系统音频现在可用

为何需要这个：

  • macOS 安全模型
  • 屏幕录制捕获一切
  • 用户必须明确允许
  • 防止间谍软件

2. 无 NVIDIA/AMD 硬件加速

Mac 硬件加速：
• Intel Mac：Intel Quick Sync（如可用）
• Apple Silicon：VideoToolbox（卓越）
• 外接 GPU：不支持用于编码
• 没有 NVENC 或 AMD VCE（芯片不存在）

性能：

  • Apple Silicon 如此高效以致没关系
  • 带 Quick Sync 的 Intel Mac 也很好
  • 没有 Quick Sync 的老 Intel Mac 使用 CPU 编码

3. 沙盒限制

macOS 安全：
• 应用是沙盒的
• 必须请求权限以使用：
  - 麦克风
  - 相机（如使用）
  - 屏幕录制
  - 文件系统位置
  - 下载文件夹
  - 桌面

我应该下载哪个版本？

检查你的 Mac 类型：
苹果菜单 (🍎) → 关于本机 → 芯片

如果你看到：
• "Apple M1"、"Apple M2" 或 "Apple M3"
  → 下载：SeaMeet-macOS-arm64-[version].dmg

• "Intel Core i5"、"Intel Core i7" 等
  → 下载：SeaMeet-macOS-x64-[version].dmg

为何独立安装包？

✅ 下载更小（~100 MB 而非 ~180 MB 通用）
✅ 为你特定处理器优化
✅ 与原生模块没有兼容性问题
✅ 更简单的构建和更新流程

性能：

Apple Silicon (arm64)：
• M1、M2、M3 芯片
• 卓越性能
• 更好电池续航
• 原生 arm64 执行

Intel (x64)：
• 2013-2021 Mac
• 完整功能对等
• Quick Sync 加速
• 原生 x64 执行

安装：

1. 为你的 Mac 下载正确的 DMG
2. 打开 DMG 文件
3. 拖动 SeaMeet 到应用程序
4. 启动并授予权限

macOS 会议检测功能

macOS 上的 SeaMeet 包含具有每应用音频监控的高级会议检测：

每应用麦克风监控：

工作原理：
• 监控哪个应用在使用你的麦克风
• 检测会议何时开始/停止
• 使用 native-audio-node 进行每应用检测
• 在 macOS 14.2+ (Sonoma) 上可用

支持的平台：
• Zoom
• Google Meet
• Microsoft Teams
• Apple FaceTime
• Webex
• 以及其他会议平台

浏览器会议检测：

自动检测以下活动会议：
• Google Meet (Chrome/Firefox/Safari)
• Zoom 网页客户端
• Webex 网页客户端
• Teams 网页
• 其他基于网页的会议平台

窗口预选：
• 自动选择会议窗口
• 防止意外录制其他应用
• 除非明确启用，否则不自动开始
• 维持用户控制

要求：

macOS 14.2 Sonoma 或更新
• native-audio-node API 所需
• 覆盖所有现代 Mac 用户
• 启用每应用音频检测

第 5 部分：Linux 特定信息

Linux 特征

1. 多变的体验

Linux 版本因发行版而异：

Ubuntu（推荐）：
• 最佳支持
• 最简设置
• 大多数功能工作
• 定期测试

Fedora：
• 良好支持
• 新的包
• 可能需要额外仓库

其他发行版：
• 各有差异
• 社区支持
• 可能需要手动修复

2. 音频捕获复杂性

Linux 音频更复杂：

音频系统：
• PulseAudio（最常见）
• PipeWire（较新、现代）
• ALSA（低级）
• JACK（专业音频）

需要设置：
可能需要创建虚拟音频设备
或使用回环模块
不像 Windows 那样即插即用

PulseAudio 设置：

# 为系统音频创建虚拟接收器
pactl load-module module-null-sink sink_name=SeaMeet sink_properties=device.description=SeaMeetRecording

# 监听它
pactl load-module module-loopback source=SeaMeet.monitor

3. 硬件加速因情况而异

Linux 上的 NVIDIA：
• NVENC 通过专有驱动可用
• 必须单独安装
• 工作时质量良好

Linux 上的 AMD：
• VCE 支持因驱动而异
• 开源 vs 专有驱动
• 可能需要配置

Linux 上的 Intel：
• VA-API 用于编码
• 通常工作良好
• Mesa 驱动的一部分

Linux 设置指南

Ubuntu 安装：

# 下载 .deb 包
# 或如可用通过仓库安装

sudo dpkg -i seameet-linux.deb
sudo apt-get install -f  # 修复依赖

# 授予权限
# 把用户加入 video 组
sudo usermod -a -G video $USER

# 注销并重新登录

Fedora 安装：

# 下载 .rpm 包
sudo rpm -i seameet-linux.rpm

# 或如在仓库中通过 dnf
sudo dnf install seameet

安装后设置：

# 1. 音频设置（复杂）
# 按 SeaMeet 应用内音频设置指南

# 2. 硬件加速
# 安装适当驱动：
# NVIDIA：nvidia-utils 或专有
# AMD：mesa-va-drivers
# Intel：intel-media-driver

# 3. 权限
# 可能需要配置 udev 规则
# 用于设备访问

Linux 特定快捷键

全局快捷键：
• Ctrl + Alt + R — 开始/停止录制
• Ctrl + Alt + F — 保存 Flashback
• Ctrl + Alt + S — 截图

注意：可能与桌面快捷键冲突
如需要在 SeaMeet 设置中配置

第 6 部分：平台特定故障排查

Windows 特定问题

问题：无法捕获系统音频

解决方案：

1. 启用 Stereo Mix：
   - Sound Control Panel → Recording
   - 显示禁用设备
   - 启用 Stereo Mix

2. 使用 WASAPI 方法：
   - SeaMeet 设置 → Audio → Method
   - 选择 WASAPI 回环

3. Realtek 上没有 Stereo Mix：
   - 更新 Realtek 驱动
   - 或改用 WASAPI 方法

4. Windows 11 特定：
   - 检查隐私设置
   - Settings → Privacy → Microphone
   - 确保应用可以访问音频

问题：游戏录制黑屏

解决方案：

1. 禁用全屏优化：
   - 右键游戏 exe → Properties
   - Compatibility → 禁用全屏优化

2. 使用窗口或无边框模式

3. 禁用 Windows Game Bar：
   - 可能与 SeaMeet 冲突

4. 以管理员运行 SeaMeet

5. 如可用使用游戏捕获模式

macOS 特定问题

问题：没有系统音频

解决方案：

1. 授予 Screen Recording 权限：
   System Preferences → Security & Privacy → Privacy → Screen Recording
   勾选 SeaMeet
   重启 SeaMeet

2. 安装 BlackHole（虚拟音频）：
   brew install blackhole-2ch
   或从 GitHub 下载

3. 设置多输出设备：
   Audio MIDI Setup → 创建多输出
   添加喇叭 + BlackHole
   设为系统输出

4. 较新 macOS (12+)：
   可能有内置回环
   检查 SeaMeet 设置

问题：SeaMeet 无法启动

解决方案：

1. 检查权限：
   - Screen Recording
   - Microphone
   - Accessibility
   - System Events

2. 右键 → 打开：
   - 首次可能需要这个
   - 绕过 Gatekeeper

3. 检查隔离属性：
   xattr -d com.apple.quarantine /Applications/SeaMeet.app

4. 验证 macOS 版本：
   • 需要 macOS 14.2 Sonoma 或更新
   • 用苹果图标 → 关于本机检查
   • 如需要请更新

5. 完全重启：
   - 强制退出：Cmd+Q
   - 完全杀死应用
   - 重新启动

6. 重新安装 SeaMeet
   - 从应用程序中移除
   - 下载新的 DMG
   - 重新安装

问题：会议检测不工作

解决方案：

1. 验证 macOS 版本：
   • 会议检测需要 macOS 14.2+
   • 检查关于本机
   • 如在更老版本上请更新

2. 授予必要权限：
   System Preferences → Security & Privacy → Privacy
   ✓ Screen Recording
   ✓ Microphone
   重启 SeaMeet

3. 检查会议平台：
   • 确保会议应用有麦克风访问
   • System Preferences → Security & Privacy → Microphone
   • 如需要添加会议应用（Zoom、Teams 等）

4. 测试窗口检测：
   • 在支持的应用中开始会议
   • 检查窗口是否出现在 SeaMeet 中
   • 先尝试手动选择窗口

5. 浏览器会议：
   • 确保会议浏览器标签活跃
   • 浏览器必须有屏幕录制权限
   • 部分浏览器可能需要额外设置

Linux 特定问题

问题：没有音频设备显示

解决方案：

1. 检查音频系统：
   - PulseAudio 在运行吗？
   - 或 PipeWire？
   pactl info

2. 权限：
   - 把用户加入 audio 组
   sudo usermod -a -G audio $USER

3. 安装 pavucontrol：
   - PulseAudio Volume Control
   - 检查输入/输出设备

4. SeaMeet 可能需要特定设置：
   - 按应用内音频配置
   - 可能需要虚拟设备

问题：高 CPU 使用率

解决方案：

1. 启用硬件加速：
   - 安装 VA-API 驱动
   - NVIDIA：检查 NVENC 支持
   - AMD：可能有限

2. 使用较低质量设置：
   - 720p 而不是 1080p
   - 较低帧率

3. 检查是否录到慢盘上：
   - 如可能使用 SSD
   - 检查盘性能

4. 桌面环境：
   - 部分 DE 使用更多资源
   - 如需要尝试较轻的 WM

第 7 部分：跨平台工作流提示

在平台之间移动

设置传输：

SeaMeet 设置在本地存储
没有自动云同步

手动传输：
1. 导出设置（如功能可用）
2. 或记下关键设置
3. 在另一平台上重新配置
4. 期待一些差异

文件兼容性：

录音文件是通用的：
• MP4 在所有平台上工作
• WebM 在所有平台上工作
• MOV 在所有平台上工作（带编解码器）

切换计算机时无需转换

键盘快捷键：

Windows/Linux：Ctrl + Alt + [键]
Mac：Cmd + Shift + [键]

肌肉记忆需要调整
在每个平台的设置中检查快捷键

特定用途的最佳平台

游戏：

  • Windows（最佳硬件支持，最多游戏）

创意工作：

  • macOS（与创意应用集成）

编程/开发：

  • 任何（个人偏好）
  • 如果偏好开源，Linux

商业/企业：

  • Windows（最常见，IT 支持最简单）
  • macOS（在商业中增长）

隐私：

  • Linux（最多控制）

总结

SeaMeet 在所有主要平台上工作，但每个都有优势：

✅ Windows： 大多数功能、最简设置、最佳游戏、全面音频控制

✅ macOS： 精致、智能会议检测、通过独立优化的 DMG 在 Intel 和 Apple Silicon 上工作（不是通用二进制——挑选与你芯片匹配的），卓越性能

✅ Linux： 灵活、注重隐私、社区支持、仅源码安装（无预构建安装包——从 v2.1.4 开始 npm install 是干净的）

平台推荐：

选 Windows 如果：

  • 你想要最大兼容性
  • 你录制游戏
  • 你需要简易系统音频捕获
  • 你使用 NVIDIA/AMD GPU
  • 你需要最大功能控制

选 macOS 如果：

  • 你在 Apple 生态系统中
  • 你有 Intel 或 Apple Silicon Mac（都支持）
  • 你想要精致的原生体验
  • 你做创意工作
  • 你想要自动会议检测和智能窗口选择
  • 你重视集成的每应用音频监控

选 Linux 如果：

  • 你技术倾向
  • 你重视开源
  • 你想要最大控制
  • 你不介意配置
  • 你偏好社区支持的选项

v1.0.5+ 中的 macOS 优势：

✨ 新功能 (macOS 14.2+)：
• 每应用麦克风监控 (native-audio-node)
• 自动会议检测
• 智能窗口预选
• 浏览器会议检测
• 自动开始预防
• 单独优化的安装包（Intel + Apple Silicon）
• 较小下载（每架构 ~100 MB）
