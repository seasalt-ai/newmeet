了解檔案格式

第 5 章：了解檔案格式

到目前為止，你已經完成了幾次錄音，也注意到 SeaMeet 會將檔案儲存為像 recording.webm 這樣的名稱，或者你見過其他以 .mp3、.mp4、.wav 等結尾的檔案。但這些字母代表什麼意思？為什麼一個錄音只佔 2 MB，而另一個卻佔了 200 MB？為什麼你的影片有時候在朋友的電腦上無法播放？

本章將為你揭開檔案格式、編解碼器和所有技術術語的神秘面紗。我們會用日常生活的比喻來解釋為什麼檔案有不同的格式、它們如何影響品質和大小，以及——最重要的——針對你的特定需求，應該使用哪種格式。

基礎知識：什麼是檔案格式？

讓我們從一個簡單的問題開始：為什麼你不能用紙袋裝湯？

因為容器很重要。

紙袋適合裝三明治，但完全不適合裝湯。你需要一個能夠：

  • 妥善容納內容物
  • 保持東西有條理
  • 符合你使用方式的容器

檔案格式完全相同。 它們就是音訊和視訊的容器。

容器的比喻

把檔案格式想像成一個運送箱：

箱子（檔案格式/容器）：

  • 決定了形狀和大小限制
  • 有一個標籤（.webm、.mp4、.mp3 副檔名）
  • 將所有東西整合在一起

箱子裡面的東西（實際資料）：

  • 音訊軌道（你的聲音、音樂）
  • 視訊軌道（螢幕錄影）
  • 中繼資料（時間、日期、錄音資訊）
  • 字幕或說明文字（如果有的話）

不同用途的不同箱子：

  • MP3 箱子：只能裝音訊（像一個裝易碎物品的加墊信封）
  • MP4 箱子：可裝視訊 + 音訊（像一個堅固的運送箱）
  • WebM 箱子：現代、高效的網路內容箱子
  • WAV 箱子：裝未壓縮音訊（像一個堅固的金屬箱——很重但保護力強）

音訊格式 vs. 視訊格式：有什麼不同？

很多混淆就是從這裡開始的。讓我們一次說清楚。

純音訊格式

這些容器只能裝聲音——沒有視訊、沒有圖片，只有音訊。

常見的純音訊格式：

  • MP3 (.mp3)
  • WAV (.wav)
  • FLAC (.flac)
  • AAC/M4A (.m4a, .aac)
  • OGG (.ogg)
  • Opus (.opus)

可以把它們想像成： 純音訊容器，就像一張音樂 CD（還記得那些嗎？）或一台錄音機。

當你看到這些格式時：

  • 你知道裡面沒有視訊
  • 它們只包含聲音
  • 通常檔案大小較小

視訊格式

這些容器可以同時容納視訊和音訊。

常見的視訊格式：

  • MP4 (.mp4)
  • WebM (.webm)
  • MOV (.mov)
  • MKV (.mkv)
  • AVI (.avi)

可以把它們想像成： 完整的套裝，可以同時裝「電影」（視訊）和「配樂」（音訊）。

當你看到這些格式時：

  • 它們可能有視訊、音訊或兩者兼具
  • 通常檔案大小較大
  • 結構更複雜

MP3 vs. MP4 的混淆

這是最容易混淆的地方：

MP3 = 純音訊

  • 像你手機上的音樂檔案
  • 只包含聲音
  • 無法容納視訊
  • 例如：iTunes 或 Spotify 上的歌曲

MP4 = 視訊 + 音訊

  • 像電影或 YouTube 影片
  • 同時包含畫面和聲音
  • 也可以只裝音訊（確實令人困惑！）
  • 例如：YouTube 下載的檔案、電影檔案

簡單的記憶方式：

  • MP3 = 「MPEG-1 Audio Layer 3」 = 純音訊
  • MP4 = 「MPEG-4 Part 14」 = 視訊容器

比喻：

  • MP3 就像卡式錄音帶（純音訊）
  • MP4 就像 DVD（可以有視訊 + 音訊）

了解編解碼器：關鍵要素

現在我們需要談談一個叫做**編解碼器（codec）**的東西。這部分會有點技術性，但我們會讓它簡單易懂。

什麼是編解碼器？

Codec = Coder（編碼器）+ Decoder（解碼器）

編解碼器就像一個翻譯員：

  1. 儲存時編碼（壓縮）你的錄音，使其變小
  2. 播放時解碼（解壓縮）它

壓縮的比喻：

想像你有一大堆衣服（你的原始錄音）。你有兩個選擇：

選項 1：不壓縮（WAV，未壓縮）

  • 把所有東西原封不動地丟進行李箱
  • 佔滿整個行李箱
  • 打開時，一切都跟你放進去時一模一樣
  • 完美品質，但體積巨大

選項 2：壓縮（MP3、AAC、Opus）

  • 把所有東西整齊地摺好並真空密封
  • 只佔行李箱的十分之一
  • 打開時，衣服大致上一樣
  • 有些微小皺褶（品質損失），但效率高得多

編解碼器就是摺疊方法——不同的編解碼器用不同的方式摺疊（壓縮），在大小和品質之間有不同的取捨。

常見音訊編解碼器說明

MP3 (MPEG-1 Audio Layer 3)

它是什麼： 最著名的音訊編解碼器 年齡： 1993 年發明（超過 30 年了！） 品質： 對音樂來說不錯，對語音可接受 壓縮： 使檔案縮小約 10 倍

最適合：

  • 音樂
  • Podcast
  • 廣泛相容性（到處都能播放）

取捨：

  • 檔案大小小 ✓
  • 輕微品質損失（尤其在較低位元率時）

為什麼它無處不在： MP3 成為標準，是因為它是第一個讓音樂檔案小到可以在 1990 年代的慢速網路上分享的格式。

AAC（進階音訊編碼）

它是什麼： MP3 的繼任者 年齡： 1997 年發明 品質： 在相同檔案大小下優於 MP3 壓縮： 比 MP3 更有效率

最適合：

  • Apple 生態系（iPhone、iTunes）
  • 串流（YouTube、Netflix 使用此格式）
  • 語音錄音

為什麼它比 MP3 好：

  • 相同品質但更小的檔案
  • 對語音更好
  • 現代標準

你會在哪裡看到它：

  • Apple Music
  • YouTube 音訊
  • 大多數串流服務
  • 副檔名為 .m4a 或 .aac 的檔案

Opus

它是什麼： 最現代、最高效的音訊編解碼器 年齡： 2012 年發布 品質： 優秀，尤其對語音 壓縮： 非常高效——小檔案，好品質

最適合：

  • 語音和演講
  • 視訊通話
  • 串流
  • 當品質和大小都很重要時

為什麼 SeaMeet 使用 Opus：

  • 完美適合語音錄音
  • 優秀的壓縮效果
  • 免費且開放的標準（無授權費用）
  • 與 WebM 容器配合得很好

秘密武器： Opus 是「聰明的」——它會根據錄音內容自動調整壓縮方式。語音用一種壓縮方式，音樂用另一種。

WAV（波形音訊檔案格式）

它是什麼： 未壓縮的原始音訊 年齡： 1991 年發明 品質： 完美——完全不壓縮 檔案大小： 巨大（比 MP3 大 10 倍）

最適合：

  • 專業音訊編輯
  • 封存原始錄音
  • 當品質比大小更重要時
  • 音訊製作

為什麼使用它：

  • 零品質損失
  • 容易編輯
  • 專業人士的行業標準

為什麼避免使用它：

  • 檔案極其龐大
  • 不適合分享
  • 對大多數用途來說過度了

把它想像成： RAW 照片 vs. JPEG——最高品質，最大體積。

FLAC（免費無損音訊編解碼器）

它是什麼： 壓縮但無損（完美品質） 年齡： 2001 年發布 品質： 完美——無品質損失 檔案大小： 約為 WAV 的一半

最適合：

  • 發燒友
  • 音樂封存
  • 當你想要完美品質但合理大小時

神奇之處： FLAC 就像音訊的 ZIP 檔案——它讓檔案變小但不損失任何品質。當你「解壓縮」它時，你得到的跟原來完全一樣。

你會在哪裡看到它：

  • 高品質音樂下載
  • 發燒友收藏
  • 封存重要錄音

OGG Vorbis

它是什麼： MP3 的開源替代方案 年齡： 2000 年發布 品質： 與 MP3 相近 壓縮： 高效

最適合：

  • 開源專案
  • 當你想避免專有格式時
  • 遊戲音訊

注意： 經常與 OGG Opus 混淆（那是不同的，而且對語音更好）。

音訊編解碼器比較

編解碼器檔案大小品質最適合相容性
Opus非常小優秀語音、串流、會議良好（現代裝置）
AAC小很好音樂、一般用途優秀
MP3小好通用相容性通用
FLAC中等完美封存、音樂良好
WAV巨大完美專業編輯優秀
OGG小好開源專案中等

了解視訊編解碼器

視訊比音訊更複雜，因為資料量更大。視訊編解碼器必須壓縮每分鐘數千張圖片（幀）。

常見視訊編解碼器說明

VP9

它是什麼： 現代、高效的視訊編解碼器 開發者： Google 品質： 優秀 壓縮： 非常高效

最適合：

  • YouTube（YouTube 大部分影片使用 VP9）
  • 網路串流
  • 合理檔案大小的高品質視訊
  • 4K 和 HD 內容

為什麼它很出色：

  • 與 H.264 相同品質但檔案更小
  • 免費且開放（無授權費用）
  • 優秀的串流效果

你會在哪裡看到它：

  • WebM 檔案內
  • YouTube 影片
  • 現代瀏覽器

VP8

它是什麼： VP9 的前身 開發者： Google 品質： 好 壓縮： 好

最適合：

  • 當 VP9 不可用時的替代方案
  • 較舊的裝置
  • 網路視訊

現狀： 正被 VP9 取代，但仍然獲得廣泛支援。

H.264 (AVC)

它是什麼： 支援最廣泛的視訊編解碼器 年齡： 2003 年發布 品質： 很好 壓縮： 好

最適合：

  • 最大相容性
  • 在任何裝置上播放
  • 與他人分享
  • 專業視訊

為什麼它無處不在：

  • 幾乎在每台裝置上都能運作
  • 超過十年的行業標準
  • 用於藍光、串流、廣播

缺點：

  • 需要授權費用（製造商支付）
  • 不如較新的編解碼器（VP9、H.265）高效

你會在哪裡看到它：

  • MP4 檔案內
  • YouTube
  • Netflix
  • iPhone 影片
  • DVD 和藍光

H.265 (HEVC)

它是什麼： H.264 的繼任者 年齡： 2013 年發布 品質： 優秀 壓縮： 在相同品質下比 H.264 小 50%

最適合：

  • 4K 視訊
  • 當檔案大小很關鍵時
  • 高品質串流

取捨：

  • 比 H.264 更好的壓縮
  • 但對較舊裝置相容性較差
  • 更高的授權費用

你會在哪裡看到它：

  • iPhone 4K 錄影
  • 部分串流服務
  • MKV 檔案內

AV1

它是什麼： 視訊編解碼器的未來 年齡： 2018 年發布 品質： 優秀 壓縮： 優於 VP9 和 H.265

最適合：

  • 串流的未來
  • 最高效率
  • 當你想要最佳壓縮時

目前狀況：

  • 非常新
  • 在較舊裝置上支援有限
  • YouTube 和 Netflix 正開始使用

視訊編解碼器比較

編解碼器檔案大小品質相容性最適合
VP9小優秀良好（現代裝置）網路、YouTube、串流
H.264中等很好通用分享、相容性
H.265非常小優秀中等4K、注重大小時
VP8中等好良好替代方案、較舊裝置
AV1非常小優秀有限（新）面向未來

了解容器（檔案格式）

既然你已經了解了編解碼器，讓我們來談談容器。記住：容器是箱子，編解碼器是箱子裡面的東西。

為什麼容器很重要

不同的容器可以容納不同的編解碼器組合。有些很靈活，有些則有限制。

比喻：

  • 貨櫃（像貨船上的那種）幾乎可以裝任何東西
  • 珠寶盒專門為珠寶設計
  • CD 盒只能裝 CD

音訊/視訊容器的運作方式相同。

純音訊容器

MP3 容器 (.mp3)

可容納： 僅 MP3 音訊 能裝視訊嗎？ 不能 能裝其他編解碼器嗎？ 不能，只能裝 MP3

把它想像成： 一台專用的 MP3 播放器——只能播 MP3。

為什麼使用它：

  • 通用相容性
  • 簡單直接
  • 所有裝置都支援

WAV 容器 (.wav)

可容納： 未壓縮音訊（PCM） 能裝視訊嗎？ 不能 能裝其他編解碼器嗎？ 可以，但通常是未壓縮的

把它想像成： 專業儲存金庫——以最純粹的形式保存音訊。

為什麼使用它：

  • 專業編輯
  • 無品質損失
  • 容易處理

FLAC 容器 (.flac)

可容納： FLAC 壓縮音訊 能裝視訊嗎？ 不能 能裝其他編解碼器嗎？ 不能，只能裝 FLAC

把它想像成： 壓縮金庫——完美品質，更小體積。

M4A 容器 (.m4a)

可容納： AAC 音訊（通常） 能裝視訊嗎？ 不能（那是 MP4） 能裝其他編解碼器嗎？ 技術上可以，但通常是 AAC

把它想像成： Apple 偏好的音訊箱子。

為什麼使用它：

  • Apple 生態系
  • 比 MP3 好
  • 良好的壓縮效果

視訊容器

WebM 容器 (.webm)

可容納：

  • 視訊：VP8、VP9 或 AV1
  • 音訊：Opus 或 Vorbis

能裝 H.264 嗎？ 不能 能裝 MP3 嗎？ 不能

把它想像成： 現代、高效的網路視訊箱子。

為什麼 SeaMeet 使用 WebM：

  • 優秀的壓縮效果（小檔案）
  • 高品質
  • 免費且開放（無授權費用）
  • 完美適合語音 + 螢幕錄影
  • 在網頁瀏覽器中表現出色

相容性：

  • ✓ Chrome、Firefox、Edge（優秀）
  • ✓ VLC Media Player
  • ✓ 現代媒體播放器
  • ✗ Windows Media Player（可能需要編解碼器）
  • ✗ QuickTime（較舊版本）

取捨：

  • 對現代裝置表現出色
  • 在較舊的 Windows 電腦上可能需要 VLC

MP4 容器 (.mp4)

可容納：

  • 視訊：H.264、H.265 或其他
  • 音訊：AAC、MP3 或其他

能裝 VP9 嗎？ 技術上可以，但很少使用

把它想像成： 通用視訊箱子——到處都能用。

為什麼它受歡迎：

  • 通用相容性
  • 在每台裝置上都能運作
  • 分享的標準格式
  • iPhone 和 Android 原生支援

你會在哪裡看到它：

  • YouTube 下載
  • iPhone 錄影
  • 分享的影片
  • 專業視訊

MOV 容器 (.mov)

可容納：

  • 視訊：各種編解碼器（通常是 H.264）
  • 音訊：各種編解碼器

把它想像成： Apple 的視訊箱子。

為什麼使用它：

  • Apple 的原生格式
  • 專業視訊編輯
  • 適合 Mac 工作流程

注意： 現代 MOV 檔案與 MP4 非常相似。許多 MOV 檔案可以在任何裝置上播放。

MKV 容器 (.mkv)

可容納： 幾乎所有東西！

  • 視訊：H.264、H.265、VP9、VP8 等
  • 音訊：MP3、AAC、FLAC、Opus 等
  • 字幕：多種語言
  • 章節：像 DVD 章節

把它想像成： 視訊容器界的瑞士刀。

為什麼它很強大：

  • 可以容納多條音訊軌道（英語、西班牙語等）
  • 可以容納多條字幕軌道
  • 可以容納章節
  • 非常靈活

缺點：

  • 相容性不如 MP4
  • 部分裝置無法原生播放 MKV
  • 更適合儲存而非分享

最適合：

  • 封存包含多種語言的電影
  • 儲存帶字幕的影片
  • 當你需要最大靈活性時

容器視訊編解碼器音訊編解碼器靈活性相容性最適合

為什麼 SeaMeet 使用 WebM

你可能已經注意到 SeaMeet 將錄音儲存為 .webm 檔案。讓我們解釋原因。

WebM 的優勢

1. 完美適合語音 WebM 使用 Opus 音訊編解碼器，對語音和語音錄音表現優秀。就像擁有一個專門為會議和對話設計的編解碼器。

2. 高效壓縮 WebM 搭配 VP9 視訊和 Opus 音訊所產生的檔案：

  • 比 MP4 搭配 H.264 更小
  • 在相同大小下品質優於 MP4
  • 完美適合螢幕錄影

3. 免費且開放 WebM 完全免費：

  • 無授權費用
  • 無需擔心專利
  • 任何人都可以使用
  • 開源

4. 現代且對網路友善 WebM 是為網路而設計的：

  • 在瀏覽器中表現出色
  • 串流效率高
  • 完美適合上傳到網路平台

5. 非常適合螢幕錄影 VP9（WebM 中的視訊編解碼器）特別擅長：

  • 清晰地錄製文字和 UI 元素
  • 高效壓縮螢幕內容
  • 保留銳利的邊緣和細節

WebM 的取捨

相容性考量： 雖然 WebM 很優秀，但它的通用支援程度不如 MP4：

表現出色：

  • ✓ Google Chrome
  • ✓ Mozilla Firefox
  • ✓ Microsoft Edge
  • ✓ VLC Media Player
  • ✓ 現代 Android 裝置
  • ✓ 大多數現代媒體播放器

可能有問題：

  • ✗ Windows Media Player（舊版本）
  • ✗ QuickTime Player
  • ✗ 部分較舊裝置
  • ✗ iPhone（沒有第三方應用程式的話）

解決方案： 如果你需要分享給無法播放 WebM 的人，你可以：

  1. 請他們安裝 VLC（免費，什麼都能播）
  2. 轉換為 MP4（見下方轉換章節）
  3. 上傳到 YouTube 或類似平台（它們會處理格式）

你應該使用哪種格式？

這是實際的問題。以下是簡單的指南：

音訊錄音

分享給任何人（最大相容性）： → MP3

  • 什麼都能播
  • 小檔案
  • 好品質

Apple 生態系（iPhone、Mac、iTunes）： → M4A (AAC)

  • Apple 原生支援
  • 品質優於 MP3
  • 高效

封存（保留最佳品質）： → FLAC

  • 完美品質
  • 合理大小
  • 面向未來

專業編輯： → WAV

  • 無壓縮
  • 容易編輯
  • 最高品質

視訊錄影

分享給任何人（最大相容性）： → MP4 搭配 H.264

  • 在每台裝置上都能播放
  • iPhone 相容
  • 通用標準

上傳到網路/YouTube： → MP4 或 WebM

  • 兩者都表現出色
  • YouTube 兩種都接受
  • 高效串流

最佳品質、合理大小： → WebM 搭配 VP9（SeaMeet 使用的格式）

  • 優秀的壓縮效果
  • 出色的品質
  • 現代標準

封存包含多條音訊軌道： → MKV

  • 可容納多種語言
  • 靈活
  • 面向未來

iPhone/Mac 工作流程： → MOV

  • Apple 原生支援
  • 無縫運作
  • 良好品質

在格式之間轉換

有時候你需要將檔案從一種格式轉換為另一種。以下是方法。

何時轉換

將 WebM 轉換為 MP4 的時機：

  • 分享給無法播放 WebM 的人
  • 上傳到偏好 MP4 的平台
  • 需要 iPhone 相容性

轉換為 MP3 的時機：

  • 你只需要音訊
  • 想要更小的檔案
  • 需要最大相容性

將 WAV 轉換為 FLAC 的時機：

  • 想節省空間
  • 不需要進一步編輯
  • 封存

如何轉換

選項 1：使用 SeaMeet 的內建功能（如果可用）

某些版本的 SeaMeet 可以匯出不同格式：

  1. 選擇你的錄音
  2. 尋找「Export」或「Convert」選項
  3. 選擇你想要的格式
  4. 儲存新檔案

選項 2：使用 VLC Media Player（免費）

VLC 幾乎可以轉換任何格式：

步驟：

  1. 下載 VLC（可從 videolan.org 免費取得）
  2. 開啟 VLC
  3. 前往 Media → Convert/Save
  4. 新增你的檔案
  5. 點擊「Convert/Save」
  6. 選擇輸出格式（MP4、MP3 等）
  7. 選擇目的地
  8. 點擊 Start

優點：

  • 完全免費
  • 幾乎支援任何格式
  • 穩定可靠

缺點：

  • 可能很慢
  • 介面有點技術性

選項 3：線上轉換器

幫你轉換檔案的網站：

熱門選擇：

  • CloudConvert
  • Convertio
  • Online-Convert

步驟：

  1. 前往該網站
  2. 上傳你的檔案
  3. 選擇輸出格式
  4. 等待轉換
  5. 下載結果

優點：

  • 容易使用
  • 不需要安裝軟體
  • 對小檔案來說很快

缺點：

  • 隱私疑慮（你正在上傳到伺服器）
  • 檔案大小限制
  • 需要網路

隱私提示： 不要將敏感的錄音上傳到線上轉換器。對機密內容使用 VLC 或桌面軟體。

選項 4：桌面軟體

Windows/Mac 適用：

  • HandBrake（免費，視訊轉換優秀）
  • Freemake Video Converter（有免費版本）
  • Any Video Converter
  • Adobe Media Encoder（專業版，付費）

純音訊：

  • Audacity（免費，優秀的音訊編輯器）
  • XLD（Mac，用於無損音訊）
  • dBpoweramp（Windows，功能全面）

將 SeaMeet 的 WebM 轉換為 MP4

由於你可能需要將 WebM 轉換為 MP4 來分享，以下是具體指南：

使用 VLC：

  1. 開啟 VLC
  2. Media → Convert/Save
  3. 新增你的 .webm 檔案
  4. 點擊 Convert/Save 按鈕
  5. 在「Profile」下拉選單中，選擇：
    • 「Video - H.264 + MP3 (MP4)」用於視訊
    • 「Audio - MP3」用於純音訊
  6. 選擇目的地檔案（確保副檔名為 .mp4）
  7. 點擊 Start
  8. 等待轉換

品質注意事項： 轉換總是會有一些品質損失。就像影印一份影印件一樣。請保留原始 WebM 作為你的「母帶」副本。

技術深入探討：壓縮如何運作

對於對技術面感興趣的人，以下是音訊和視訊壓縮如何運作的簡單說明。

音訊壓縮

被移除的內容：

1. 人類聽不到的頻率

  • 非常高的音調（20 kHz 以上）
  • 非常低的音調（20 Hz 以下）
  • 大多數成年人本來就聽不到這些

2. 被較大聲音遮蔽的聲音

  • 如果一個響亮的鼓聲響起，你不會聽到同一時刻的輕聲耳語
  • 編解碼器會移除「聽不到」的耳語

3. 多餘的資訊

  • 靜音幾乎不佔用任何資料
  • 重複的聲音會被有效率地儲存

結果：

  • MP3 移除了約 90% 的資料
  • 但對人耳來說聽起來幾乎一樣
  • 就像從一本書中移除每第十頁——你仍然可以讀懂故事

視訊壓縮

被移除的內容：

1. 空間冗餘（一幀之內）

  • 藍天有數百萬個藍色像素
  • 編解碼器不會逐一描述每個像素，而是說「這個區域是藍色的」
  • 就像說「接下來的 100 個像素是同一個顏色」

2. 時間冗餘（幀與幀之間）

  • 30 fps 的視訊有相似的幀
  • 第 1 幀和第 2 幀可能有 95% 相同
  • 編解碼器只儲存那改變的 5%
  • 就像動畫賽璐璐片——只有移動的部分會被重畫

3. 無法察覺的細節

  • 你不會注意到的微小細節
  • 陰影中的顏色
  • 細微的紋理

結果：

  • VP9 可以將視訊壓縮 100:1 或更多
  • 一個 2GB 的原始視訊變成 20MB
  • 幾乎沒有可見的品質損失

位元率：品質控制

位元率是決定品質和檔案大小的關鍵概念。

什麼是位元率？

簡單定義： 每秒音訊或視訊使用多少資料。

測量單位：

  • kbps（千位元每秒）用於音訊
  • Mbps（百萬位元每秒）用於視訊

比喻： 把位元率想像成水管中流動的水：

  • 高位元率 = 消防水管（更多水/資料，更好的品質，更大的檔案）
  • 低位元率 = 花園水管（更少的水/資料，較低的品質，更小的檔案）

音訊位元率

位元率品質用途檔案大小（3 分鐘歌曲）
64 kbps差僅語音通話~1.4 MB
128 kbps可接受標準 MP3~2.8 MB
192 kbps好較佳 MP3~4.2 MB
256 kbps很好高品質 MP3~5.6 MB
320 kbps優秀最佳 MP3~7 MB
1411 kbps完美CD 品質（未壓縮）~30 MB
無損完美FLAC（大小不定）~15-25 MB

你應該使用什麼位元率？

語音錄音：

  • 64-96 kbps（Opus 編解碼器）= 優秀品質，極小的檔案
  • 128 kbps（MP3）= 好品質，小檔案
  • 192+ kbps = 對語音來說過度了

音樂：

  • 192 kbps（MP3）= 好，可接受的品質
  • 256-320 kbps（MP3）= 很好到優秀
  • 無損（FLAC）= 完美，用於封存

關於格式的常見問題

「我應該把所有 WebM 檔案都轉換成 MP4 嗎？」

不，不一定。 保留 WebM 作為你的封存格式（它品質更高且更有效率）。只在需要分享給無法播放 WebM 的人時，才轉換副本為 MP4。

把它想像成：

  • WebM = 你的原始底片（妥善保管，最佳品質）
  • MP4 = 你分享的沖印照片（為了相容性）

「為什麼我的 WAV 檔案比 MP3 大 50 倍？」

因為 WAV 是未壓縮的。它保留了每一個位元的音訊資料。MP3 移除了人耳聽不到或不會注意到的資料。就像這兩者的差異：

  • 一份詳細的建築藍圖（WAV）
  • 一張建築物的照片（MP3）

兩者都展示了建築物，但藍圖有更多的細節。

「將 MP3 轉換為 WAV 會提升品質嗎？」

不會。 一旦品質已經損失（透過壓縮為 MP3），你無法透過轉換為 WAV 來恢復它。就像試圖將壓縮過的 JPEG 恢復為 RAW 照片——細節已經永遠消失了。

原則： 始終保留你最高品質的原始檔。降級副本用於分享，而不是母帶。

「為什麼我的 iPhone 無法播放 WebM 檔案？」

Apple 裝置原生偏好自己的格式（MOV、M4A）。雖然現代 iOS 版本可以在 Safari 中播放某些 WebM 檔案，但原生的「照片」App 和較舊的裝置可能會有困難。

解決方案：

  1. 為 iPhone 轉換為 MP4
  2. 在 iPhone 上使用 VLC App（什麼都能播）
  3. 上傳到雲端並串流

「MP4 品質比 WebM 好嗎？」

不一定。 品質取決於：

  • 內部使用的編解碼器
  • 位元率/設定
  • 原始素材

高位元率的 WebM 搭配 VP9 可以看起來比低位元率的 MP4 搭配 H.264 更好。

真正的差異： 相容性。MP4 到處都能用。WebM 在現代裝置和瀏覽器上能用。

「封存應該使用什麼格式？」

最大限度的面向未來：

  • 視訊： MKV（最靈活）或 MP4（最相容）
  • 音訊： FLAC（完美品質，合理大小）

實用的封存方式：

  • 保留 SeaMeet 的 WebM 檔案——它們品質很高
  • 製作 MP4 副本以確保相容性
  • 儲存在多個硬碟/雲端

最佳實踐總結

黃金法則

  1. 保留原始檔

    • 永遠不要刪除你的原始錄音
    • 製作其他格式的副本用於分享
    • 原始檔 = 最高品質版本

  2. 根據用途選擇格式

    • 封存？ → WebM、MKV、FLAC
    • 分享？ → MP4、MP3
    • 編輯？ → WAV、高位元率格式

  3. 不要不必要地轉換

    • 每次轉換都會損失一些品質
    • 轉換一次，多次使用該副本
    • 保持原始檔不動

  4. 不確定時，使用 MP4/MP3

    • 最大相容性
    • 在每台裝置上都能運作
    • 分享的安全選擇

  5. 使用無損格式封存

    • 音訊用 FLAC
    • 視訊用高位元率 WebM 或 MKV
    • 讓你的收藏面向未來
