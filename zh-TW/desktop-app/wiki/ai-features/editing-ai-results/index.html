編輯AI結果 - 精修細節

第34章：編輯AI結果 — 精修細節

這就像轉錄服務交付草稿後的校對工作——繁重的工作已經完成，您只需要打磨最後幾個粗糙的邊緣。AI已完成了擷取和結構化所有內容的工作。現在您來決定「說話者 2」是否應該改稱「Alice」，以及今天的提取是否比上週的版本更好。

本章涵蓋兩種類型的編輯：

  • A節：說話者標籤 — 在即時轉錄中重新命名、合併和重新指派說話者標籤
  • B節：版本歷史記錄 — 瀏覽、比較和切換先前的AI提取執行結果

本章目標

閱讀本章後，您將能夠：

  • 重新命名說話者標籤，並讓其立即在所有地方更新
  • 合併屬於同一人的兩個說話者標籤
  • 將個別的逐字稿段落重新指派給正確的說話者
  • 了解版本標誌的位置及使用方法
  • 在不遺失最新版本的情況下瀏覽先前的提取執行結果
  • 透過過時版本橫幅識別您正在查看歷史版本的時機

A節：說話者標籤

為何標籤很重要

自動說話者偵測會指派像「說話者 1」、「說話者 2」這樣的佔位名稱。這些名稱雖然功能性上可用，但可讀性不佳。「說話者 1說我們需要在週五前出貨」遠不如「Alice說我們需要在週五前出貨」有用——也更難分享。

重新命名只需30秒，即可將逐字稿從技術輸出轉變為專業文件。

說話者標籤編輯適用於即時轉錄（如第27章所述，在錄音時啟用了即時轉錄功能的錄音）。由AI摘要提取生成的逐字稿使用相同的標籤，也可以從Transcript分頁重新命名。

重新命名說話者

重新命名一個說話者標籤會更改該說話者在整個錄音中的每一次出現——逐字稿、摘要、待辦事項、決策和章節全部同時更新。如果AI寫了「說話者 1提議削減15%的預算」，將「說話者 1」重新命名為「Alice」後，該行將在所有地方顯示為「Alice提議削減15%的預算」。

步驟說明：

  1. 在您的錄音資料庫中開啟錄音

  2. 在詳細資訊面板中點擊「AI Insights」，然後選擇 Transcript 分頁

    • 您會看到： 包含所有段落和說話者標籤的逐字稿。在左側邊緣（或右側，取決於版面配置）有一個說話者面板，列出所有偵測到的說話者標籤。

  3. 在說話者面板中，點擊您要重新命名的說話者旁邊的鉛筆圖示✏️

    • 您會看到： 標籤變為可編輯的文字欄位，預先填入目前的名稱（「說話者 1」）。

  4. 輸入新名稱（例如「Alice」）

    • 您會看到： 字符取代了佔位文字。

  5. 按Enter（或點擊欄位外）

    • 您會看到： 所有逐字稿段落中「說話者 1」的每一次出現同時更新為「Alice」。說話者面板現在在「說話者 1」的位置列出「Alice」。

提示： 請在錄音後立即重新命名說話者，趁您還記得誰在說話的時候。情境記憶消逝得很快。

合併兩個說話者

有時AI會為一個人建立兩個標籤——當聲音在錄音的不同點聽起來不同時就會發生這種情況（例如某人移動得離麥克風更遠，或者笑了之後恢復正常音調）。合併功能可以將兩個標籤合而為一。

步驟說明：

  1. 在說話者面板中，找到您想要吸收到另一個標籤中的說話者（「來源」說話者）

  2. 點擊合併圖示（或在說話者標籤上按右鍵並選擇 Merge into…）

    • 您會看到： 下拉選單或子面板出現，列出所有其他偵測到的說話者。

  3. 選擇目標說話者 — 您希望來源說話者合併入的那一個

    • 範例： 您想讓「說話者 3」成為「Alice」。選擇「Alice」作為目標。

  4. 點擊 Apply（或在彈出視窗中確認）

    • 您會看到： 所有先前歸屬於「說話者 3」的段落現在歸屬於「Alice」。「說話者 3」從說話者面板中消失。逐字稿在所有地方立即更新。

注意： 合併無法撤銷。如果合併錯誤，您需要手動重新命名個別段落（請參閱下一節）。套用前請仔細確認。

重新指派單一段落

如果大多數段落的歸屬是正確的，但特定段落被錯誤識別，您可以更正該個別段落，而不影響其他段落。

步驟說明：

  1. 在Transcript分頁中，找到歸屬給錯誤說話者的段落

  2. 點擊該段落上顯示的說話者名稱（例如「說話者 2」）

    • 您會看到： 一個小型彈出視窗或內嵌下拉選單出現，列出所有偵測到的說話者。

  3. 從清單中選擇正確的說話者

    • 您會看到： 該段落的說話者標籤更新為所選說話者。其他段落不受影響。

這對於孤立的錯誤歸屬很有用——例如，當別人短暫回答了一個問題，而AI將其歸屬給了錯誤的人。

說話者編輯的限制

限制詳情
僅限即時轉錄說話者編輯適用於在錄音期間或由AI摘要提取生成的逐字稿。不適用於匯入的逐字稿檔案。
無法重新命名為現有名稱如果「Alice」已作為標籤存在，您無法將「說話者 2」重新命名為「Alice」——請改用合併功能。
無法撤銷說話者更改會立即儲存，無法撤銷。請謹慎使用合併功能。
名稱為本地設定說話者名稱僅儲存在這筆錄音中，不影響其他錄音。

B節：版本歷史記錄

為何存在版本功能

每次您點擊⟳重新生成AI提取時，SeaMeet都會在覆寫之前悄悄地將先前的結果儲存為帶編號的版本快照。任何內容都不會被銷毀。

這意味著您可以：

  • 自由地重新生成，無需擔心遺失良好的結果
  • 將目前的提取與較舊的版本進行比較
  • 如果重新生成產生了較差的結果，可以返回到先前的版本

版本標誌

版本標誌顯示在 AI Insights分頁列中，位於內容分頁和匯出按鈕之間：

[Transcript] [Summary] [Actions] [Decisions] [Chapters]  ·  v3 ▾  [MD] [SRT] [JSON] [⟳]
  • 「v3 ▾」 — 您正在查看第3版（最新版），▾表示有下拉選單
  • 標誌僅在至少一次重新生成後才會出現——首次使用的用戶不會看到介面有任何變化

如果您只執行過一次AI摘要提取（從未重新生成），標誌將不會出現。這是設計如此——目前沒有可供比較的內容。

瀏覽版本

點擊版本標誌以開啟版本選擇器：

┌─────────────────────────────────────────┐
│  ✓  v3 — 最新版                         │
│      2026年3月1日，上午9:15             │
├─────────────────────────────────────────┤
│     v2                                  │
│      2026年3月1日，上午9:00             │
├─────────────────────────────────────────┤
│     v1                                  │
│      2026年2月27日，上午10:30           │
└─────────────────────────────────────────┘
  • 勾選符號（✓）標記您目前正在查看的版本
  • 版本按最新到最舊排列
  • 每個條目顯示提取完成的日期和時間
  • 最新版始終是最近一次執行

查看舊版本：

  1. 點擊版本標誌（「v3 ▾」）
  2. 點擊您想要的版本（例如「v1」）
  3. 您會看到： 所有五個分頁以該次執行的歷史資料重新載入。頂端出現過時版本橫幅。

過時版本橫幅

每當您查看最新版本以外的任何版本時，內容區域頂部都會出現一個細長的琥珀色橫幅：

┌──────────────────────────────────────────────────────────────┐
│  ⚠  正在查看第2版，共3版 · 生成於3月1日，上午9:00  [View latest →]│
└──────────────────────────────────────────────────────────────┘
  • 「正在查看第2版，共3版」 — 哪個歷史版本及共有多少個版本
  • 「生成於3月1日，上午9:00」 — 此版本的建立時間
  • 「View latest →」 — 一次點擊即可返回最近的提取

過時版本橫幅是一個安全信號。它確保您始終知道自己何時不是在查看最新結果，防止在分享或根據內容採取行動時產生混淆。

在查看歷史版本時匯出會匯出該版本的資料，而非最新版本的資料。匯出按鈕正常運作——它們只是對當前顯示的內容進行操作。

即時基準線

如果在錄音期間啟用了即時轉錄（第27章），無論您進行了多少次重新生成，原始的即時轉錄始終可作為版本選擇器底部的特殊條目使用：

┌─────────────────────────────────────────────┐
│  ✓  v3 — 最新版                             │
│      2026年3月1日，上午9:15                 │
├─────────────────────────────────────────────┤
│     v2                                      │
│      2026年3月1日，上午9:00                 │
├─────────────────────────────────────────────┤
│     v1                                      │
│      2026年2月27日，上午10:30               │
├─────────────────────────────────────────────┤
│     Live (original)                         │
│      AI驅動 · 錄製於2月27日                 │
└─────────────────────────────────────────────┘

選擇「Live (original)」時：

  • 僅 Transcript 分頁有內容——這是錄音期間實時捕捉的逐字文字
  • Summary、Actions、Decisions和Chapters 分頁顯示「此版本不適用」——即時AI引擎僅產生了逐字稿，未產生完整的提取輸出
  • 過時版本橫幅出現，因為這不是最新的提取結果

即時基準線對於比較以下內容很有用：

  • 即時AI聽到的內容（Live）與後處理AI轉錄的內容（任何vN版本）
  • 在即時處理和後續提取之間，說話者偵測是否有所改進或變化

版本歷史記錄的限制

限制詳情
唯讀歷史版本是快照，無法直接編輯。若要編輯，請切換到最新版本並在那裡進行更改。
無法刪除個別版本無法刪除（可以刪除整筆錄音，這將移除所有內容）。
無法重新命名版本無法命名或加上標籤（例如「好版本」）。它們僅以編號和時間戳記識別。
無差異比對視圖版本一次只能查看一個。此版本不支援並排比較。
標誌需要至少1次重新生成標誌僅在至少一次重新生成後才會出現。只有一次提取執行記錄的錄音不顯示標誌。

故障排除

「版本標誌未顯示」

症狀： 您已執行AI摘要提取，但分頁列中未出現版本標誌。

原因： 標誌僅在至少一次重新生成（點擊⟳）後才會出現。單次初始提取執行不會建立版本——目前沒有可供比較的內容。

處理方法： 點擊⟳重新生成。新的提取完成後，標誌將出現並顯示「v2 ▾」。

「說話者更改未儲存」

症狀： 您重新命名了說話者並點擊了其他地方，但下次載入時舊名稱又出現了。

請依序嘗試以下步驟：

  1. 檢查您的網路連線——某些說話者編輯需要同步步驟
  2. 在關閉錄音前等待5秒——更改會有短暫的延遲後才儲存
  3. 從資料庫重新載入錄音並再次檢查

如果問題持續，請嘗試重新啟動SeaMeet並再次套用重新命名。

「合併選項呈灰色」

症狀： 右鍵點擊說話者標籤或點擊合併圖示沒有回應，或選項呈灰色。

原因： 合併需要至少兩個不同的說話者標籤。如果只偵測到一個說話者，則沒有可合併的對象。

處理方法： 逐字稿可能只識別了一個說話者——這對於獨奏錄音或一個人主導的訪談來說是正常的。

最佳實踐

錄音後立即重新命名說話者 誰說了什麼的記憶消逝得很快。在錄音後一小時內開啟AI Insights，在情境消失前完成重新命名。

將最新版本保持為您的工作版本 歷史版本供參考和比較之用。不要將舊版本設定為您的預設視圖——最新版本始終是最完整、最近處理的版本。

可選擇在重新生成前匯出 版本歷史記錄會自動保存過去的結果，因此在⟳之前匯出並非絕對必要。但如果您想要一個獨立檔案（用於電子郵件或附件），請先行匯出。

對於重複項目，先合併再重新命名 如果您注意到同一個人出現為兩個說話者（例如「說話者 1」和「說話者 3」），請使用合併功能，而非手動重新命名兩個。合併更快速，並確保所有未來的引用都整合在一起。

審查即時基準線的準確性 如果您進行了即時轉錄，請將「Live (original)」視圖與最新的提取進行比較。即時轉錄有時會捕捉到後處理遺漏的細節，反之亦然。
