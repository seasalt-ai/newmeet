Différences entre plateformes

Chapitre 29 : Différences entre plateformes

Introduction

SeaMeet fonctionne sur plusieurs plateformes — Windows, macOS et Linux — mais chaque système d'exploitation a ses propres particularités, capacités et limitations. Ce qui fonctionne parfaitement sur Windows peut se comporter différemment sur Mac. Certaines fonctionnalités sont disponibles sur une plateforme mais pas sur une autre. Comprendre ces différences vous aide à tirer le meilleur parti de SeaMeet quel que soit l'ordinateur que vous utilisez.

Ce chapitre explique comment SeaMeet s'adapte à chaque plateforme, quelles fonctionnalités sont spécifiques à la plateforme et quelles limitations vous devriez connaître.

Objectifs du chapitre

Après avoir lu ce chapitre, vous serez capable de :

  • Comprendre les différences entre les versions Windows, macOS et Linux
  • Savoir quelles fonctionnalités sont spécifiques à la plateforme
  • Configurer SeaMeet correctement pour votre système d'exploitation
  • Contourner les limitations spécifiques à la plateforme
  • Choisir la bonne plateforme pour vos besoins d'enregistrement

Partie 1 : Vue d'ensemble par plateforme

SeaMeet sur Windows

Idéal pour :

  • Compatibilité maximale
  • Enregistrement de jeux
  • Environnements professionnels
  • Version la plus complète en fonctionnalités

Caractéristiques clés :

  • La plupart des fonctionnalités disponibles
  • Meilleure prise en charge de l'accélération matérielle (NVIDIA/AMD/Intel)
  • Capture audio système facile
  • Compatibilité d'applications la plus large
  • Le plus testé et stable

Versions Windows prises en charge :

  • Windows 10 (version 1809 et ultérieure)
  • Windows 11
  • Windows Server 2019/2022 (prise en charge limitée)

Architectures Windows prises en charge :

  • x64 (Intel/AMD 64 bits) : Prise en charge complète, toutes les fonctionnalités disponibles
  • ARM64 (Windows sur ARM) : Pris en charge, certaines fonctionnalités audio indisponibles
    • Surface Pro X et appareils similaires
    • Enregistrement d'écran, vidéo et microphone entièrement pris en charge
    • Capture audio système et énumération des périphériques audio non disponibles (dégradation gracieuse)
    • Voir la section Windows ARM64 ci-dessous pour plus de détails

Non pris en charge :

  • Windows 7, 8, 8.1 (fin de vie)
  • Windows XP/Vista (anciens)
  • Windows 32 bits (x86)

SeaMeet sur macOS

Idéal pour :

  • Professionnels créatifs
  • Utilisateurs de l'écosystème Apple
  • Interface propre et cohérente
  • Intégration avec les flux de travail Mac

Caractéristiques clés :

  • Interface Mac native et soignée
  • Excellentes performances sur Apple Silicon (M1/M2/M3)
  • Excellentes performances sur Intel Macs
  • Intégration système étroite
  • Modèle d'autorisations différent
  • Surveillance du microphone par application
  • Détection de réunions dans le navigateur et prévention du démarrage automatique

Versions macOS prises en charge :

  • macOS 14.2 Sonoma (minimum - requis pour les fonctionnalités native-audio-node)
  • macOS 15 Sequoia
  • Versions futures

Architectures macOS prises en charge :

  • Apple Silicon (arm64) : Prise en charge complète, toutes les fonctionnalités, y compris la détection audio par application
  • Intel (x64) : Prise en charge complète avec installateur séparé

Prise en charge Apple Silicon et Intel :

  • Deux installateurs DMG séparés : un pour Intel, un pour Apple Silicon
  • Téléchargez la version correspondant au processeur de votre Mac
  • Macs M1/M2/M3 → Téléchargez la version arm64
  • Intel Macs → Téléchargez la version x64
  • Les deux versions ont des fonctionnalités identiques
  • Accélération matérielle via VideoToolbox (Apple Silicon) ou Quick Sync (Intel)
  • Détection de microphone par application (native-audio-node)
  • Pré-sélection intelligente de fenêtre pour les applications de réunion

SeaMeet sur Linux

Idéal pour :

  • Utilisateurs techniques exécutant SeaMeet à partir des sources
  • Développeurs contribuant au projet
  • Utilisateurs soucieux de la confidentialité
  • Défenseurs de l'open source

Caractéristiques clés :

  • Pris en charge par la communauté, source uniquement (pas d'installateur préconstruit officiel)
  • Ensemble de fonctionnalités variable selon la distribution
  • Plus de configuration manuelle requise
  • Convivial pour la ligne de commande
  • Moins de fonctionnalités "ça marche tout seul"

Distributions prises en charge :

  • Ubuntu 20.04+ (meilleur support)
  • Fedora 34+
  • Debian 11+
  • Autres distributions basées sur Debian/Ubuntu

Notes d'installation Linux (v2.1.4+) :

✅ npm install réussit maintenant proprement sur Linux

Jusqu'à v2.1.4, `npm install` échouait sur Linux avec EBADPLATFORM
car native-audio-node — un module natif macOS/Windows uniquement —
était listé dans `dependencies`. Depuis v2.1.4, il vit dans
`optionalDependencies` aux côtés d'autres packages audio spécifiques
à la plateforme (macos-audio-devices, native-sound-mixer, win-audio),
donc npm les ignore sur Linux au lieu d'avorter.

Si vous avez précédemment rencontré `npm ERR! EBADPLATFORM`:
1. Récupérez v2.1.4 ou ultérieur
2. Supprimez node_modules et package-lock.json
3. Exécutez npm install à nouveau — il devrait se terminer sans erreur

Limitations :

  • Pas d'installateur préconstruit officiel — exécutez depuis la source via npm start
  • La surveillance du microphone par application et la détection automatique des réunions ne sont pas disponibles (nécessitent native-audio-node, qui n'a pas de binaire Linux)
  • La disponibilité de la barre des tâches système dépend de l'environnement de bureau (voir la section Barre des tâches ci-dessous)
  • L'accélération matérielle varie selon la combinaison GPU/pilote
  • Plus de configuration requise pour la capture audio système (boucle PulseAudio / PipeWire)

Barre des tâches système et Mode Lite par plateforme

SeaMeet continue de fonctionner en arrière-plan après la fermeture de la fenêtre principale — la barre des tâches système (appelée barre de menus sur macOS) est la façon dont vous y revenez, changez l'état d'enregistrement et quittez proprement. L'API Tray d'Electron est spécifique à la plateforme, donc le comportement varie :

Notes de la barre des tâches Linux :

La barre des tâches Electron fonctionne de manière fiable sur GNOME (avec l'extension AppIndicator), KDE Plasma, XFCE, Cinnamon et la plupart des bureaux par défaut Ubuntu/Fedora. Sur les sessions Wayland uniquement et certains gestionnaires de fenêtres minimaux, l'icône de la barre des tâches peut ne pas apparaître du tout — l'application s'exécute toujours, mais vous devrez la relancer depuis le terminal ou utiliser un raccourci clavier global pour ramener la fenêtre. Il n'y a pas d'asset d'icône de barre des tâches spécifique à Linux ; le même .ico est chargé que pour Windows.

Mode Lite :

Le Mode Lite (introduit dans v2.x) est une disposition compacte côté renderer — une barre flottante 560×80 avec les contrôles d'enregistrement, la forme d'onde et les actions rapides au lieu de la fenêtre d'application complète. Il est contrôlé par le paramètre ui.appMode ('full' ou 'lite') et bascule à l'exécution via Paramètres. Le Mode Lite fonctionne de manière identique sur les trois plateformes car il n'a pas de chemin de code spécifique à la plateforme.

Partie 3 : Fonctionnalités et configuration spécifiques à Windows

Avantages Windows

1. L'audio système est facile

Sur Windows, capturer l'audio système est simple :

Méthode : Stereo Mix (la plus fiable)

Configuration :
1. Clic droit icône haut-parleur → Ouvrir les paramètres son
2. Panneau Son → Enregistrement
3. Clic droit dans zone vide → Afficher les périphériques désactivés
4. Clic droit "Stereo Mix" → Activer
5. Définir comme par défaut

SeaMeet peut maintenant capturer directement l'audio système

Méthodes alternatives :

  • Boucle WASAPI (méthode moderne)
  • Capture DirectSound
  • Câbles audio virtuels

2. Accélération matérielle abondante

Windows a la meilleure prise en charge des encodeurs GPU :

GPU NVIDIA :

GTX série 600 et plus récente :
• Puce d'encodeur NVENC dédiée
• Excellente qualité
• Très efficace
• SeaMeet prend en charge automatiquement

GPU AMD :

Radeon HD série 7000 et plus récente :
• VCE (Video Coding Engine)
• Bonne qualité
• Encodage efficace
• Prise en charge automatique

Intel intégré :

Core 4ème génération et plus récent :
• Quick Sync Video
• Qualité étonnamment bonne
• Très économe en énergie
• Idéal pour les ordinateurs portables

3. Fonctionnalités de jeu

Intégration de jeu spécifique à Windows :

Prise en charge Game Mode :
• API Windows Game Mode
• Détection auto en jeu
• Optimisation des ressources
• Disponible uniquement sur Windows

Intégration Game Bar :
• Peut fonctionner avec Xbox Game Bar
• Pas de conflits
• Raccourcis séparés

Guide de configuration Windows

Configuration optimale :

1. Activer Stereo Mix pour audio système
2. Mettre à jour les pilotes GPU :
   - NVIDIA : GeForce Experience
   - AMD : Radeon Software
   - Intel : Intel Driver Assistant

3. Activer l'accélération matérielle dans SeaMeet :
   Paramètres → Vidéo → Utiliser l'accélération matérielle

4. Définir le plan d'alimentation sur "Haute performance" pour l'enregistrement

5. Désactiver Windows Game Mode si problèmes :
   Paramètres → Jeux → Game Mode → Off

Raccourcis spécifiques à Windows

Raccourcis globaux (fonctionnent partout) :
• Ctrl + Alt + R — Démarrer/Arrêter l'enregistrement
• Ctrl + Alt + F — Enregistrer Flashback
• Ctrl + Alt + S — Capture d'écran

Gestion des fenêtres :
• Win + G — Game bar (si activée)
• Win + Alt + R — Enregistrement Xbox Game Bar
   (fonctionne avec SeaMeet)

Informations spécifiques à Windows ARM64

Qu'est-ce que Windows ARM64 ?

ARM64 est une architecture de processeur différente :
• Utilisée dans les appareils Windows sur ARM (Surface Pro X, etc.)
• Prise en charge native pour les processeurs ARM
• Peut émuler les applications x64 (plus lent)
• Prise en charge croissante des applications ARM64 natives

SeaMeet sur ARM64

SeaMeet a une prise en charge ARM64 native à partir de v1.0.2+ :

✅ Entièrement pris en charge sur ARM64 :
• Enregistrement d'écran (haute performance)
• Enregistrement vidéo (haute performance)
• Enregistrement microphone (API Windows directe)
• Détection et gestion de fenêtre
• Widget Floater et raccourcis clavier
• Paramètres et bibliothèque d'enregistrements
• Toutes les fonctionnalités UI

❌ Non disponible sur ARM64 :
• Capture audio système (audio des apps/haut-parleurs)
• Énumération des périphériques audio (détection micro/haut-parleur)
• Contrôle de mixeur audio
• Ceux-ci nécessitent des modules natifs non compilés pour ARM64

Quand vous devriez utiliser ARM64

Idéal pour :

  • Utilisateurs Surface Pro X voulant des performances natives
  • Enregistrement vidéo/écran sans audio système
  • Enregistrement microphone (l'enregistrement direct fonctionne)
  • Performance complète sans ralentissement d'émulation

Pas idéal pour :

  • Capture audio système (sera indisponible)
  • Flux de travail audio complexes
  • Sélection de périphérique audio (non disponible)

Comment savoir quelle version vous avez

Paramètres Windows :
1. Paramètres → Système → À propos
2. Cherchez "Type de système"
3. Affiche soit :
   • "Processeur basé sur x64" (Intel/AMD 64 bits)
   • "Processeur basé sur ARM" (Windows sur ARM)

Ligne de commande :

PowerShell : wmic os get osarchitecture
Sortie : 64-bit ou ARM 64-bit

Installation

SeaMeet détecte automatiquement votre architecture :

• Téléchargez l'installateur générique
• Il installera automatiquement la bonne version
• Utilisateurs x64 obtiennent : SeaMeet-...-x64-Setup.exe
• Utilisateurs ARM64 obtiennent : SeaMeet-...-arm64-Setup.exe

Ou téléchargez manuellement le bon depuis les versions :
• Vérifiez votre Type de système (ci-dessus)
• Téléchargez l'architecture correspondante

Auto-Updater sur ARM64

Mises à jour transparentes :
• L'application vérifie automatiquement les mises à jour
• ARM64 met à jour vers ARM64 (pas x64)
• Rétro-compatible avec les versions précédentes
• Aucune intervention manuelle nécessaire

Dépannage des problèmes ARM64

Problème : L'option "Audio système" est grisée

Comportement attendu sur ARM64 :
✓ C'est normal
✓ Module natif non disponible
✓ Peut toujours enregistrer le microphone
✓ Pas d'erreur - dégradation gracieuse

Problème : Impossible de sélectionner microphone/haut-parleur

Solutions :
1. Utilisez les périphériques système par défaut
2. Allez dans les paramètres Son Windows pour choisir un périphérique
3. SeaMeet utilisera ce que Windows a sélectionné
4. Sélection manuelle de périphérique non disponible sur ARM64

Problème : L'enregistrement microphone ne fonctionne pas

Solutions :
1. Vérifiez les paramètres Son Windows
2. Le microphone doit être le périphérique d'entrée par défaut
3. Accordez les autorisations microphone à SeaMeet
4. Windows doit afficher le niveau d'enregistrement
5. Testez dans l'application d'enregistrement Windows d'abord

Partie 4 : Fonctionnalités et configuration spécifiques à macOS

Avantages macOS

1. Interface soignée

SeaMeet sur Mac semble natif :

• Suit les directives de conception macOS
• Utilise les contrôles natifs
• Respecte le thème système
• Prise en charge Touch Bar (sur les Macs compatibles)
• Bonne intégration de la barre de menus

2. Excellente prise en charge Apple Silicon

Les puces M1/M2/M3 fonctionnent très bien :

Fonctionnalités Apple Silicon :
• Accélération matérielle via VideoToolbox
• Excellente performance par watt
• Encodage rapide
• Fonctionnement frais
• Longue autonomie de batterie en enregistrement

3. Intégration système

Intégration macOS :
• Prise en charge iCloud Drive
• Compatible Time Machine
• Prêt pour Handoff/Continuity
• Sandboxing approprié
• Signets liés à la sécurité

Limitations macOS

1. L'audio système nécessite une autorisation

Contrairement à Windows, macOS nécessite une autorisation explicite :

Étapes de configuration :

1. Première fois pour enregistrer l'audio système :
   Préférences Système → Sécurité et confidentialité → Confidentialité
   
2. Cliquez sur "Enregistrement d'écran" à gauche

3. Cochez "SeaMeet" dans la liste
   (Vous devrez peut-être déverrouiller avec votre mot de passe)

4. Redémarrez complètement SeaMeet

5. L'audio système fonctionnera maintenant

Pourquoi c'est requis :

  • Modèle de sécurité macOS
  • L'enregistrement d'écran capture tout
  • L'utilisateur doit autoriser explicitement
  • Protège contre les logiciels espions

2. Pas d'accélération matérielle NVIDIA/AMD

Accélération matérielle Mac :
• Intel Macs : Intel Quick Sync (si disponible)
• Apple Silicon : VideoToolbox (excellent)
• GPU externes : Non pris en charge pour l'encodage
• Pas de NVENC ou AMD VCE (puces non présentes)

Performance :

  • Apple Silicon est si efficace que ce n'est pas important
  • Les Intel Macs avec Quick Sync sont bien
  • Les Intel Macs plus anciens sans Quick Sync utilisent l'encodage CPU

3. Restrictions sandbox

Sécurité macOS :
• Les applications sont en sandbox
• Doit demander l'autorisation pour :
  - Microphone
  - Caméra (si utilisée)
  - Enregistrement d'écran
  - Emplacements du système de fichiers
  - Dossier Téléchargements
  - Bureau

SeaMeet vous demandera ceux-ci au besoin

Installateurs spécifiques à l'architecture macOS

SeaMeet sur macOS fournit des installateurs séparés pour les Macs Intel et Apple Silicon :

Quelle version dois-je télécharger ?

Vérifiez votre type de Mac :
Menu Apple (🍎) → À propos de ce Mac → Puce

Si vous voyez :
• "Apple M1", "Apple M2", ou "Apple M3"
  → Téléchargez : SeaMeet-macOS-arm64-[version].dmg

• "Intel Core i5", "Intel Core i7", etc.
  → Téléchargez : SeaMeet-macOS-x64-[version].dmg

Pourquoi des installateurs séparés ?

✅ Taille de téléchargement plus petite (~100 Mo chacun vs ~180 Mo universel)
✅ Optimisé pour votre processeur spécifique
✅ Pas de problèmes de compatibilité avec les modules natifs
✅ Processus de build et de mise à jour plus simple

Performance :

Apple Silicon (arm64) :
• Puces M1, M2, M3
• Excellentes performances
• Meilleure autonomie de batterie
• Exécution arm64 native

Intel (x64) :
• Macs 2013-2021
• Parité de fonctionnalités complète
• Accélération Quick Sync
• Exécution x64 native

Installation :

1. Téléchargez le DMG correct pour votre Mac
2. Ouvrez le fichier DMG
3. Glissez SeaMeet vers Applications
4. Lancez et accordez les autorisations

Fonctionnalités de détection de réunion macOS

SeaMeet sur macOS inclut une détection de réunion avancée avec surveillance audio par application :

Surveillance du microphone par application :

Comment ça fonctionne :
• Surveille quelle application utilise votre microphone
• Détecte quand les réunions commencent/se terminent
• Utilise native-audio-node pour la détection par application
• Disponible sur macOS 14.2+ (Sonoma)

Plateformes prises en charge :
• Zoom
• Google Meet
• Microsoft Teams
• Apple FaceTime
• Webex
• Et d'autres plateformes de réunion

Détection de réunion dans le navigateur :

Détecte automatiquement les réunions actives dans :
• Google Meet (Chrome/Firefox/Safari)
• Client web Zoom
• Client web Webex
• Teams web
• Autres plateformes de réunion basées sur le web

Pré-sélection de fenêtre :
• Sélectionne automatiquement la fenêtre de réunion
• Empêche l'enregistrement accidentel d'autres applications
• Pas de démarrage automatique sauf si explicitement activé
• Contrôle utilisateur maintenu

Exigences :

macOS 14.2 Sonoma ou ultérieur
• Requis pour les API native-audio-node
• Couvre tous les utilisateurs Mac modernes
• Active la détection audio par application

Guide de configuration macOS

Configuration initiale :

1. Installez SeaMeet
   - Téléchargez le DMG correct (arm64 pour Apple Silicon, x64 pour Intel)
   - Ouvrez le fichier DMG
   - Glissez SeaMeet vers Applications
   - Double-cliquez pour lancer

2. Accordez les autorisations (Critique !) :
   Préférences Système → Sécurité et confidentialité → Confidentialité

   Activez pour :
   ☑ Enregistrement d'écran
   ☑ Microphone
   ☑ Accessibilité (pour certains raccourcis)
   ☑ Événements système (pour l'interaction avec la barre de menus)

3. Redémarrez complètement SeaMeet
   - Forcer à quitter (Cmd+Q)
   - Relancez

4. Test d'enregistrement
   - Test simple d'abord
   - Puis essayez la détection de réunion

5. Pour l'audio système :
   - SeaMeet détecte automatiquement l'audio système
   - Ou utilisez BlackHole (pilote audio virtuel) pour des configurations avancées
   - Ou utilisez la boucle intégrée sur macOS plus récent
   - Suivez les instructions dans l'application si nécessaire

Raccourcis spécifiques à macOS

Raccourcis globaux :
• Cmd + Shift + R — Démarrer/Arrêter l'enregistrement
• Cmd + Shift + F — Enregistrer Flashback
• Cmd + Shift + S — Capture d'écran

Intégration macOS :
• Touch Bar : Bouton d'enregistrement (si disponible)
• Barre de menus : Contrôles rapides
• Centre de notifications : État d'enregistrement

Partie 5 : Informations spécifiques à Linux

Caractéristiques Linux

1. Expérience variable

Les versions Linux varient selon la distribution :

Ubuntu (recommandé) :
• Mieux pris en charge
• Configuration la plus facile
• La plupart des fonctionnalités fonctionnent
• Tests réguliers

Fedora :
• Bon support
• Packages plus récents
• Peut nécessiter des dépôts supplémentaires

Autres distributions :
• Votre kilométrage peut varier
• Support communautaire
• Peut nécessiter des correctifs manuels

2. Complexité de la capture audio

L'audio Linux est plus complexe :

Systèmes audio :
• PulseAudio (le plus courant)
• PipeWire (plus récent, moderne)
• ALSA (bas niveau)
• JACK (audio professionnel)

Configuration requise :
Peut avoir besoin de créer des périphériques audio virtuels
Ou utiliser des modules de boucle
Pas "plug and play" comme Windows

Configuration PulseAudio :

# Créer un sink virtuel pour l'audio système
pactl load-module module-null-sink sink_name=SeaMeet sink_properties=device.description=SeaMeetRecording

# Le surveiller
pactl load-module module-loopback source=SeaMeet.monitor

3. L'accélération matérielle varie

NVIDIA sur Linux :
• NVENC disponible via pilotes propriétaires
• Doit installer séparément
• Bonne qualité quand ça fonctionne

AMD sur Linux :
• Le support VCE varie selon le pilote
• Pilotes open source vs propriétaires
• Peut nécessiter une configuration

Intel sur Linux :
• VA-API pour l'encodage
• Fonctionne généralement bien
• Fait partie des pilotes Mesa

Guide de configuration Linux

Installation Ubuntu :

# Téléchargez le package .deb
# Ou installez via le dépôt si disponible

sudo dpkg -i seameet-linux.deb
sudo apt-get install -f  # Corriger les dépendances

# Accorder les autorisations
# Ajouter l'utilisateur au groupe vidéo
sudo usermod -a -G video $USER

# Se déconnecter et se reconnecter

Installation Fedora :

# Téléchargez le package .rpm
sudo rpm -i seameet-linux.rpm

# Ou via dnf si dans les dépôts
sudo dnf install seameet

Configuration post-installation :

# 1. Configuration audio (complexe)
# Suivez le guide de configuration audio dans l'application SeaMeet

# 2. Accélération matérielle
# Installez les pilotes appropriés :
# NVIDIA : nvidia-utils ou propriétaire
# AMD : mesa-va-drivers
# Intel : intel-media-driver

# 3. Autorisations
# Peut nécessiter de configurer les règles udev
# Pour l'accès aux périphériques

Raccourcis spécifiques à Linux

Raccourcis globaux :
• Ctrl + Alt + R — Démarrer/Arrêter l'enregistrement
• Ctrl + Alt + F — Enregistrer Flashback
• Ctrl + Alt + S — Capture d'écran

Remarque : Peut entrer en conflit avec les raccourcis du bureau
Configurez dans les paramètres SeaMeet si nécessaire

Partie 6 : Dépannage spécifique à la plateforme

Problèmes spécifiques à Windows

Problème : Impossible de capturer l'audio système

Solutions :

1. Activer Stereo Mix :
   - Panneau Son → Enregistrement
   - Afficher les périphériques désactivés
   - Activer Stereo Mix

2. Utiliser la méthode WASAPI :
   - Paramètres SeaMeet → Audio → Méthode
   - Sélectionner boucle WASAPI

3. Pas de Stereo Mix sur Realtek :
   - Mettre à jour les pilotes Realtek
   - Ou utiliser la méthode WASAPI à la place

4. Spécifique à Windows 11 :
   - Vérifier les paramètres de confidentialité
   - Paramètres → Confidentialité → Microphone
   - Assurer que les apps peuvent accéder à l'audio

Problème : Écran noir lors de l'enregistrement de jeu

Solutions :

1. Désactiver l'optimisation plein écran :
   - Clic droit exe du jeu → Propriétés
   - Compatibilité → Désactiver les optimisations plein écran

2. Utiliser le mode fenêtré ou sans bordure

3. Désactiver Windows Game Bar :
   - Peut entrer en conflit avec SeaMeet

4. Exécuter SeaMeet en tant qu'administrateur

5. Utiliser le mode Game Capture si disponible

Problèmes spécifiques à macOS

Problème : Pas d'audio système

Solutions :

1. Accorder l'autorisation Enregistrement d'écran :
   Préférences Système → Sécurité et confidentialité → Confidentialité → Enregistrement d'écran
   Cocher SeaMeet
   Redémarrer SeaMeet

2. Installer BlackHole (audio virtuel) :
   brew install blackhole-2ch
   Ou télécharger depuis GitHub

3. Configurer un périphérique multi-sortie :
   Configuration audio MIDI → Créer Multi-Sortie
   Ajouter haut-parleurs + BlackHole
   Définir comme sortie système

4. macOS plus récent (12+) :
   Peut avoir une boucle intégrée
   Vérifier les paramètres SeaMeet

Problème : SeaMeet ne démarre pas

Solutions :

1. Vérifier les autorisations :
   - Enregistrement d'écran
   - Microphone
   - Accessibilité
   - Événements système

2. Clic droit → Ouvrir :
   - Première fois peut nécessiter ceci
   - Contourner Gatekeeper

3. Vérifier l'attribut de quarantaine :
   xattr -d com.apple.quarantine /Applications/SeaMeet.app

4. Vérifier la version macOS :
   • Nécessite macOS 14.2 Sonoma ou ultérieur
   • Vérifier avec icône Apple → À propos de ce Mac
   • Mettre à jour si nécessaire

5. Redémarrer complètement :
   - Forcer à quitter : Cmd+Q
   - Tuer complètement l'application
   - Relancer

6. Réinstaller SeaMeet
   - Supprimer de Applications
   - Télécharger un nouveau DMG
   - Réinstaller

Problème : La détection de réunion ne fonctionne pas

Solutions :

1. Vérifier la version macOS :
   • La détection de réunion nécessite macOS 14.2+
   • Vérifier À propos de ce Mac
   • Mettre à jour si version plus ancienne

2. Accorder les autorisations nécessaires :
   Préférences Système → Sécurité et confidentialité → Confidentialité
   ✓ Enregistrement d'écran
   ✓ Microphone
   Redémarrer SeaMeet

3. Vérifier la plateforme de réunion :
   • Assurer que l'app de réunion a accès au microphone
   • Préférences Système → Sécurité et confidentialité → Microphone
   • Ajouter l'app de réunion si nécessaire (Zoom, Teams, etc.)

4. Tester la détection de fenêtre :
   • Démarrer une réunion dans l'app prise en charge
   • Vérifier si la fenêtre apparaît dans SeaMeet
   • Essayer de sélectionner la fenêtre manuellement d'abord

5. Réunions dans le navigateur :
   • Assurer que l'onglet du navigateur de réunion est actif
   • Le navigateur doit avoir l'autorisation d'enregistrement d'écran
   • Certains navigateurs peuvent nécessiter une configuration supplémentaire

Problèmes spécifiques à Linux

Problème : Aucun périphérique audio n'apparaît

Solutions :

1. Vérifier le système audio :
   - PulseAudio est-il en cours d'exécution ?
   - Ou PipeWire ?
   pactl info

2. Autorisations :
   - Ajouter l'utilisateur au groupe audio
   sudo usermod -a -G audio $USER

3. Installer pavucontrol :
   - PulseAudio Volume Control
   - Vérifier les périphériques d'entrée/sortie

4. SeaMeet peut nécessiter une configuration spécifique :
   - Suivre la configuration audio dans l'application
   - Peut nécessiter des périphériques virtuels

Problème : Utilisation élevée du CPU

Solutions :

1. Activer l'accélération matérielle :
   - Installer les pilotes VA-API
   - NVIDIA : Vérifier la prise en charge NVENC
   - AMD : Peut être limité

2. Utiliser des paramètres de qualité inférieure :
   - 720p au lieu de 1080p
   - Fréquence d'images plus basse

3. Vérifier si l'enregistrement vers un disque lent :
   - Utiliser SSD si possible
   - Vérifier les performances du disque

4. Environnement de bureau :
   - Certains DEs utilisent plus de ressources
   - Essayer un WM plus léger si nécessaire

Partie 7 : Conseils de flux de travail multi-plateforme

Se déplacer entre les plateformes

Transfert de paramètres :

Les paramètres SeaMeet sont stockés localement
Non synchronisés automatiquement avec le cloud

Transfert manuel :
1. Exporter les paramètres (si la fonctionnalité est disponible)
2. Ou noter les paramètres clés
3. Reconfigurer sur l'autre plateforme
4. Attendez-vous à certaines différences

Compatibilité des fichiers :

Les fichiers d'enregistrement sont universels :
• MP4 fonctionne sur toutes les plateformes
• WebM fonctionne sur toutes les plateformes
• MOV fonctionne sur toutes les plateformes (avec codecs)

Aucune conversion nécessaire lors du changement d'ordinateur

Raccourcis clavier :

Windows/Linux : Ctrl + Alt + [touche]
Mac : Cmd + Shift + [touche]

La mémoire musculaire devra s'ajuster
Vérifiez les raccourcis dans les paramètres sur chaque plateforme

Meilleure plateforme pour des usages spécifiques

Pour le jeu :

  • Windows (meilleur support matériel, plus de jeux)

Pour le travail créatif :

  • macOS (intégration avec applications créatives)

Pour la programmation/développement :

  • Toute (préférence personnelle)
  • Linux si vous préférez l'open source

Pour les affaires/entreprises :

  • Windows (le plus courant, support IT le plus facile)
  • macOS (croissant dans les affaires)

Pour la confidentialité :

  • Linux (le plus de contrôle)

Résumé

SeaMeet fonctionne sur toutes les principales plateformes mais chacune a ses forces :

✅ Windows : Le plus de fonctionnalités, configuration la plus facile, meilleur pour les jeux, contrôle audio complet

✅ macOS : Soigné, détection de réunion intelligente, fonctionne à la fois sur Intel et Apple Silicon via des DMG optimisés séparés (pas un binaire universel — choisissez celui correspondant à votre puce), excellentes performances

✅ Linux : Flexible, axé sur la confidentialité, pris en charge par la communauté, installation source uniquement (pas d'installateur préconstruit — npm install propre à partir de v2.1.4)

Recommandations de plateforme :

Choisissez Windows si :

  • Vous voulez une compatibilité maximale
  • Vous enregistrez des jeux
  • Vous avez besoin d'une capture audio système facile
  • Vous utilisez des GPU NVIDIA/AMD
  • Vous avez besoin d'un contrôle maximal des fonctionnalités

Choisissez macOS si :

  • Vous êtes dans l'écosystème Apple
  • Vous avez un Mac Intel ou Apple Silicon (les deux sont pris en charge)
  • Vous voulez une expérience native soignée
  • Vous faites du travail créatif
  • Vous voulez une détection automatique de réunion et une sélection de fenêtre intelligente
  • Vous appréciez la surveillance audio par application intégrée

Choisissez Linux si :

  • Vous êtes techniquement enclin
  • Vous appréciez l'open source
  • Vous voulez un contrôle maximal
  • Cela ne vous dérange pas la configuration
  • Vous préférez les options prises en charge par la communauté

Avantages macOS dans v1.0.5+ :

✨ Nouvelles fonctionnalités (macOS 14.2+) :
• Surveillance du microphone par application (native-audio-node)
• Détection automatique de réunion
• Pré-sélection de fenêtre intelligente
• Détection de réunion dans le navigateur
• Prévention du démarrage automatique
• Installateurs optimisés séparés (Intel + Apple Silicon)
• Tailles de téléchargement plus petites (~100 Mo par architecture)
